1. Aprender de las acciones, no de un mapa conocido

En la guía anterior, el robot calculaba una Policy óptima porque las probabilidades de transición y los Rewards estaban dados. Un robot real no suele recibir ese mapa completo. Puede saber que existe un cruce de rutas sin conocer qué decisión producirá mayor recompensa a lo largo de sucesivos envíos. Reinforcement Learning (RL) aborda este problema actualizando estimaciones a partir de transiciones observadas.

Seguiremos un único caso sintético de logística: enviar un paquete directamente o pasar por un cruce donde aparece otra decisión. Calcularemos valores exactos como referencia para verificar el algoritmo; el Agent que aprende no recibe esos valores de referencia. Es fundamental distinguir la verificación del analista de la información disponible para el Agent.

Responderemos: ¿cómo modifica una experiencia a \(Q(s,a)\)?, ¿qué distingue SARSA de Q-Learning?, ¿por qué Exploration puede modificar el comportamiento conveniente? y ¿cómo evaluar una Policy aprendida sin confundir simulación con evidencia industrial?

2. El MDP completo y las unidades

Un MDP (Markov Decision Process) especifica States, Actions, Transition Probabilities, Rewards y un factor de descuento. D es el depósito, J el cruce y T el estado terminal absorbente. La Markov assumption indica que el State actual contiene la información relevante suficiente para definir la distribución de la siguiente transición dada la Action actual; no significa que la historia jamás sea relevante en un problema real.

State actual Action State siguiente Reward inmediato (puntos)
D direct T +5
D via J J −1
J express T +7
J standard T +5

Cada transición tiene probabilidad 1 en el caso didáctico principal. Esta simplicidad deliberada permite comprobar exactamente la aritmética del aprendizaje. Los Rewards representan puntos de utilidad inventados, no dinero, probabilidades ni productividad medida. El episodio termina en T; después de T, el valor futuro es cero. Más adelante introduciremos resultados aleatorios en express con la misma recompensa esperada, para distinguir promedio y riesgo.

Utilizamos \(\gamma=0.9\): un punto recibido un paso después aporta 0.9 puntos al Return presente. El instante inicial coincide con la decisión actual; el Reward inmediato no se descuenta.

3. Return: calcular cada ruta sin adivinar

El Return \(G_t\) suma los Rewards futuros con descuento: \(G_t=R_{t+1}+\gamma R_{t+2}+\gamma^2R_{t+3}+\cdots\). El Reward de la Action tomada en \(t\) tiene exponente cero. Como aquí el episodio termina después de una o dos acciones, la suma es finita.

Enviar directamente entrega un solo Reward: \(G(D,\mathrm{direct})=5\). Pasar por J y elegir express produce dos Rewards: primero \(-1\) y después \(+7\). Por lo tanto, \(G(D,\mathrm{viaJ},\mathrm{express})=-1+0.9(7)=-1+6.3=5.3\). Si la segunda Action es standard: \(-1+0.9(5)=-1+4.5=3.5\). Estas tres trayectorias completas permiten comparar decisiones con claridad.

La primera ruta recibe 5 puntos ahora. La ruta express pierde 1 punto ahora para obtener 7 después; su total descontado es 5.3, apenas 0.3 puntos superior a direct. La ruta standard produce 3.5, inferior a direct. Sin descuento, la ruta express valdría 6 en lugar de 5.3. Por ello es indispensable definir el horizonte de las decisiones.

4. Action Values Q(s,a) frente a State Values V(s)

El Action Value \(Q^\pi(s,a)\) pregunta: «Si tomo Action \(a\) en State \(s\) y luego sigo la Policy \(\pi\), ¿cuánto Return descontado espero obtener?». El State Value \(V^\pi(s)\) incorpora también la decisión de la Policy sobre la acción actual. Una Policy \(\pi(a|s)\) expresa la probabilidad de elegir \(a\) estando en \(s\).

\[V^\pi(s)=\sum_a\pi(a|s)Q^\pi(s,a)\]

Si la Policy es determinista y Greedy, \(V^\pi(s)\) coincide con el Action Value escogido. Si \(Q(J,\mathrm{express})=7\) y \(Q(J,\mathrm{standard})=5\), elegir siempre express produce \(V(J)=7\). Si la Policy utiliza express 75% de las veces y standard 25%, entonces \(V(J)=0.75(7)+0.25(5)=5.25+1.25=6.50\) puntos.

No confundamos \(Q\) con Reward inmediato. \(Q(D,\mathrm{viaJ})\) incluye las consecuencias de la acción siguiente; su Reward inmediato es únicamente \(-1\). En Model-Free Learning, el Agent estima \(Q\) con muestras, sin recibir directamente la tabla de valores del MDP.

5. La Policy óptima como referencia independiente

Para verificar luego el aprendizaje, nosotros como analistas resolvemos el MDP pequeño. Como todas las acciones desde J terminan en T, \(Q^*(J,\mathrm{express})=7+0.9(0)=7\) y \(Q^*(J,\mathrm{standard})=5+0.9(0)=5\). El asterisco representa el Action-Value Function óptimo: el mayor Return esperado si las acciones posteriores se seleccionan óptimamente.

En D, direct vale 5. La Action via J produce \(-1+0.9\max(7,5)=-1+6.3=5.3\). Por tanto:

\[Q^*(D,\mathrm{direct})=5,\qquad Q^*(D,\mathrm{viaJ})=5.3.\]

La Policy determinista óptima elige via J desde D y express desde J. Reconstruyamos su Return: \(-1+0.9(7)=5.3\), igual al resultado de Bellman. Esta es una referencia matemática de verificación, no una tabla proporcionada en secreto al algoritmo de aprendizaje. La usaremos para comprobar si Q-Learning se aproxima correctamente a la solución.

6. Por qué Trial-and-Error Learning no es planificación

Planning supone que conocemos el modelo de Transition Probabilities y Rewards: calcula esperanzas sobre posibles States siguientes. Model-Free Reinforcement Learning modifica las estimaciones usando transiciones efectivamente observadas: \((s,a,r,s')\). Una transición registra State anterior, Action elegida, Reward recibido y State siguiente. SARSA registra, además, la siguiente Action elegida \(a'\). Ninguno de los dos métodos necesita conocer toda la tabla de probabilidades para realizar una actualización individual.

Por ejemplo, observar \((D,\mathrm{viaJ},-1,J)\) informa que visitar J cuesta un punto ahora. Esa observación por sí sola no revela qué Action conviene desde J ni el valor de largo plazo de usar esa ruta. Aprender requiere experiencias posteriores, estimaciones numéricas y Exploration suficiente. La misma transición de cuatro componentes puede observarse repetidamente y modificar las estimaciones una y otra vez.

Esta distinción importa en aplicaciones reales: saber que una ruta existe no garantiza conocer su valor operativo esperado. Los algoritmos Model-Free aprenden mediante interacciones, pero ensayar acciones sin restricciones en un almacén real puede ser costoso o peligroso; pueden necesitarse simuladores validados, registros y experimentos controlados.

7. Exploration versus Exploitation con números

Exploitation consiste en elegir la Action actualmente mejor estimada; Exploration consiste en probar ocasionalmente otras alternativas para aprender. Una epsilon-greedy Policy elige una acción aleatoria con probabilidad \(\varepsilon\) y una acción Greedy con probabilidad \(1-\varepsilon\). La elección aleatoria también puede seleccionar la acción Greedy, así que su probabilidad total no es simplemente \(1-\varepsilon\).

En J existen dos acciones y express es Greedy. Con \(\varepsilon=0.5\), la rama Greedy contribuye \(1-0.5=0.5\) de probabilidad de express y la exploración aleatoria aporta \(0.5\times(1/2)=0.25\). Por tanto, \(P(\mathrm{express}|J)=0.5+0.25=0.75\) y \(P(\mathrm{standard}|J)=0.25\). Comprobación: \(0.75+0.25=1\).

El Reward esperado de esa conducta exploratoria en J es \(0.75(7)+0.25(5)=6.5\), no 7. Exploration tiene un costo de oportunidad observable de \(7-6.5=0.5\) puntos esperados por visita a J. En otros entornos puede tener consecuencias mayores de seguridad o equidad.

8. TD Error: aprender antes de conocer todo el futuro

Un Temporal-Difference (TD) Target combina un Reward inmediato observado con una estimación del valor posterior. La diferencia entre el Target y la estimación anterior es el TD Error, simbolizado por \(\delta\). No debe confundirse con un Residual de regresión, aunque ambos son diferencias.

\[\delta =\underbrace{r+\gamma\widehat V_{\mathrm{next}}}_{\mathrm{TD\ target}}-\underbrace{Q(s,a)}_{\mathrm{estimacion\ anterior}}\]

La actualización es \(Q_{\rm new}(s,a)=Q(s,a)+\alpha\delta\), donde \(\alpha\in(0,1]\) es el Learning Rate que determina cuánto cambia la estimación con la observación. El término \(\widehat V_{\mathrm{next}}\) depende del algoritmo: SARSA utiliza el valor de la siguiente Action realmente seleccionada; Q-Learning utiliza el mayor Action Value estimado en el siguiente State.

Si la transición llega a T, no existe otra decisión y el término futuro es cero. Con Reward terminal \(r=7\), valor anterior \(Q(J,\mathrm{express})=3\) y \(\alpha=0.5\), obtenemos \(\delta=7-3=4\) y \(Q_{\rm new}=3+0.5(4)=5\). No necesitamos esperar nuevos episodios.

9. SARSA: derivación de la actualización On-Policy

El nombre SARSA corresponde a cinco elementos de la experiencia: State, Action, Reward, next State, next Action. Su TD Target evalúa la siguiente Action seleccionada por la misma Policy de comportamiento que produce los datos. Por eso se denomina On-Policy TD Control.

\[Q_{\rm new}(s,a)=Q(s,a)+\alpha\big[r+\gamma Q(s',a')-Q(s,a)\big]\]

Consideremos una tabla de estimaciones actual: \(Q(D,\mathrm{viaJ})=2\), \(Q(J,\mathrm{express})=7\) y \(Q(J,\mathrm{standard})=5\). El Agent escoge via J, observa \(r=-1\), llega a J y selecciona standard como siguiente Action, quizá por exploración. Tomamos \(\alpha=0.5\) y \(\gamma=0.9\).

El Target es \(-1+0.9(5)=3.5\). El TD Error es \(3.5-2=1.5\). La actualización entrega \(2+0.5(1.5)=\boxed{2.75}\). Se utiliza la Action standard efectivamente seleccionada, aunque express tenga una estimación mayor. Después standard generará su Reward +5 y recibirá su propia actualización. La actualización actual de SARSA no sustituye \(a'\) por una acción Greedy imaginaria.

10. Q-Learning: derivación de la actualización Off-Policy

Q-Learning utiliza la misma transición observada \((s,a,r,s')\), pero propaga el máximo valor estimado disponible desde \(s'\), aunque la Policy de comportamiento no seleccione esa acción. Así intenta aprender una Policy objetivo Greedy óptima mientras puede recolectar datos mediante otra Policy exploratoria: Off-Policy TD Control.

\[Q_{\rm new}(s,a)=Q(s,a)+\alpha\big[r+\gamma\max_{a'}Q(s',a')-Q(s,a)\big]\]

Reutilicemos exactamente los mismos números: \(Q(D,\mathrm{viaJ})=2\) inicialmente, los valores siguientes son express 7 y standard 5; \(r=-1\), \(\alpha=0.5\) y \(\gamma=0.9\). El máximo es \(\max(7,5)=7\). El Target vale \(-1+0.9(7)=5.3\), el TD Error \(5.3-2=3.3\) y la estimación nueva \(2+0.5(3.3)=\boxed{3.65}\).

SARSA produjo 2.75 y Q-Learning produjo 3.65 desde la misma transición física. Lo que cambió fue la Action futura usada en el Target. Ninguno de estos números es una promesa: ambos dependen de estimaciones Q actuales, posiblemente imprecisas. Una sobreestimación inicial puede propagarse hacia muchos otros States.

11. Tabla para diferenciar Policy de comportamiento y Policy objetivo

La Behavior Policy decide las acciones durante la recolección de experiencias. La Target Policy indica qué comportamiento estamos evaluando o aprendiendo. En SARSA ambas representan la misma Policy cambiante; en Q-Learning de un paso la Policy de comportamiento puede explorar aunque el Target suponga selección Greedy.

Pregunta SARSA Q-Learning
¿Qué aparece en el Target? \(Q(s',a')\) de la Action \(a'\) elegida \(\max_b Q(s',b)\)
Relación de Policies On-Policy Off-Policy
¿Puede explorar con \(\varepsilon>0\)? Sí Sí
¿Siempre son diferentes las actualizaciones? No, la siguiente Action puede ser Greedy No, pueden coincidir los valores
¿Prueba seguridad operativa? No No

Una confusión frecuente es creer que Q-Learning debe ejecutar siempre la acción Greedy. Eso impediría explorar acciones desconocidas. Puede ejecutar standard mientras calcula un Target basado en express. SARSA tampoco es simplemente Q-Learning con otro nombre: dado que la próxima Action se muestrea, la Exploration persistente puede influir en qué Policy aprende a preferir.

12. Expected SARSA verifica resultados, pero no sustituye a SARSA muestreado

SARSA ordinario actualiza utilizando la única Action siguiente realmente seleccionada. Expected SARSA, un algoritmo relacionado, reemplaza la muestra por el promedio ponderado de acciones de la Policy. Aquí sirve como referencia analítica independiente para entender cómo la Exploration persistente afecta al valor.

\[\mathrm{Expected\ SARSA\ target}=r+\gamma\sum_{a'}\pi(a'|s')Q(s',a')\]

Con \(\varepsilon=0.5\) y estimaciones en J de 7 y 5, express tiene probabilidad 0.75 y standard 0.25. Por consiguiente, \(V^\pi(J)=0.75(7)+0.25(5)=6.5\). El Target esperado de via J es \(-1+0.9(6.5)=\boxed{4.85}\), mientras que el Target Greedy de Q-Learning es \(-1+0.9(7)=5.30\).

Partiendo de \(Q(D,\mathrm{viaJ})=2\) y \(\alpha=.5\), una actualización de Expected SARSA entregaría \(2+.5(4.85-2)=3.425\). No equivale al resultado de una actualización individual de SARSA ordinario tras elegir standard (2.75) o express (3.65). En efecto, \(0.25(2.75)+0.75(3.65)=3.425\). Verificamos de manera independiente la esperanza promediando ambas actualizaciones posibles.

13. Una distinción esencial: comportamiento óptimo frente a exploratorio

Nuestros dos algoritmos responden preguntas asintóticas diferentes si epsilon permanece en 0.5 y se cumplen condiciones apropiadas de aprendizaje. El valor Greedy óptimo desde D es 5.3 via J, como verificamos antes. Pero una Behavior Policy que explora en J obtiene 6.5 en promedio, por lo que la ruta via J vale \(-1+0.9(6.5)=4.85\). Enviar direct todavía entrega 5. Por ello, con exploración epsilon-greedy persistente, una Policy Greedy respecto de sus propios Action Values On-Policy prefiere direct.

Esto no prueba que SARSA sea un algoritmo inferior ni que Q-Learning sea universalmente mejor. Si epsilon disminuye hacia cero, SARSA también puede aproximarse a la Policy Greedy óptima bajo los supuestos usuales de convergencia tabular. Además, ejecutar la Behavior Policy exploratoria de Q-Learning aún expone al Agent a acciones subóptimas, incluso si sus Q-values objetivo ya son óptimos.

14. Umbral exacto de Exploration: ¿cuándo cambia la decisión?

El valor esperado en J bajo epsilon-greedy con dos Actions (si express es Greedy) es \([1-\varepsilon/2](7)+[\varepsilon/2](5)=7-\varepsilon\). Ocurre porque Exploration elige standard con probabilidad \(\varepsilon/2\) y sacrifica 2 puntos respecto de express.

El valor de via J resulta \(Q^\pi(D,\mathrm{viaJ})=-1+0.9(7-\varepsilon)=5.3-0.9\varepsilon\). Para encontrar el punto de indiferencia de la Policy entre via J y direct, resolvemos \(5.3-0.9\varepsilon=5\). Restamos 5: \(0.3=0.9\varepsilon\). Dividimos entre 0.9: \(\boxed{\varepsilon=1/3\approx0.3333}\). Por encima de un tercio, direct tiene mayor valor esperado bajo esta Policy de continuación exploratoria; por debajo, via J tiene mayor valor.

Comprobemos \(\varepsilon=.2\): via J \(5.3-.9(.2)=5.12>5\); gana. Con \(\varepsilon=.5\): via J \(5.3-.9(.5)=4.85<5\); gana direct. El umbral depende de los Rewards y gamma inventados; no es una regla universal para SARSA.

15. Seguir tres episodios SARSA sin omitir operaciones

Comenzamos con todos los Q-values iguales a cero, \(\alpha=0.5\), \(\gamma=.9\), y los episodios explícitamente seleccionados. Son transiciones didácticas, no una muestra aleatoria de desempeño. En acciones terminales, la contribución de valor futuro es cero. Actualizamos online después de cada transición observada.

Verifiquemos 3a: \(\delta=2.15-(-0.75)=2.90\); \(Q_{\rm new}=-0.75+0.5(2.90)=-0.75+1.45=0.70\). La actualización J express ocurre después de la actualización en D, así que D utiliza el valor anterior 3.5, no el posterior 5.25. Es un error frecuente difícil de detectar. 16. Q-Learning en los mismos tres episodios

Repitamos los tres episodios seleccionados con Q-Learning, Q inicial en cero y \(\alpha=.5\). En el episodio 1, \(Q(D,via)\) pasa a \(0+.5(-1)=-.5\); la primera transición terminal express establece \(Q(J,express)=3.5\).

En el episodio 2, el Agent vuelve a tomar via J, aunque la siguiente Action ejecutada será standard. Q-Learning utiliza el máximo actual en J: \(\max(3.5,0)=3.5\). El Target desde D es \(-1+.9(3.5)=2.15\). Con Q anterior −0.5: \(Q_{nuevo}=-.5+.5[2.15-(-.5)]=-.5+1.325=\boxed{0.825}\). SARSA produjo −0.75 en ese mismo episodio porque la acción standard seleccionada tenía valor cero. Después J standard se actualiza a 2.5.

En el episodio 3, \(Q(J,express)=3.5\) y \(Q(J,standard)=2.5\). El Target de Q-Learning en D sigue siendo 2.15, de modo que \(Q(D,via)=0.825+.5(2.15-.825)=\boxed{1.4875}\). Después, express terminal actualiza su valor desde 3.5 a 5.25. Observar distintas tablas después de la misma secuencia demuestra la diferencia algorítmica. Tres episodios no constituyen evidencia de exactitud final.

17. Monte Carlo Return frente a TD Bootstrapping

Monte Carlo Learning espera el Return observado al concluir el episodio; Temporal-Difference Learning utiliza un Reward inmediato más una estimación actual de valor futuro. Introducir una estimación dentro de otra se denomina Bootstrapping. Los dos métodos aprenden de experiencias, pero utilizan información disponible en momentos distintos.

Para D→J (−1), J→T express (+7), el Return completo observado desde D es \(G=-1+.9(7)=5.3\). Con Q(D,via) anterior igual a 2 y \(\alpha=.5\), Monte Carlo produce \(2+.5(5.3-2)=3.65\). En cambio, si SARSA eligió standard en J con estimación actual 5, el Target TD inmediato es 3.5 y el valor nuevo es 2.75; el Reward posterior todavía no estaba disponible. Son preguntas distintas de actualización, no resultados aritméticos contradictorios.

En pasos terminales, no existe estimación futura: \(Q(T,\cdot)=0\) es una convención terminal y no una pareja con Action válida. Para Reward express +7 desde J hacia T, tanto SARSA como Q-Learning usan Target 7. Los métodos Monte Carlo ordinarios requieren episodios completos; TD permite actualizar durante una trayectoria. Esto no determina automáticamente sesgo, varianza ni superioridad en cualquier entorno.

18. Learning Rate alpha: calcular la sensibilidad

Con Q anterior igual a 2 y Target Q-Learning de 5.3, \(Q_{nuevo}=2+\alpha(5.3-2)=2+3.3\alpha\). Por tanto, alpha controla el tamaño de la actualización mientras que el TD Error mide la información nueva respecto de la estimación.

\(\alpha\) Sustitución explícita Q nuevo
0 2+0×3.3 2.000
0.1 2+0.1×3.3 2.330
0.5 2+0.5×3.3 3.650
1.0 2+1×3.3 5.300

Incluimos alpha=0 exclusivamente como caso límite sin aprendizaje, no como configuración práctica de entrenamiento. Un alpha alto reacciona rápido, pero puede causar fluctuaciones con muestras ruidosas; un alpha bajo es más conservador, pero tarda más en adaptarse a cambios. Alpha no modifica el Reward observado: determina cuánto del Target se incorpora a la estimación Q.

19. Epsilon schedules y su significado práctico

Un epsilon fijo continúa explorando indefinidamente. Un decay schedule reduce epsilon poco a poco. Por ejemplo, \(\varepsilon_k=\max(0.05,0.5\times0.99^k)\) comienza en 0.5 y se acerca al piso 0.05. Nunca llega a cero, así que no satisface todos los teoremas que requieren que la Policy de comportamiento se vuelva Greedy en el límite.

Con epsilon 0.05, express se selecciona en J con probabilidad \(1-.05/2=.975\) y standard con .025. El Reward esperado en J es \(.975(7)+.025(5)=6.825+.125=6.95\). Por tanto, via J con esta continuación exploratoria produce \(-1+.9(6.95)=5.255\), superior a direct=5. Con epsilon=.5 la ruta obtenía 4.85, inferior a direct. Así verificamos numéricamente el cambio de decisión.

Si epsilon cae demasiado rápido, una Action podría no visitarse lo suficiente para obtener estimaciones útiles. Si cae muy lentamente, las Actions elegidas deliberadamente para recopilar información pueden generar costos operativos persistentes. Debemos documentar el Exploration schedule de Training separado de la Policy de evaluación: modificar epsilon en Test cambia la Policy evaluada.

20. Initialization, cobertura y empates

Cuando todos los Q-values comienzan en cero, las acciones inicialmente Greedy pueden estar empatadas. Una convención reproducible es desempatar aleatoriamente entre acciones con el máximo valor. Elegir siempre la primera opción de una lista fija puede distorsionar las visitas iniciales. En los episodios manuales se indica explícitamente la Action siguiente, así que no existe un desempate oculto que cambie los cálculos.

Optimistic Initialization asigna valores iniciales altos a acciones no probadas para incentivar su exploración. Una Action inicializada en 10 podría atraer visitas cuando otras estimaciones están cerca de 5, pero ello no siempre es seguro: una maniobra desconocida puede ocasionar daños reales. Los valores iniciales son supuestos, no observaciones históricas.

Una auditoría de cobertura cuenta las visitas State–Action. El ejemplo tiene cuatro parejas válidas: (D,direct), (D,via), (J,express), (J,standard). Si (J,standard) nunca se visita, su cero es un valor de Initialization, no evidencia de inutilidad. En espacios grandes o continuos, la cobertura completa puede ser imposible; hay que informar claramente el alcance de la experiencia disponible.

21. Supuestos de convergencia: ¿qué está realmente garantizado?

Q-Learning tabular cuenta con resultados de convergencia para ciertos MDPs finitos y estacionarios cuando los Rewards son acotados, se visitan suficientemente las parejas State–Action y los Learning Rates decrecen apropiadamente. Un patrón clásico de tamaños de paso por pareja cumple \(\sum_n\alpha_n=\infty\) y \(\sum_n\alpha_n^2<\infty\). Estas expresiones representan aprendizaje persistente sin acumular indefinidamente ruido cuadrático de las actualizaciones.

Para SARSA, converger a comportamiento Greedy óptimo puede requerir exploración suficiente mientras epsilon tiende a cero, condición conocida como GLIE (Greedy in the Limit with Infinite Exploration) junto con Learning Rates apropiados. Si epsilon permanece en 0.5, la Policy SARSA no se vuelve Greedy y sus valores On-Policy pueden diferir de los óptimos. Esto explica nuestra diferencia entre 4.85 y 5.3.

Estos son resultados matemáticos condicionales, no prueba de convergencia tras 100 episodios. Tampoco se trasladan automáticamente a aproximaciones con Neural Networks, cambios en Rewards, States que no cumplen Markov, Exploration sin restricciones o registros Offline correlacionados. Las hipótesis forman parte del propio resultado.

22. Separar la evaluación de Policies Greedy y exploratorias

Una training Behavior Policy elige acciones para reunir experiencias; la Evaluation Policy final debe definirse y congelarse antes de medir desempeño. Una Policy Greedy utiliza epsilon=0; una Behavior Policy con epsilon=.5 sigue eligiendo acciones exploratorias. Son Policies diferentes y no deben compartir métricas sin explicación.

Nuestra ruta Greedy óptima es via J seguida de express y genera 5.3. Con SARSA y epsilon=.5 persistente, la acción Greedy en D puede ser direct y producir 5 al implementarse sin Exploration. Si en cambio ejecutamos la Behavior Policy SARSA con epsilon=.5 también en D, elegirá direct con probabilidad .75 y via J con .25. El valor de via J incluye Exploration en J y vale 4.85; el valor inicial de todo el comportamiento exploratorio es \(0.75(5)+0.25(4.85)=3.75+1.2125=\boxed{4.9625}\). No equivale a 5 ni a 5.3.

Para comparar algoritmos correctamente, debemos definir Policies de Training y Test, informar epsilon, episodios y Random Seeds, y evaluar en escenarios independientes no reutilizados para seleccionar Hyperparameters. Un simulador finito puede generar cálculos exactos y aun así representar mal las condiciones reales del almacén.

23. Rewards aleatorios: la esperanza no garantiza seguridad

El MDP principal es determinista. En un escenario de sensibilidad sintético separado, supongamos que express en J produce +10 con probabilidad .9 y −20 con probabilidad .1, manteniendo standard en +5. El Reward esperado de express es \(0.9(10)+0.1(-20)=9-2=\boxed{7}\), igual al caso determinista de express (+7). Un planificador neutral al riesgo continúa prefiriendo via J y express porque el Return esperado desde D sigue siendo \(-1+.9(7)=5.3\).

Pero los Returns realizados posibles son \(-1+.9(10)=8\) tras el éxito y \(-1+.9(-20)=-19\) tras el fracaso. Verifiquemos el promedio: \(.9(8)+.1(-19)=7.2-1.9=5.3\). Tener la misma media no significa tener el mismo riesgo; un administrador podría imponer una restricción de pérdida máxima que impida usar express, pero sería otro problema de optimización.

No mezclaremos silenciosamente esta extensión aleatoria con las muestras deterministas del laboratorio principal. Con Rewards aleatorios, los Q-values pueden contener ruido y debemos informar su variabilidad. Además, consecuencias negativas pueden ser operativa o éticamente inadmisibles incluso con utilidad esperada positiva.

24. Máximos ruidosos y motivación de Double Q-Learning

Q-Learning propaga \(\max_a Q(s',a)\). Si los Q-values contienen ruido, elegir el máximo puede seleccionar también un error de estimación excepcionalmente positivo. Considera dos Actions cuyo valor verdadero es 5 en ambos casos y estimaciones temporales de 7 y 3. El máximo estimado es 7, superior al verdadero máximo en 2. Este ejemplo no establece un tamaño universal del sesgo, sino que muestra su mecanismo.

Double Q-Learning separa selección y evaluación entre dos tablas. Una actualización puede elegir \(a^*=\arg\max_a Q_A(s',a)\) y evaluarla mediante \(Q_B(s',a^*)\). Si la tabla A estima (7,3) y la B estima (4,6), A selecciona la Action 1, pero B la valora en 4; la actualización no tiene por qué reutilizar el máximo 7 de A. Los pasos pueden alternar la tabla que aprende.

Esta idea conduce a Double DQN cuando Q-values son aproximados por Neural Networks. Pero una comparación entre dos tablas no demuestra que Double Q elimine todos los sesgos. Lo relevante es qué estimador selecciona la Action y cuál la evalúa, otra aplicación de la separación cuidadosa entre Target y Policy.

25. Reward misspecification y sensibilidad al descuento

Un Agent optimiza el Reward numérico definido por su diseñador, no un objetivo humano que quedó implícito. Un Reward logístico real podría considerar tiempo, combustible, daños, seguridad y efectos sobre clientes. Combinar dimensiones en puntos de utilidad exige ponderaciones, restricciones y unidades documentadas. Si los daños no tienen penalización, una ruta aparentemente rentable puede ignorar costos reales importantes.

El descuento también puede invertir la decisión. Nuestra trayectoria óptima via J vale \(-1+7\gamma\) mientras direct vale 5. Igualamos: \(-1+7\gamma=5\). Sumamos 1: \(7\gamma=6\); dividimos entre 7: \(\boxed{\gamma=6/7\approx0.85714}\). Con gamma=.8, via J produce \(-1+5.6=4.6<5\); con gamma=.9 produce 5.3>5.

El resultado no indica cuál es el factor de descuento ético o financiero correcto: gamma es una decisión de modelado relacionada con objetivos y horizonte. Tampoco un Reward alto en simulación demuestra seguridad operacional. Modificar Rewards o gamma reiteradamente después de consultar Test invalidaría cualquier pretensión de evaluación independiente.

26. De la tabla de cuatro Q-values a Deep Q-Networks

El entorno tabular contiene apenas cuatro parejas State–Action. Los sistemas reales pueden tener miles de Features, cantidades continuas y múltiples acciones, haciendo inviable una tabla. Function Approximation estima \(Q_\theta(s,a)\) mediante parámetros aprendidos \(\theta\), frecuentemente con Neural Networks.

Una Deep Q-Network (DQN) aproxima Action Values utilizando Targets con Bootstrapping. Una TD Loss cuadrática ilustrativa es \(L(\theta)=[r+\gamma\max_{a'}Q_{\theta^-}(s',a')-Q_\theta(s,a)]^2\), donde \(\theta^-\) representa una Target Network congelada durante cierto intervalo. Experience Replay muestrea transiciones almacenadas en lugar de depender solo de las consecutivas; puede disminuir correlaciones pero no vuelve automáticamente independiente toda experiencia.

DQN incorpora problemas ausentes en la tabla: sesgo del aproximador, inestabilidad de Optimization, Targets cambiantes, arquitectura, memoria y Generalization. Primero debemos comprender la diferencia matemática entre \(Q(s',a')\) de SARSA y \(\max_a Q(s',a)\) de Q-Learning. Además, DQN estándar supone acciones discretas; Continuous Control frecuentemente requiere otras familias de algoritmos.

28. Laboratorio ejecutable II: aprender valores desde episodios muestreados

El segundo laboratorio entrena realmente dos Agents tabulares, en lugar de devolver solo fórmulas de referencia. Ambos utilizan el mismo entorno determinista de cuatro acciones, gamma .9, epsilon .5 y Random Seeds fijos. Un tamaño de paso por pareja State–Action de \(\alpha_n=1/n\) utiliza el número de visitas para promediar evidencia repetida, en vez de asignar peso indefinidamente alto a muestras recientes.

import random
GAMMA=0.9
EPSILON=0.5
ACTIONS={'D':('direct','via'), 'J':('express','standard')}

def run(algorithm,seed=300,episodes=100000):
    rng=random.Random(seed)
    Q={(s,a):0.0 for s in ACTIONS for a in ACTIONS[s]}
    N={(s,a):0 for s,a in Q}
    def choose(s):
        actions=ACTIONS[s]
        if rng.random()<EPSILON: return rng.choice(actions)
        top=max(Q[s,a] for a in actions)
        options=[a for a in actions if abs(Q[s,a]-top)<1e-12]
        return rng.choice(options)
    for _ in range(episodes):
        state='D'; action=choose(state)
        while True:
            reward, next_state = ({'direct':(5,'T'),'via':(-1,'J')}
                                    if state=='D' else
                                    {'express':(7,'T'),'standard':(5,'T')})[action]
            next_action=choose(next_state) if next_state!='T' else None
            bootstrap=0.0 if next_state=='T' else (
                Q[next_state,next_action] if algorithm=='SARSA'
                else max(Q[next_state,a] for a in ACTIONS[next_state]))
            key=(state,action);N[key]+=1
            alpha=1.0/N[key]
            Q[key]+=alpha*(reward+GAMMA*bootstrap-Q[key])
            if next_state=='T': break
            state,action=next_state,next_action
    return Q,N

for method in ('Q-Learning','SARSA'):
    Q,N=run(method)
    print(method,[(k,round(Q[k],6),N[k]) for k in Q])
print('reference greedy 5.3 / ongoing behavior 4.85')

Inspecciona recuentos de visitas además de Q-values: una pareja no visitada no tiene una estimación sustentada por observaciones. El valor aprendido por Q-Learning para via J debería aproximarse a 5.3, mientras que el valor On-Policy SARSA con epsilon=.5 persistente debería aproximarse a 4.85, sujeto al muestreo finito y a las condiciones de aprendizaje. Estos resultados provienen de un entorno sintético determinista; no constituyen validación de un almacén real.

Laboratorio III — Reposición de inventarios: desde una actualización hasta curvas de aprendizaje repetidas

¿Por qué una segunda aplicación? El ejemplo del depósito aísla la diferencia entre las actualizaciones TD On-Policy y Off-Policy. Ahora transferimos las mismas ideas a un simulador de inventario sintético, la segunda aplicación establecida en el Blueprint curricular. Los tres estados de existencias, las órdenes legales y las demandas aleatorias no proceden de una tienda real. Permiten comprobar aritmética, reproducibilidad y transferencia del razonamiento, no afirmar ganancias operativas.

Estado y acción. Al comenzar un día quedan \(s\in\{0,1,2\}\) unidades. Se piden \(a\in\{0,\ldots,2-s\}\) unidades, recibidas antes de la demanda; la capacidad máxima del estante es de dos unidades. Los pares State–Action legales son \((0,0),(0,1),(0,2),(1,0),(1,1),(2,0)\). Un inventario de dos unidades no puede solicitar una tercera. El siguiente State equivale a las unidades restantes después de vender. Suponemos demandas diarias independientes entre sí y de las acciones, con \(P(d=0)=0.2,\ P(d=1)=0.5,\ P(d=2)=0.3\). Estas probabilidades describen el simulador para nuestra auditoría; el Agent observa demandas individuales, no recibe la tabla de probabilidades.

Para calcular el Reward, primero obtenemos \(x=s+a\) unidades disponibles, ventas \(u=\min(x,d)\), inventario final \(s'=x-u\) y demanda perdida \(\ell=d-u\). La contribución inmediata, en dólares, es

\[r=7u-\left(\mathbf 1_{a>0}+1.5a\right)-1(s')-5\ell .\]

El indicador \(\mathbf 1_{a>0}\) vale 1 si se hace un pedido y 0 en caso contrario. Consideremos inventario inicial 0, pedido 1 y demanda 1. Hay \(0+1=1\) unidad disponible; ventas \(\min(1,1)=1\); sobrante \(1-1=0\); venta perdida \(1-1=0\). Por tanto, \(r=7(1)-(1+1.5(1))-1(0)-5(0)=7-2.5=\boxed{4.5}\) dólares y el siguiente State es 0. Si todos los Q-values comienzan en cero, la primera actualización Q-Learning para ese par usa \(n=1,\alpha_1=1\), TD Target \(4.5+0.9\max_b0=4.5\), TD Error \(4.5-0=4.5\) y nuevo valor \(Q(0,1)=0+1(4.5)=\boxed{4.5}\). Esto es una actualización muestreada, no el valor a largo plazo de la acción.

Comprobación independiente del Reward aleatorio. Mantenemos inventario inicial 0 y pedido 1, pero variamos la demanda. Con demanda 0: no se vende nada, queda una unidad y \(r=0-2.5-1=-3.5\). Con demanda 1: \(r=4.5\). Con demanda 2: se vende una unidad y se pierde otra, por lo que \(r=7-2.5-5=-0.5\). El Reward inmediato esperado es \(0.2(-3.5)+0.5(4.5)+0.3(-0.5)=-0.7+2.25-0.15=\boxed{1.4}\) dólares. No equivale al Q-value: este también incorpora consecuencias futuras descontadas, dependientes del stock. Conocer las probabilidades verdaderas sirve para nuestra auditoría, pero ninguno de los dos algoritmos Model-Free las necesita durante el aprendizaje.

Contrato de evaluación. Ocho semillas independientes de entrenamiento (310–317) producen 3,000 episodios simulados cada una por algoritmo, con 15 días por episodio; el stock inicial se restablece a 1 en cada episodio. La tarea descontada subyacente es continua: aquí cada reinicio representa un corte artificial de trayectoria, no un estado terminal. En consecuencia, incluso en el día 15 la actualización TD utiliza el Q-value del siguiente inventario; sustituirlo erróneamente por cero cambiaría el problema. Los dos algoritmos reciben el mismo flujo de demanda para una misma semilla, pero pueden elegir distintas acciones exploratorias y seguir trayectorias distintas. Se pueden explorar los seis pares legales. Usamos \(\alpha_n=n^{-0.6}\), donde \(n\) cuenta visitas a cada par, no una cuenta global.

En los puntos 0, 1, 2, 5, 10, 25, 100, 400, 1,200 y 3,000 congelamos la Q-table y evaluamos su Greedy Policy, sin acciones exploratorias ni actualizaciones. Todos los puntos usan las mismas 200 trayectorias sintéticas de demanda reservadas para evaluación (12 días cada una, con stock inicial 1); no se introducen al entrenamiento. La métrica de la figura es el promedio aritmético de la contribución diaria en dólares sin descuento. El entrenamiento sigue optimizando el Return descontado con \(\gamma=0.9\); la métrica de evaluación es un resumen operativo y no constituye el TD Target. Reutilizar estos escenarios para informes sucesivos es transparente, pero no equivale a nuevas pruebas independientes después de seleccionar entre checkpoints.

Comprobación numérica compacta tomada de las ejecuciones guardadas: las cifras siguientes son promedios de ocho semillas, en dólares por día de evaluación; los ± corresponden a desviaciones estándar muestrales. En el episodio 0, ambos tienen el valor inicial determinístico \(-4.425\). En el episodio 1, Q-Learning obtiene \(3.26930\pm0.63648\) y SARSA \(3.22443\pm0.84850\). En el episodio 25, ambos promedian \(4.13734\pm0.22200\). Desde el episodio 100, ambos alcanzan \(4.21583\) sin variación dentro de este conjunto finito de políticas Greedy evaluadas; la variación cero no significa certeza sobre los Q estimados ni sobre resultados futuros.

Por qué SARSA y Q-Learning difieren en magnitud. En la tabla final de la semilla 310, Q-Learning estima \(Q(0,2)\approx41.725\) dólares descontados, mientras que SARSA estima \(Q(0,2)\approx38.390\). SARSA usa la siguiente acción de comportamiento, elegida con \(\varepsilon=0.2\), en su Target; Q-Learning usa la acción legal de mayor valor estimado en el siguiente State. Ambas Policies coinciden aquí porque pedir dos unidades desde stock cero ocupa el primer lugar en ambas tablas. Este único simulador sencillo no demuestra que un algoritmo domine al otro en general.

import random, statistics
GAMMA = 0.9
EPSILON = 0.2
TRAIN_DAYS = 15
EVAL_DAYS = 12
CHECKPOINTS = (0,1,2,5,10,25,100,400,1200,3000)
SEEDS = tuple(range(310,318))
ACTIONS = {0:(0,1,2),1:(0,1),2:(0,)}

def inventory_step(stock, order, demand):
    assert order in ACTIONS[stock] and demand in (0,1,2)
    available=stock+order
    sales=min(available,demand)
    remaining=available-sales
    lost=demand-sales
    order_cost=(1+1.5*order) if order else 0.0
    reward=7.0*sales-order_cost-remaining-5.0*lost
    return remaining,reward

def demand_from(rng):
    u=rng.random()
    return 0 if u<0.2 else 1 if u<0.7 else 2

def choose(stock,q,rng):
    a=ACTIONS[stock]
    if rng.random()<EPSILON:return rng.choice(a)
    mx=max(q[(stock,act)] for act in a)
    ties=[act for act in a if abs(q[(stock,act)]-mx)<1e-10]
    return rng.choice(ties)

# Frozen, common, unseen evaluation demand traces; no training updates.
evaluation_paths=[]
for j in range(200):
    eval_rng=random.Random(100_000+j)
    evaluation_paths.append([demand_from(eval_rng) for _ in range(EVAL_DAYS)])

def greedy_action(stock,q):
    return max(ACTIONS[stock], key=lambda a:(q[(stock,a)],-a))

def score(q):
    total=0.0
    for path in evaluation_paths:
        stock=1
        for demand in path:
            stock,reward=inventory_step(stock,greedy_action(stock,q),demand)
            total+=reward
    return total/(len(evaluation_paths)*EVAL_DAYS)

def train(method,seed):
    q={(stock,action):0.0 for stock,actions in ACTIONS.items() for action in actions}
    visits={k:0 for k in q}
    act_rng=random.Random(seed)
    demand_rng=random.Random(seed+10000)
    scores={0:score(q)}
    history={0:q.copy()}
    for episode in range(1,max(CHECKPOINTS)+1):
        stock=1
        action=choose(stock,q,act_rng)
        for day in range(TRAIN_DAYS):
            demand=demand_from(demand_rng)
            next_stock,reward=inventory_step(stock,action,demand)
            next_action=choose(next_stock,q,act_rng)
            bootstrap=(q[(next_stock,next_action)] if method=='SARSA' else
                       max(q[(next_stock,a)] for a in ACTIONS[next_stock]))
            k=(stock,action)
            visits[k]+=1
            alpha=visits[k]**(-0.6)
            q[k]+=alpha*(reward+GAMMA*bootstrap-q[k])
            stock,action=next_stock,next_action
        if episode in CHECKPOINTS:
            scores[episode]=score(q)
            history[episode]=q.copy()
    return scores,history,visits

assert inventory_step(0,1,1)==(0,4.5)
assert abs(0.2*(-3.5)+0.5*4.5+0.3*(-0.5)-1.4)<1e-12
runs={m:[train(m,seed) for seed in SEEDS]

Interpretación y limitaciones. Todos los valores son contribuciones en dólares sintéticos: no incluyen plazos de proveedor, caducidad, pedidos pendientes, variación temporal de demanda ni restricciones reales de nivel de servicio. Suponemos reposición inmediata y capacidad de dos unidades. En una aplicación empresarial habría que volver a validar probabilidades, precios, costos y restricciones. La evaluación Greedy con trayectorias congeladas es una comparación didáctica, no un experimento A/B real ni autorización para desplegar decisiones de compra. Si el pedido demorara dos días, el stock ya no sería un State suficiente: habría que incluir las órdenes pendientes y sus fechas de llegada.

29. Limitaciones científicas, seguridad y evaluación Offline

Los Offline RL logs históricos fueron producidos por una Behavior Policy anterior; no necesariamente aportan evidencia sobre acciones nunca realizadas. Si standard nunca fue probado en J, su resultado carece de apoyo directo en esos registros. El cociente matemáticamente indefinido \(\pi_{\rm target}(a|s)/\pi_{\rm behavior}(a|s)\) cuando la probabilidad de comportamiento es cero ilustra una limitación de cobertura de Off-Policy Evaluation con ponderaciones. La falta de soporte no se resuelve solo ejecutando más iteraciones de Optimization.

Antes de cualquier implementación real, debemos establecer restricciones de seguridad, pérdidas máximas toleradas, intervención humana, procedimientos alternativos y escenarios representativos de evaluación. La validez de un cálculo manual, el éxito en simulación, la Generalization estadística desde registros y el beneficio físico medido requieren evidencias diferentes. Nuestros Rewards logísticos son sintéticos y sencillos; no permiten afirmar efectividad industrial real.

Transferencia: supongamos que standard es la única ruta legal para carga peligrosa. La Policy factible óptima en J será standard aunque valga 5 y express valga 7. Es un conjunto de acciones restringido, no una contradicción matemática: maximizar sobre acciones permitidas cambia Bellman. El valor via J desde D será \(-1+0.9(5)=3.5\), así que direct=5 gana si también está permitido.

31. Diecinueve ejercicios resueltos y Student Understanding Test final

Resuelve las preguntas antes de desplegar las soluciones completamente razonadas. El primer grupo reconstruye cantidades, el segundo compara algoritmos y el último modifica supuestos, restricciones y condiciones de evaluación. Memorizar las etiquetas «On-Policy» y «Off-Policy» no basta para superar la prueba.

1. Identifica los States no terminales y cuántas parejas State–Action válidas existen.

D permite direct y via J; J permite express y standard. En total 2+2=4 parejas. T es terminal, sin acción y con valor futuro cero por convención.

2. Calcula el Return via J con express para gamma=.9.

Reward −1 ahora y express +7 un paso después: −1+.9×7=−1+6.3=5.3 puntos. No multiplicar −1 por .9.

3. Calcula el Return via J con standard.

−1+.9×5=−1+4.5=3.5. Direct vale 5, por tanto via J seguido de standard es 1.5 puntos inferior.

4. Calcula probabilidades epsilon-greedy en J con epsilon=.5.

Rama Exploitation .5 más rama aleatoria .5×1/2=.25 resulta express .75; standard tiene .25. Suman 1.

5. Calcula el Reward esperado en J bajo esa Behavior Policy.

0.75×7+0.25×5=5.25+1.25=6.5 puntos; es .5 inferior a elegir express siempre.

6. Calcula la transición SARSA D→J con Q(D,via)=2 y siguiente standard Q=5.

Target=−1+.9×5=3.5; TD Error=3.5−2=1.5; Q nuevo=2+.5×1.5=2.75.

7. Calcula Q-Learning desde la misma transición y compara.

Target=−1+.9×max(7,5)=5.3; TD Error=5.3−2=3.3; Q nuevo=2+.5×3.3=3.65; diferencia frente a SARSA=.90.

8. Calcula Expected SARSA y distingue la esperanza de una muestra.

Esperanza J=6.5, Target=−1+.9×6.5=4.85; Q nuevo=2+.5×(4.85−2)=3.425, igual a .75×3.65+.25×2.75.

9. Deriva el umbral epsilon que iguala via J con direct=5.

Via J esperado=5.3−.9 epsilon. Igualamos a 5: .9 epsilon=.3, entonces epsilon=1/3. Con .5 conviene direct; con .2, via J.

10. Calcula la actualización SARSA 3a con Q(D,via)=−.75 y Q(J,express)=3.5.

Target TD=−1+.9×3.5=2.15; TD Error=2.15−(−.75)=2.90; nuevo Q D=−.75+.5×2.90=.70.

11. Calcula Q-Learning 2a desde −.5 con estimaciones J de 3.5 y 0.

Target=−1+.9×3.5=2.15; Q nuevo=−.5+.5[2.15−(−.5)]=−.5+1.325=.825.

12. Calcula el Return inicial esperado del comportamiento SARSA con epsilon=.5.

En D, direct Greedy se elige .75 y via J .25. La continuación por J vale 4.85. Total=.75×5+.25×4.85=3.75+1.2125=4.9625.

13. Transferencia: cambia gamma a .8. ¿Qué ruta Greedy gana?

Via express=−1+.8×7=−1+5.6=4.6; direct=5. Gana direct por .4. Gamma importa porque express ocurre un paso después.

14. Transferencia: express pasa a +10 con probabilidad .9 y −20 con .1.

Reward esperado J=.9×10+.1×(−20)=7. Return esperado desde D=−1+.9×7=5.3, pero los resultados realizados son 8 y −19: igual media no implica igual riesgo.

15. Transferencia: express queda prohibido para carga peligrosa. ¿Qué primera Action es óptima?

En J solo standard=5 está permitida, así que via J=−1+.9×5=3.5. Direct=5 gana si también es legal. La restricción de acciones cambia el máximo.

16. ¿Por qué puede fallar Q-Learning Offline para acciones no observadas y cómo evaluar con seguridad?

Sin observaciones, no hay resultados respaldados por los registros; Importance Sampling es indefinido si probabilidad de comportamiento=0. Se requiere cobertura autorizada o restricciones, simulación validada, separación Training/Test y supervisión humana.

17. Transferencia: calcule toda la transición de inventario y la primera actualización Q.

Con stock inicial 0, pedido 1 y demanda 1, se dispone de \(0+1=1\) unidad, se vende \(\min(1,1)=1\), queda \(1-1=0\) y no hay demanda perdida. Los ingresos son $7, el pedido cuesta \(1+1.5=2.5\) y los costos de almacenamiento y desabastecimiento son cero: Reward inmediata $4.5. En la primera visita \(\alpha_1=1\), con \(Q(0,1)=0\) y máximo Q siguiente de cero, Target \(4.5+0.9(0)=4.5\). Nuevo Q: \(0+1(4.5-0)=4.5\). Es una muestra, no el Return esperado a largo plazo.

18. Transferencia: aumente la penalidad por demanda perdida a $8. Recalcule el Reward inmediato esperado de pedir una unidad con stock cero.

Con demanda 0, el Reward permanece en −$3.5 (una unidad sobrante y costo de pedido $2.50); con demanda 1, en $4.5. Con demanda 2 se vende una y se pierde una: \(7-2.5-8=-3.5\). Ponderando por probabilidades, \(0.2(-3.5)+0.5(4.5)+0.3(-3.5)=-0.7+2.25-1.05=\boxed{0.50}\) dólares; antes era $1.40. Una penalidad mayor reduce el Reward esperado de esta acción en $0.90, pero eso no demuestra por sí solo que la orden óptima a largo plazo siga siendo la misma: hay que evaluar inventario futuro y órdenes alternativas.

19. ¿Por qué puede coincidir el desempeño Greedy si los Q-values difieren, y qué cambia si el pedido tarda dos días?

La evaluación Greedy utiliza solo la acción legal mejor clasificada en cada State. Con la semilla 310, Q-Learning estima \(Q(0,2)\approx41.725\) y SARSA aproximadamente 38.390, pero ambos clasifican primero pedir dos unidades cuando el stock es cero; las acciones Greedy finales con stocks 0, 1 y 2 son 2, 1 y 0. Las mismas trayectorias reservadas producen por ello el mismo promedio. Los Targets difieren: Q-Learning maximiza el Q siguiente y SARSA usa la siguiente acción exploratoria efectivamente escogida. Si los pedidos demoran dos días, el State debe incluir las órdenes pendientes y fechas estimadas de llegada, además del inventario disponible. De lo contrario falla el supuesto Markov y la tabla actual de seis pares no representa bien el problema.

32. Glosario: mapa final del proceso de aprendizaje

La terminología de Reinforcement Learning es más clara cuando cada término responde una pregunta específica. Utiliza el glosario al reproducir los dos laboratorios, no como sustituto de las demostraciones. «Value», «Target» y «Return» parecen similares en una conversación informal, pero representan cálculos diferentes.
