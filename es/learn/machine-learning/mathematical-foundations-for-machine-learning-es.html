1. Las matemáticas son el lenguaje con el que aprendemos de los datos

Un técnico observa que algunas máquinas industriales presentan vibraciones anormales antes de fallar. ¿Podríamos combinar mediciones de sensores para ayudar a priorizar inspecciones? Esta guía utiliza esa pregunta para conectar las bases matemáticas que aparecen una y otra vez en Machine Learning (ML). No pretendemos que seis observaciones permitan implementar un sistema confiable de seguridad: construimos intencionalmente un dataset pequeño para que el estudiante pueda verificar cada cifra.

Un modelo recibe inputs numéricos, los combina mediante operaciones matemáticas, produce una predicción y, cuando corresponde, ajusta Parameters aprendidos. Estas tareas relacionan cuatro ámbitos: Linear Algebra representa la información; Calculus permite estudiar cambios y optimización; Probability y Statistics cuantifican incertidumbre; y Geometry ayuda a comprender semejanza y distancia. No son capítulos independientes: sus ideas se encuentran dentro de los mismos algoritmos.

Dataset ilustrativo completo

Máquina Temperatura (°C) Vibración (mm/s) Falla en los próximos 30 días (y)
A 60 2 0
B 70 3 1
C 65 4 0
D 80 6 1
E 75 5 0
F 85 7 1

Una Observation corresponde a una máquina en una fecha de referencia. Sus Features son la temperatura y la vibración conocidas entonces; su Target indica si falló durante los 30 días siguientes (1 = sí; 0 = no). Las etiquetas fueron inventadas, no provienen de mediciones reales. La máquina B falla pese a tener sensores moderados y E no falla aunque sus lecturas sean elevadas: incluso un ejemplo elemental debe mostrarnos por qué no basta con aplicar un umbral a ciegas.

Ejemplo conductor. Representaremos A mediante un Vector, combinaremos Features con un Dot Product, calcularemos el output de un modelo probabilístico hipotético, ejecutaremos una actualización de Gradient Descent y usaremos las etiquetas para aprender Conditional Probability y analizar errores. Los modelos avanzados se desarrollarán en guías posteriores.

Al terminar deberías poder interpretar las dimensiones y unidades de una fórmula, reproducir operaciones con Vectors y Matrices, explicar Derivatives y Gradients, aplicar Bayes' Theorem y distinguir cuidadosamente un cálculo didáctico de evidencia suficiente para desplegar un modelo real.

2. Scalars, Variables, unidades y notación matemática

Un Scalar es un número individual, como 60°C o una etiqueta binaria 0. Una Feature es una característica observada; una Variable puede asumir distintos valores. Un Parameter es una cantidad que utiliza un modelo para transformar Features en un output. Conviene no confundirlos: la temperatura es un input, el coeficiente que la multiplica es un Parameter y la probabilidad estimada es un resultado.

Porcentajes, puntos porcentuales y unidades

Si la vibración sube de 2 a 3 mm/s, el cambio absoluto es 1 mm/s y el aumento relativo es \((3-2)/2\times100=50\%\). Si una tasa estimada de fallas pasa de 10% a 15%, el cambio absoluto equivale a 5 puntos porcentuales, mientras que el cambio relativo es \((15-10)/10=50\%\). Describirlos incorrectamente produce interpretaciones engañosas incluso cuando la aritmética está bien hecha.

Dos cifras no deben sumarse simplemente porque aparecen en la misma tabla. La operación \(60+2=62\) es válida como aritmética pura, pero sumar grados Celsius con mm/s carece de significado físico. Las sumas ponderadas pueden resultar útiles si sus coeficientes tienen unidades coherentes o si transformamos correctamente las Features. Siempre debemos preguntar qué unidades necesita cada coeficiente para interpretar el output.

Índices y símbolos para representar una fila

Sea \(i\) el identificador de una máquina, \(x_{i1}\) su temperatura, \(x_{i2}\) su vibración y \(y_i\) la etiqueta observada de falla. Para C, \(x_{31}=65\), \(x_{32}=4\) y \(y_3=0\). El 3 en el subíndice identifica una fila: no significa elevar una variable a la tercera potencia. En cambio, \(x_{31}^2=65^2\) representa el cuadrado de la medición.

\[x_{i1}=\text{temperatura},\qquad x_{i2}=\text{vibración},\qquad y_i\in\{0,1\}\]

El símbolo \(\in\) significa «pertenece a» y las llaves señalan los valores admisibles. Más adelante, \(\hat y\) indicará una predicción, diferente del Label observado, y \(\theta\) representará Parameters del modelo. Definir los símbolos antes de manipularlos evita confundir observaciones, predicciones y configuraciones.

Error frecuente. Un registro de 0.75 podría representar una proporción (75%) o un porcentaje de 0.75%. Si una función compara 0.75 con un umbral de 50 definido para la escala de 0 a 100, producirá resultados incorrectos aunque el código no muestre ningún error.

3. Vectors: representar una observación y medir distancias

Un Vector es una colección ordenada de números. Escribimos los sensores de A como un Column Vector: la primera posición corresponde siempre a temperatura y la segunda a vibración. Invertir silenciosamente las posiciones cambia los cálculos.

\[\mathbf{x}_A=\begin{bmatrix}60\\2\end{bmatrix},\qquad \mathbf{x}_D=\begin{bmatrix}80\\6\end{bmatrix}\]

Ambos pertenecen a \(\mathbb{R}^2\), el espacio de dos coordenadas reales. La resta de Vectors se realiza posición por posición: \(\mathbf{x}_D-\mathbf{x}_A=[20,4]^T\). Multiplicar un Vector por 2 duplica cada componente: \(2\mathbf{x}_A=[120,4]^T\). Esto describe una operación matemática, no implica que una máquina real pueda duplicar temperatura sin otras consecuencias.

Norms y Euclidean Distance

La Euclidean Norm mide la longitud de un Vector y la Euclidean Distance mide la longitud de la diferencia entre dos Vectors. Si por ahora ignoramos que las unidades son incompatibles, la separación numérica entre A y D es:

\[\|\mathbf{x}_D-\mathbf{x}_A\|_2=\sqrt{(80-60)^2+(6-2)^2}=\sqrt{416}\approx20.396\]

El subíndice 2 señala la norma L2 o euclidiana. Este resultado no representa una distancia física expresable en una sola unidad, porque combina °C y mm/s: es una distancia numérica dentro de nuestra representación. La diferencia de temperatura, 20, pesa más numéricamente que la diferencia de vibración, 4.

También existe la Manhattan Distance (L1), que suma diferencias absolutas: \(|80-60|+|6-2|=24\). Sigue siendo una puntuación en el sistema de coordenadas elegido hasta justificar cómo combinar unidades. Algoritmos como k-Nearest Neighbors y k-Means dependen de estas definiciones.

Interpretación. Decir que dos máquinas son «parecidas» requiere escoger Features, escalas y una métrica de distancia. Las agrupaciones obtenidas por un algoritmo pueden cambiar al modificar razonablemente la escala, aun cuando los datos originales sean idénticos.

Geometría y dirección, además de longitud

Dos Vectors pueden tener direcciones parecidas y magnitudes distintas. El Dot Product relaciona dirección y longitud mediante \(\mathbf{a}^T\mathbf{b}=\|\mathbf{a}\|_2\|\mathbf{b}\|_2\cos\phi\), donde \(\phi\) es el ángulo entre ambos. Los Unit Vectors \([1,0]^T\) y \([0,1]^T\) tienen Dot Product cero y son perpendiculares; \([1,0]^T\) consigo mismo produce uno y tiene la misma dirección. Cosine Similarity divide entre las longitudes y no está definida para un Vector nulo. Estos conceptos ayudan a entender similitud entre embeddings de texto, pero combinar sensores con unidades incompatibles sigue requiriendo una interpretación cuidadosa.

4. Dot Product: combinar diversas Features en una puntuación

El Dot Product multiplica las posiciones correspondientes de dos Vectors y suma esos productos. Dados \(\mathbf{a}=[a_1,a_2]^T\) y \(\mathbf{b}=[b_1,b_2]^T\), obtenemos un Scalar:

\[\mathbf{a}^T\mathbf{b}=a_1b_1+a_2b_2\]

El superíndice \(T\) significa Transpose: convertir un Column Vector en Row Vector. Consideremos pesos hipotéticos \(w_T=0.04\) por °C y \(w_V=0.30\) por mm/s, junto con Intercept \(b=-4\). La puntuación lineal resultante es:

\[z=b+\mathbf{w}^T\mathbf{x}=-4+0.04\,T+0.30\,V.\]

Para la máquina A, sustituimos ambas mediciones mostrando todos los términos:

\[z_A=-4+(0.04\times60)+(0.30\times2)=-4+2.40+0.60=-1.00\]

Para F: \(z_F=-4+(0.04\times85)+(0.30\times7)=-4+3.40+2.10=1.50\). Estos Parameters fueron elegidos para enseñar, no aprendidos por un algoritmo. Como interpretamos \(z\) como puntuación sin unidades, el peso de temperatura debe poseer unidades inversas a °C y el de vibración inversas a (mm/s).

¿Por qué importa el Dot Product?

La misma estructura aparece en Linear Regression, Logistic Regression y unidades de Neural Networks. Los inputs contribuyen mediante pesos. Si mantenemos vibración constante, aumentar temperatura eleva nuestra puntuación hipotética porque su coeficiente es positivo. Esa propiedad matemática no demuestra que calentar una máquina cause una falla.

Una puntuación no necesariamente es una probabilidad. Aquí \(z_A=-1\) y \(z_F=1.5\), valores que no pertenecen ambos al intervalo de 0 a 1. Una transformación como la Sigmoid Function puede producir un resultado en (0,1); lo explicaremos luego.

Comprobación. Si la vibración de A aumentara exactamente 1 mm/s sin modificar temperatura, el score subiría 0.30. Si la temperatura aumentara 1°C, subiría 0.04. Hablamos de cambios en la puntuación bajo pesos fijos, no de aumentos demostrados en el riesgo real de falla.

Descomponer un cambio en contribuciones de Features

Comparemos A y D: la temperatura aumenta 20°C y la vibración 4 mm/s. Al restar los scores, el Intercept se cancela: \(z_D-z_A=0.04(80-60)+0.30(6-2)=0.80+1.20=2.00\). También sabemos que \(z_D=1\) y \(z_A=-1\), así que la diferencia es \(1-(-1)=2\). Los componentes 0.80 y 1.20 descomponen legítimamente este score lineal definido por nosotros. No son estimaciones de efectos causales de sensores ni contribuciones físicas demostradas al riesgo real de avería.

5. Matrices: representar todo el dataset y conservar su significado

Una Matrix es una tabla rectangular de números. Tenemos seis máquinas y dos Features de sensores, de modo que nuestra Feature Matrix contiene seis filas y dos columnas. Normalmente colocamos Observations en filas y Features en columnas:

\[X=\begin{bmatrix}60&2\\70&3\\65&4\\80&6\\75&5\\85&7\end{bmatrix}\in\mathbb{R}^{6\times2},\qquad \mathbf{y}=\begin{bmatrix}0\\1\\0\\1\\0\\1\end{bmatrix}\in\mathbb{R}^{6}.\]

Las dimensiones establecen un contrato: \(X\) tiene Shape 6×2 y las filas siguen el orden A–F. Los Labels constituyen un Vector de seis posiciones. Transponer la Matrix produce \(X^T\in\mathbb{R}^{2\times6}\): las seis temperaturas aparecen en una fila y las vibraciones en otra. Transpose reordena ejes, no cambia ninguna medición.

Incorporar una columna para el Intercept

Nuestra puntuación incluye el término \(b\), constante para todas las máquinas. Podemos integrarlo en una Design Matrix, agregando una primera columna de unos:

\[\widetilde X=\begin{bmatrix}1&60&2\\1&70&3\\1&65&4\\1&80&6\\1&75&5\\1&85&7\end{bmatrix},\quad \boldsymbol\theta=\begin{bmatrix}-4\\0.04\\0.30\end{bmatrix}.\]

Ahora las dimensiones son 6×3 y 3×1; por tanto, \(\widetilde X\boldsymbol\theta\) entrega un Vector 6×1. Su primera fila produce \(1(-4)+60(0.04)+2(0.30)=-1\). Para poder efectuar una multiplicación convencional de Matrices, el número de columnas del primer factor debe coincidir con el número de filas del segundo.

Esta representación no significa que los Labels futuros estén disponibles durante la predicción. Se muestran junto a los inputs para explicar matemáticas, pero un Pipeline verdadero debe impedir que resultados posteriores entren accidentalmente en los inputs históricos.

Las dimensiones no bastan para definir el significado

Imaginemos un dataset nuevo con 200 filas y tres columnas de sensores. Su Shape sería 200×3, pero ese número no indica si la tercera columna es presión, horas de funcionamiento o un Label duplicado por error. Necesitamos un Feature Schema que defina nombre, unidades, fecha de disponibilidad y orden de cada columna. Si incorporamos Intercept, la Design Matrix será 200×4 y el Parameter Vector deberá tener cuatro entradas. Comprobar dimensiones protege la aritmética; comprobar el Schema protege la interpretación. Ambas verificaciones son necesarias para reproducir Machine Learning.

6. Matrix Multiplication, Linear Transformations y dimensiones compatibles

La Matrix Multiplication no consiste en multiplicar posiciones correspondientes. Si \(A\in\mathbb{R}^{m\times n}\) y \(B\in\mathbb{R}^{n\times p}\), el producto \(AB\) tendrá dimensiones \(m\times p\). Cada elemento de salida es el Dot Product de una fila de A y una columna de B.

Un cálculo pequeño, completo y verificable

Sean \(A=\begin{bmatrix}1&2\\3&4\end{bmatrix}\) y \(B=\begin{bmatrix}2&0\\1&5\end{bmatrix}\). Calculemos las cuatro entradas:

\[AB=\begin{bmatrix}1(2)+2(1)&1(0)+2(5)\\3(2)+4(1)&3(0)+4(5)\end{bmatrix}=\begin{bmatrix}4&10\\10&20\end{bmatrix}.\]

Si invertimos el orden: \(BA=\begin{bmatrix}2&4\\16&22\end{bmatrix}\), distinto de \(AB\). En general, \(AB\ne BA\). Esta propiedad es fundamental al analizar transformaciones sucesivas o el orden de operaciones en modelos.

Transformar simultáneamente las seis observaciones

Tomemos \(\widetilde X\boldsymbol\theta\) de la sección anterior. El resultado es:

\[\mathbf{z}=\widetilde X\boldsymbol\theta=\begin{bmatrix}-1.00\\-0.30\\-0.20\\1.00\\0.50\\1.50\end{bmatrix}.\]

Verifiquemos la tercera entrada: \(-4+65(0.04)+4(0.30)=-4+2.6+1.2=-0.2\). La expresión matricial aplica una misma regla a las seis máquinas. En programación, no deberíamos resolver errores de Shape reorganizando arbitrariamente los arrays hasta que desaparezca el mensaje: antes debemos revisar qué representa cada dimensión.

Una Linear Transformation transforma Vectors mediante multiplicación matricial. Agregar el Intercept convierte nuestra función total en una transformación afín, no estrictamente lineal desde el punto de vista matemático. La distinción será útil al estudiar Decision Boundaries y Neural Networks.

Conexión con Python. NumPy puede calcular las seis puntuaciones con Matrix Multiplication. Pero comprender las dimensiones y el orden de las columnas es indispensable: una operación que se ejecuta sin errores no garantiza que los Features hayan sido interpretados correctamente.

Cuándo dos columnas contienen información distinta

El Determinant de una Matrix cuadrada 2×2 ayuda a estudiar dependencia algebraica. Construyamos la Matrix formada por las filas A = \([60,2]\) y B = \([70,3]\). Su Determinant es \(60(3)-70(2)=180-140=40\), distinto de cero. Por ello, sus dos Column Vectors son linealmente independientes: uno no es un múltiplo exacto del otro. Eso no significa ausencia de Correlation estadística: la sección 8 encuentra una asociación importante. La dependencia lineal es una propiedad algebraica exacta; Correlation mide una relación estadística gradual. Para Matrices no cuadradas se razona con Rank en vez de calcular su Determinant.

Multiplicar matrices rectangulares: cada entrada tiene una procedencia

Para comprobar que las dimensiones son algo más que una regla memorizada, considera estas matrices abstractas (sin unidades físicas):

\[A=\begin{bmatrix}1&2&0\\0&1&3\end{bmatrix}\in\mathbb R^{2\times3},\qquad B=\begin{bmatrix}2&1\\1&0\\0&2\end{bmatrix}\in\mathbb R^{3\times2}.\]

Sus dimensiones internas coinciden (3 y 3). Para obtener la entrada superior izquierda, multiplicamos la primera fila por la primera columna: \(1(2)+2(1)+0(0)=4\). Repetimos para las otras tres entradas, sin omitir ninguna:

\[AB=\begin{bmatrix}1(2)+2(1)+0(0)&1(1)+2(0)+0(2)\\0(2)+1(1)+3(0)&0(1)+1(0)+3(2)\end{bmatrix}=\begin{bmatrix}4&1\\1&6\end{bmatrix}.\]

El resultado tiene forma 2×2: dos filas de salida y dos columnas. Un intento de calcular \(AA\) está mal definido porque las dimensiones interiores serían 3 y 2, que no coinciden. La comprobación de formas evita sumar o multiplicar cantidades que el programa no puede interpretar.

7. Feature Scaling, Norms y el significado de máquinas «similares»

En la sección 3 calculamos una distancia euclidiana que mezclaba temperatura y vibración en escalas numéricas distintas. Feature Scaling transforma las coordenadas para evitar que las diferencias de magnitud dominen arbitrariamente métodos basados en distancias, Regularization u Optimization.

Como ejemplo, dividamos las diferencias de temperatura entre 10°C y las diferencias de vibración entre 2 mm/s. De A a B hay 10°C y 1 mm/s de diferencia; el Vector de diferencias escaladas es \([10/10,\ 1/2]=[1,0.5]\). Ahora calculamos:

\[d_{AB,\mathrm{scaled}}=\sqrt{1^2+0.5^2}=\sqrt{1.25}\approx1.118.\]

Con valores sin Scaling, la distancia numérica sería \(\sqrt{10^2+1^2}=\sqrt{101}\approx10.05\). Ninguno de los dos números es intrínsecamente correcto para toda finalidad: representan diferentes decisiones sobre el peso relativo de las Features. Una práctica rigurosa comprueba qué transformación resulta apropiada para cada algoritmo.

Standardization usando estadísticas observadas

La Standardization suele emplear \(z=(x-\bar x)/s\), donde \(\bar x\) es la media de Training y \(s\) su Sample Standard Deviation. Para nuestras seis temperaturas, \(\bar x=72.5\)°C y \(s\approx9.354\)°C. A queda con temperatura estandarizada \((60-72.5)/9.354\approx-1.336\). No tiene unidades porque numerador y denominador se expresan en °C.

No confundas este z-score con el linear score \(z=b+\mathbf{w}^T\mathbf{x}\). Se utiliza la misma letra en varios contextos; la definición determina su significado.

Data Leakage. En un Workflow real calculamos medias y Standard Deviations con Training y reutilizamos esos resultados intactos sobre Validation, Test y nuevas observaciones. Calcularlos con los conjuntos reservados permitiría que su información influyera en el proceso de desarrollo.

Scaling resulta especialmente importante en k-NN, k-Means, SVM, Optimization por gradientes y distintas formas de Regularization. Los árboles de decisión suelen ser relativamente insensibles a transformaciones monótonas de Features numéricas. Por ello, «siempre hay que escalar» es menos útil que comprender el mecanismo matemático del método elegido.

Calcular una distancia después de Standardization

Volvamos a A y B. Sus diferencias son 10°C y 1 mm/s. Al dividir entre Sample Standard Deviations de 9.354°C y 1.871 mm/s, las diferencias estandarizadas son aproximadamente \(10/9.354=1.069\) y \(1/1.871=0.534\). Así, su Euclidean Distance estandarizada es \(\sqrt{1.069^2+0.534^2}\approx1.195\). La distancia numérica sin Scaling era \(\sqrt{101}\approx10.05\). Como restamos dos observaciones, sustraer la misma media se cancela; dividir entre una escala estimada no se cancela. Scaling cambia la geometría aunque preserve el orden de una Feature numérica individual.

8. Covariance, Correlation y dependencia entre Features

Antes de construir un modelo conviene investigar si dos Features varían conjuntamente. Covariance resume si una temperatura superior a su media suele aparecer con una vibración también superior a la suya. Correlation estandariza esa asociación en una escala de −1 a 1 cuando ambas variables presentan variación.

En nuestros seis registros, temperatura media = 72.5°C y vibración media = 4.5 mm/s. Calcularemos desviaciones y productos para verificar el resultado sin ocultarlo detrás de una función.

Máquina T − 72.5 V − 4.5 Producto
A −12.5 −2.5 31.25
B −2.5 −1.5 3.75
C −7.5 −0.5 3.75
D 7.5 1.5 11.25
E 2.5 0.5 1.25
F 12.5 2.5 31.25
Total 82.50

La Sample Covariance divide la suma entre \(n-1=5\), no entre 6:

\[s_{TV}=\frac{82.5}{5}=16.5\ \mathrm{(^{\circ}C)(mm/s)}.\]

Las Sample Variances son \(s_T^2=87.5\) °C² y \(s_V^2=3.5\) (mm/s)², así que las Sample Standard Deviations son \(\sqrt{87.5}\approx9.354\)°C y \(\sqrt{3.5}\approx1.871\) mm/s. Por consiguiente,

\[r_{TV}=\frac{16.5}{\sqrt{87.5}\sqrt{3.5}}\approx0.943.\]

Una Correlation positiva próxima a 1 indica que estas seis observaciones tienden a aumentar juntas siguiendo aproximadamente una relación lineal. No demuestra que temperatura cause vibración, que ambas causen fallas ni que la asociación se mantenga en otra población. Se trata de seis casos construidos con fines didácticos.

¿Para qué sirve este resultado en Machine Learning?

Features muy relacionadas pueden aportar información redundante. En algunos modelos lineales generan coeficientes inestables y complican la interpretación individual aunque las predicciones puedan ser útiles. En PCA, Covariance y Eigenvectors permiten encontrar direcciones de variación conjunta. Las consecuencias profundas se desarrollarán en sus propias guías.

Comprobar de dónde salen las cifras de Variance

Las desviaciones de temperatura respecto de 72.5 son \(-12.5,-2.5,-7.5,7.5,2.5,12.5\). Sus cuadrados suman \(156.25+6.25+56.25+56.25+6.25+156.25=437.5\); dividir entre cinco produce \(s_T^2=87.5\). Para vibración, la suma es 17.5 y \(s_V^2=17.5/5=3.5\). Utilizamos el mismo denominador muestral que en Covariance. Si expresáramos temperatura en Fahrenheit en lugar de Celsius, cambiaría la cifra de Covariance por la conversión de unidades, mientras que Correlation se mantendría igual bajo un Scaling lineal positivo. Por eso Correlation suele resultar más comparable entre unidades distintas.

9. Functions y Sigmoid: transformar un score en un resultado probabilístico

Una Function asigna un output a cada input permitido. Nuestro score \(z=-4+0.04T+0.30V\) es una función afín de los sensores. Podemos transformarlo mediante la Sigmoid Function:

\[\sigma(z)=\frac{1}{1+e^{-z}}.\]

Para cualquier valor real finito de \(z\), su output está estrictamente entre 0 y 1. Si \(z=0\), entonces \(\sigma(0)=1/(1+1)=0.5\). Para A, \(z=-1\), de modo que \(\sigma(-1)=1/(1+e^1)\approx0.2689\). Para F, \(z=1.5\) y \(\sigma(1.5)=1/(1+e^{-1.5})\approx0.8176\).

A −1.00 0.2689 0 0
B −0.30 0.4256 0 1
C −0.20 0.4502 0 0
D 1.00 0.7311 1 1
E 0.50 0.6225 1 0
F 1.50 0.8176 1 1

El modelo marca D, E y F. Comparando contra los Labels: \(TP=2\) (D, F), \(FP=1\) (E), \(FN=1\) (B) y \(TN=2\) (A, C). Accuracy = \((2+2)/6=66.67\%\). No debemos afirmar que las seis salidas Sigmoid están calibradas como probabilidades reales de falla: los coeficientes fueron inventados y nunca se entrenaron ni validaron. El rango matemático de 0 a 1 no garantiza calibración empírica.

Un Decision Threshold convierte un score o una probabilidad estimada en una clase predicha. Modificar el umbral altera las decisiones, pero no altera los valores entregados por Sigmoid. En futuras guías aprenderemos a estimar coeficientes y elegir umbrales utilizando datos de desarrollo y evaluación independientes.

10. Derivatives: comprender las tasas de cambio

Calculus responde preguntas como esta: ¿a qué velocidad cambia una función cuando cambia su input? Para \(f(x)=x^2\), pasar de \(x=3\) a 3.1 aumenta el resultado de 9 a 9.61. El cambio promedio por unidad de x es \((9.61-9)/(3.1-3)=6.1\).

Una Derivative representa el límite de ese cambio por unidad cuando el intervalo se hace cada vez más pequeño:

\[f'(x)=\lim_{h\to0}\frac{f(x+h)-f(x)}{h}.\]

Sustituyamos \(f(x)=x^2\) y desarrollemos algebraicamente:

\[\frac{(x+h)^2-x^2}{h}=\frac{x^2+2xh+h^2-x^2}{h}=2x+h.\]

Al tomar \(h\to0\), queda \(f'(x)=2x\). En \(x=3\), la pendiente instantánea es 6, coherente con que nuestra estimación por intervalo de 6.1 se acerque a 6 cuando reducimos el paso.

Interpretar signo y unidades

Una Derivative positiva indica que localmente la función aumenta al aumentar su input; una negativa, que disminuye. Una Derivative cero indica un punto estacionario, no necesariamente un mínimo. Sus unidades son «unidades del output por unidad del input». Para el score lineal hipotético, \(\partial z/\partial T=0.04\) por °C y \(\partial z/\partial V=0.30\) por mm/s.

La Derivative de Sigmoid es \(\sigma'(z)=\sigma(z)[1-\sigma(z)]\). En \(z=0\) equivale a \(0.5(1-0.5)=0.25\). Por ello, un cambio pequeño de 0.1 en el score cerca de cero produce un cambio aproximado de 0.025 en el output de Sigmoid, mediante una aproximación local. Ya podemos empezar a comprender cómo se modifican las predicciones cuando cambia un Parameter.

Por qué necesitamos Derivatives. Un algoritmo de Optimization debe calcular o estimar cómo cambia su objetivo al mover un Parameter. Las Derivatives proporcionan información local sobre dirección y magnitud, pero no garantizan que un paso arbitrariamente grande mejore el resultado.

Comprobar el límite desde diferentes aproximaciones

Con un paso más pequeño, de 3 a 3.01, la tasa promedio es \([(3.01)^2-3^2]/0.01=(9.0601-9)/0.01=6.01\). También podemos usar una diferencia simétrica \([f(3+h)-f(3-h)]/(2h)\), que para \(f(x)=x^2\) se simplifica exactamente a 6 para cualquier h distinto de cero. Estas diferencias numéricas permiten aproximar Derivatives con código y verificar operaciones manuales. Sin embargo, el redondeo numérico y el ruido importan cuando h se hace demasiado pequeño. Una Derivative analítica evita ese error específico de aproximación cuando podemos calcularla correctamente.

La Derivative es la pendiente de una recta tangente, no una regla misteriosa

La gráfica siguiente conecta el cociente de diferencias con la geometría. Para \(f(x)=x^2\), el punto estudiado es \((3,f(3))=(3,9)\). La derivada es \(f'(3)=2(3)=6\); por ello la recta tangente satisface \(y-9=6(x-3)\), equivalente a \(y=6x-9\).

Verificación de la pendiente. En la tangente, al pasar de \(x=3\) a \(x=4\), la altura aumenta de 9 a 15. Por tanto, \((15-9)/(4-3)=6\). En cambio, la función curva llega a \(f(4)=16\). La tangente aproxima la función cerca de 3, pero no la reemplaza globalmente.

11. Partial Derivatives y Gradient: modificar varios Parameters a la vez

Las funciones objetivo de Machine Learning suelen depender de múltiples Parameters. Una Partial Derivative mide el cambio asociado a una variable manteniendo las demás constantes. El Gradient reúne esas Partial Derivatives en un Vector que, bajo coordenadas euclidianas de Parameters, señala la dirección local de mayor incremento de una función escalar.

Consideremos esta función de dos Parameters:

\[L(w,b)=(w-3)^2+(b+1)^2.\]

Puede entenderse como una superficie de Loss matemática, no como una Loss estimada con nuestras seis máquinas. Su mínimo aparece en \(w=3\), \(b=-1\), porque entonces ambos cuadrados son cero. Manteniendo fijo \(b\), la Derivative respecto de \(w\) es \(\partial L/\partial w=2(w-3)\). Manteniendo fijo \(w\), obtenemos \(\partial L/\partial b=2(b+1)\). Por tanto:

\[\nabla L(w,b)=\begin{bmatrix}2(w-3)\\2(b+1)\end{bmatrix}.\]

En el punto inicial \((w,b)=(0,0)\), la Loss es \(L=9+1=10\) y el Gradient vale \([-6,2]^T\). Para reducir localmente la función avanzamos en dirección opuesta al Gradient: aumentamos \(w\) y disminuimos \(b\). Con Learning Rate \(\eta=0.2\), la actualización simultánea es:

\[\begin{bmatrix}w_{new}\\b_{new}\end{bmatrix}=\begin{bmatrix}0\\0\end{bmatrix}-0.2\begin{bmatrix}-6\\2\end{bmatrix}=\begin{bmatrix}1.2\\-0.4\end{bmatrix}.\]

No supongamos automáticamente que hubo mejora: recalculamos \(L(1.2,-0.4)=(1.2-3)^2+(-0.4+1)^2=3.24+0.36=3.60\). La Loss disminuyó efectivamente de 10 a 3.6.

El Gradient permite realizar una actualización conjunta. En funciones más complejas, cada Partial Derivative puede cambiar cuando cambia otro Parameter: los términos interactúan. La dirección local es informativa solo si el Learning Rate y la geometría del objetivo permiten una actualización razonable.

12. Chain Rule: seguir los efectos a través de varias Functions

Los modelos modernos anidan Functions. Para el score de dos sensores, sean \(z=b+w_TT+w_VV\) y \(p=\sigma(z)\). Cambiar \(w_T\) afecta al output a través del cambio previo en \(z\). La Chain Rule conecta ambos pasos:

\[\frac{\partial p}{\partial w_T}=\frac{dp}{dz}\frac{\partial z}{\partial w_T}=p(1-p)T.\]

Multiplicamos dos Derivatives, no las dos Functions originales. En A, \(T=60\) y \(p\approx0.26894\), por lo que \(\partial p/\partial w_T\approx0.26894(0.73106)(60)\approx11.797\) por unidad de cambio del peso de temperatura. Aunque parece grande, recuerda que el peso se expresa por °C: aumentarlo en una unidad sería una modificación enorme. Un incremento pequeño de \(0.001\) sugiere un cambio local aproximado de 0.0118 en el output, de modo que la escala del Parameter es fundamental.

Del output a una Loss Function

Para Label binario \(y\in\{0,1\}\) y output probabilístico \(p\), la Binary Cross-Entropy (Log Loss) de una observación es:

\[\ell(y,p)=-\big[y\ln(p)+(1-y)\ln(1-p)\big].\]

Si \(y=1\), queda \(-\ln p\): asignar una probabilidad pequeña a un evento que efectivamente ocurre recibe una penalización alta. Si \(y=0\), queda \(-\ln(1-p)\). Una predicción perfecta se aproxima a Loss cero; una predicción muy confiada y equivocada produce una Loss elevada.

Aplicando Chain Rule a través de Sigmoid obtenemos la simplificación \(\partial\ell/\partial z=p-y\). Por tanto, \(\partial\ell/\partial w_T=(p-y)T\) y \(\partial\ell/\partial b=p-y\). Son Derivatives respecto de Parameters del modelo; no representan directamente el efecto de intervenir físicamente sobre la temperatura.

Para A, cuyo Label es \(y=0\), tenemos \(z=-1\), \(p\approx0.26894\) y \(\partial\ell/\partial z\approx0.26894\). Para B, que falla aunque su output sea \(p\approx0.42556\), resulta \(\partial\ell/\partial z\approx-0.57444\). Los signos indican diferentes direcciones locales deseables para sus scores.

Límite de la interpretación. La Derivative indica cómo cambia matemáticamente la Loss cuando cambia un score calculado. No demuestra cuánto cambiaría el riesgo real si manipuláramos la temperatura o vibración de una máquina.

Derivar la simplificación de Log Loss, sin saltos

Para una observación, comencemos con \(\ell=-y\ln(p)-(1-y)\ln(1-p)\). Su Derivative respecto de \(p\) es \(\partial\ell/\partial p=-y/p+(1-y)/(1-p)\). La Derivative de Sigmoid es \(dp/dz=p(1-p)\). Multiplicamos según Chain Rule: \([-y/p+(1-y)/(1-p)]p(1-p)=-y(1-p)+(1-y)p=p-y\). No utilizamos ningún atajo misterioso: la fórmula conocida surge de aplicar las Derivatives en orden correcto. Para un dataset, promediamos los Gradients individuales según la definición de la Loss elegida.

13. Gradient Descent: convertir las Derivatives en aprendizaje

Gradient Descent actualiza repetidamente Parameters para reducir una función objetivo. En la iteración \(t\), su forma general es \(\boldsymbol\theta_{t+1}=\boldsymbol\theta_t-\eta\nabla L(\boldsymbol\theta_t)\), donde \(\eta>0\) es el Learning Rate. El Gradient aporta la dirección local y el Learning Rate establece cuánto nos moveremos.

Primero, dos actualizaciones completas sobre una parábola

Definimos \(L(w)=(w-3)^2\), cuya Derivative es \(L'(w)=2(w-3)\). Empezamos en \(w_0=0\), usamos \(\eta=0.2\) y calculamos:

\[w_1=0-0.2[-6]=1.2,\quad L(w_1)=(1.2-3)^2=3.24.\]
\[w_2=1.2-0.2[-3.6]=1.92,\quad L(w_2)=(1.92-3)^2=1.1664.\]

La Loss inicial era 9, así que \(9\to3.24\to1.1664\) permite comprobar la mejora numéricamente. La parábola es una función convexa con mínimo único en \(w=3\). En Machine Learning pueden aparecer superficies con regiones planas, geometría mal condicionada o múltiples puntos estacionarios; este ejemplo enseña el mecanismo, no una garantía de convergencia universal.

Después, una actualización Logistic basada en datos

Utilicemos solo dos filas de nuestro dataset: A con vibración 2 y Label 0; F con vibración 7 y Label 1. Definimos \(x=V/10\), obteniendo \((x_1,y_1)=(0.2,0)\) y \((x_2,y_2)=(0.7,1)\). Se trata de una demostración independiente de entrenamiento con una sola Feature, no del score fijo de dos Features utilizado antes.

Inicializamos un modelo Logistic con \(w=0,b=0\). Ambos scores son cero y ambos outputs son \(p_1=p_2=0.5\). La Binary Cross-Entropy promedio es \(L=-[\ln(0.5)+\ln(0.5)]/2\approx0.693147\). Calculemos los Batch Gradients:

\[\frac{\partial L}{\partial w}=\frac{(0.5-0)(0.2)+(0.5-1)(0.7)}{2}=\frac{0.10-0.35}{2}=-0.125,\]
\[\frac{\partial L}{\partial b}=\frac{(0.5-0)+(0.5-1)}{2}=0.\]

Con \(\eta=1\), actualizamos \(w_{new}=0-1(-0.125)=0.125\) y \(b_{new}=0\). Los nuevos outputs son \(\sigma(0.125\times0.2)\approx0.50625\) y \(\sigma(0.125\times0.7)\approx0.52186\). La nueva Loss media resulta aproximadamente 0.67804, menor que 0.69315. Verificamos de forma independiente el resultado: disponer de una fórmula de Gradient no implica automáticamente que cualquier tamaño de paso reduzca la Loss.

Compromiso del Learning Rate. Un paso demasiado pequeño puede exigir numerosas iteraciones; uno excesivo puede rebasar el mínimo o divergir. Guías posteriores distinguirán Batch, Stochastic y Mini-Batch Gradient Descent, además de estrategias de Optimization más sofisticadas.

Comprobar por qué Learning Rate no puede ser arbitrario

La misma parábola ilustra el fenómeno de Overshooting. Empezamos en \(w_0=0\) con Gradient −6. Si \(\eta=1\), obtenemos \(w_1=0-1(-6)=6\) y Loss \((6-3)^2=9\): ese salto grande no mejoró respecto del inicio. Con \(\eta=1.2\), obtendríamos \(w_1=7.2\) y Loss \((7.2-3)^2=17.64\), peor que el valor inicial 9. El ejemplo demuestra numéricamente qué significa rebasar el mínimo, en lugar de pedirle al lector que memorice la palabra Overshooting.

14. Probability: Events, frecuencias y preguntas condicionales

Probability formaliza la incertidumbre asociada a Events. En el dataset sintético, sea \(F\) «ocurre falla dentro de 30 días» y \(H\) «vibración de al menos 5 mm/s». Fallan tres máquinas (B, D y F) de las seis, por lo que la proporción observada es \(P(F)=3/6=0.5\). Aquí utilizamos \(P\) como frecuencia empírica del ejemplo, no como probabilidad poblacional demostrada.

Las máquinas D, E y F presentan vibración alta; de ellas fallan D y F. La proporción condicional de fallas es:

\[P(F\mid H)=\frac{\#(F\cap H)}{\#(H)}=\frac{2}{3}\approx0.667.\]

El símbolo \(\cap\) es la intersección («ambos Events ocurren») y \(\mid\) significa «dado que». Entre las tres máquinas con vibración inferior a 5, solo B falla: \(P(F\mid H^c)=1/3\). El superíndice \(c\) indica el complemento («no H»).

Grupo observado Falla (F) No falla Total
Vibración alta H (≥5) 2 1 3
Vibración menor Hᶜ (<5) 1 2 3
Total 3 3 6

La dirección de la condición importa

\(P(F\mid H)\) pregunta «entre las máquinas con vibración alta, ¿qué proporción falla?». Su reverso \(P(H\mid F)=2/3\) pregunta «entre las máquinas que fallaron, ¿qué proporción registraba vibración alta?». En este pequeño dataset equilibrado los dos números coinciden por casualidad, pero responden preguntas distintas y normalmente no son iguales. Por eso realizaremos un segundo ejemplo con una población diferente.

La Multiplication Rule establece \(P(F\cap H)=P(F\mid H)P(H)\), siempre que el condicionamiento esté bien definido. Aquí \((2/3)(3/6)=2/6\), exactamente las dos observaciones conjuntas entre seis. Es una comprobación de consistencia.

Precaución. Una proporción 2/3 basada en apenas tres máquinas es muy inestable. No demuestra una relación causal ni justifica afirmar que cualquier máquina industrial futura con alta vibración tenga un riesgo real de 66.7%.

Independence es una afirmación matemática precisa

Los Events \(F\) y \(H\) son independientes si \(P(F\mid H)=P(F)\) cuando \(P(H)>0\), o equivalentemente si \(P(F\cap H)=P(F)P(H)\). En nuestro dataset ilustrativo, \(P(F\mid H)=2/3\) pero \(P(F)=1/2\): las proporciones observadas no satisfacen la igualdad de Independence. Este cálculo por sí solo no demuestra dependencia poblacional con confianza estadística, porque contamos apenas con seis observaciones construidas. Independence es una propiedad de una Probability Distribution, no algo demostrado con un patrón aislado.

15. Bayes' Theorem y el problema de la prevalencia

Bayes' Theorem relaciona Conditional Probabilities que invierten el orden de los Events. Para una alerta positiva \(+\) y falla \(F\), podemos escribir:

\[P(F\mid +)=\frac{P(+\mid F)P(F)}{P(+\mid F)P(F)+P(+\mid F^c)P(F^c)}.\]

Cada término cumple una función: \(P(F)\) es el Prior o prevalencia inicial; \(P(+\mid F)\) es la Sensitivity (True Positive Rate); \(P(+\mid F^c)\) es el False Positive Rate, igual a 1 − Specificity; y \(P(F\mid+)\) es el Posterior, la probabilidad de falla después de una alerta positiva.

Otra población operativa, expresamente hipotética

Imaginemos 1,000 máquinas; el 10% falla durante el horizonte establecido. Supongamos un detector que identifica 80% de las fallas reales y produce falsas alertas en 10% de las máquinas que no fallan. Estas tasas son supuestos didácticos; no se estimaron con el dataset de seis máquinas.

Situación real Detector positivo Detector negativo Total
Falla 80 20 100
No falla 90 810 900
Total 170 830 1,000

¿Por qué 90 False Positives? Hay 900 máquinas que no fallan y el detector marca al 10%: \(0.10\times900=90\). Por consiguiente, entre las 170 alertas positivas, la proporción de fallas verdaderas es:

\[P(F\mid +)=\frac{80}{80+90}=\frac{80}{170}\approx0.4706=47.06\%.\]

La fórmula de Bayes produce lo mismo: \((0.8)(0.1)/[(0.8)(0.1)+(0.1)(0.9)]=0.08/0.17\). Aunque Sensitivity sea 80%, menos de la mitad de las alertas corresponden a fallas reales en esta población hipotética, porque las fallas son relativamente infrecuentes y existen muchas máquinas sin falla.

¿Qué sucede si cambia la prevalencia?

Si el mismo detector se usara donde el 50% falla, tendríamos \(P(F\mid+)=(0.8\times0.5)/[(0.8\times0.5)+(0.1\times0.5)]=0.4/0.45\approx88.89\%\). Mantuvimos fijos Sensitivity y False Positive Rate; solo cambiamos el Base Rate. No estamos afirmando que en la práctica el detector mantenga sus tasas al cambiar de población: aislamos un efecto matemático.

Aplicación. En Events infrecuentes, Precision (Positive Predictive Value) depende mucho de la prevalencia. Una empresa que organiza inspecciones no debería recibir únicamente Sensitivity sin conocer las proporciones relevantes de la población donde operará el detector.

Interpretar una alerta negativa con igual cuidado

La tabla de 1,000 máquinas contiene 830 alertas negativas. Entre ellas, 20 máquinas fallan a pesar de no haber sido marcadas y 810 no fallan. Por tanto, la proporción condicional de fallas tras una alerta negativa es \(P(F\mid-)=20/(20+810)=20/830\approx2.41\%\). El Negative Predictive Value (proporción de resultados negativos que efectivamente corresponden a no fallas) es \(810/830\approx97.59\%\). Estas cantidades se calculan entre las 830 alertas negativas; ninguna es Sensitivity ni Specificity y ambas dependen de la prevalencia supuesta.

Árbol de probabilidades: reconstruir los cuatro resultados posibles

El árbol organiza la misma población hipotética de 1,000 máquinas de dos maneras sucesivas: primero por el estado real de falla y después por la señal del detector. Las probabilidades de las ramas en cada bifurcación suman uno: \(0.10+0.90=1\), \(0.80+0.20=1\) y \(0.10+0.90=1\).

Por qué importa el denominador. La probabilidad de que el detector emita una señal positiva es \(P(+)=0.8(0.1)+0.1(0.9)=0.08+0.09=0.17\); por eso, entre todas las alertas, \(P(F\mid +)=0.08/0.17=8/17\approx47.06\%\). No se divide entre las 100 fallas reales, porque estamos condicionando a alerta positiva, no a falla real.

16. Random Variables, Expected Value, Variance y Standard Deviation

Una Random Variable representa numéricamente el resultado de un proceso incierto. Una variable binaria \(Y=1\) para falla y 0 en caso contrario sigue una estructura de tipo Bernoulli. Para probabilidad de evento \(p\), su media poblacional es \(E[Y]=p\) y su Variance es \(\operatorname{Var}(Y)=p(1-p)\). Si \(p=0.1\), la Variance vale \(0.1(0.9)=0.09\), no 0.1.

Calcular completamente la dispersión de vibraciones

Las seis lecturas de vibración son \(2,3,4,6,5,7\) mm/s. Su Sample Mean es:

\[\bar V=\frac{2+3+4+6+5+7}{6}=\frac{27}{6}=4.5\ \mathrm{mm/s}.\]

Restemos 4.5 a cada observación: \(-2.5,-1.5,-0.5,1.5,0.5,2.5\). Al elevarlas al cuadrado obtenemos \(6.25,2.25,0.25,2.25,0.25,6.25\), cuya suma es 17.5. La Sample Variance divide entre \(n-1\):

\[s_V^2=\frac{17.5}{6-1}=3.5\ \mathrm{(mm/s)^2},\qquad s_V=\sqrt{3.5}\approx1.871\ \mathrm{mm/s}.\]

Si estas seis mediciones se definieran como toda la población de interés, la correspondiente Population Variance dividiría entre 6: \(17.5/6\approx2.917\). La elección depende de la cantidad estadística que pretendemos describir o estimar, no de cuál división produce un resultado más sencillo.

Expected Loss ante resultados inciertos

Supongamos que una política de inspección tiene probabilidad 10% de omitir una falla cuyo costo sería $100, y 90% de no registrar pérdida. Su Expected Loss por decisión es \(E[C]=0.1(100)+0.9(0)=\$10\). Esto representa un promedio ponderado bajo probabilidades y costos supuestos, no una garantía de que cada inspección cueste exactamente $10.

Con los conteos de la sección 9 (un False Positive y un False Negative), supongamos que cada FP cuesta $10 y cada FN $100. El costo realizado ilustrativo de las seis máquinas es \(10(1)+100(1)=\$110\), equivalente a \(110/6\approx\$18.33\) por máquina. Ese promedio observado y el Expected Cost previo corresponden a supuestos distintos; no deben confundirse.

Tres conceptos diferentes. Mean resume el centro de datos observados, Variance mide dispersión y Expected Value pondera resultados posibles utilizando una Probability Distribution. Ninguno demuestra por sí solo que un modelo predictivo generalizará.

17. Sampling, Generalization y un laboratorio numérico reproducible

¿Por qué utilizamos tan solo seis observaciones? Porque permiten desarrollar los cálculos sin ocultar pasos. Pero seis registros son insuficientes para estimar tasas confiables de falla o demostrar Generalization. Las tres fallas y tres no fallas fueron construidas con fines de enseñanza; la prevalencia observada de 50% no representa una población industrial identificada.

Population, Sample, Parameter y Statistic

La Population incluye las situaciones reales de máquinas y períodos en los que deseamos predecir. Los seis registros son una Sample ilustrativa. Una probabilidad poblacional \(p\) es un Parameter; una proporción calculada \(\hat p=3/6=0.5\) es una Statistic. Un Estimator es un procedimiento para calcular una cantidad usando observaciones. Un proyecto real debe especificar muestreo, tipos de equipos, período y dependencia temporal.

Medir la misma máquina cada minuto produce muchas filas, pero no necesariamente muchas observaciones independientes. Si registros casi idénticos de una misma máquina aparecen en Training y Test, el desempeño puede parecer exageradamente alto. Particiones temporales y Group-Aware Validation pueden ser necesarias según el objetivo operativo.

Reproducir los cálculos con Python

Este código verifica scores, outputs Sigmoid, Sample Covariance y Confusion Matrix de nuestras seis observaciones. No entrena un modelo ni demuestra Accuracy fuera de la muestra.

import numpy as np

sensor_data = np.array([[60, 2], [70, 3], [65, 4],
                        [80, 6], [75, 5], [85, 7]], dtype=float)
failures = np.array([0, 1, 0, 1, 0, 1])
weights = np.array([0.04, 0.30])
scores = sensor_data @ weights - 4
probabilities = 1 / (1 + np.exp(-scores))
predicted = (probabilities >= 0.5).astype(int)

print('scores:', np.round(scores, 2))
print('sigmoid:', np.round(probabilities, 4))
print('sample covariance:', np.cov(sensor_data, rowvar=False))
print('TP FP FN TN:', [int(np.sum((predicted == a) & (failures == b)))
                      for a, b in [(1, 1), (1, 0), (0, 1), (0, 0)]])

Esperamos scores \([-1.0,-0.3,-0.2,1.0,0.5,1.5]\), Sample Covariance \(\begin{bmatrix}87.5&16.5\\16.5&3.5\end{bmatrix}\) y conteos \([2,1,1,2]\). Si obtienes otra cifra, revisa orden de columnas, unidades, Intercept y que la Sample Covariance divida entre \(n-1\).

El proceso matemático completo, conectado

Representamos cada snapshot mediante un Vector; reunimos observaciones en una Matrix; calculamos scores con Parameters; transformamos el resultado; lo comparamos con Labels obtenidos válidamente; medimos una Loss; utilizamos Derivatives para actualizar Parameters; y evaluamos registros nuevos sin usar sus resultados para diseñar el modelo. Cada transición contiene supuestos que conviene revisar.

¿Cuánta incertidumbre puede esconder una proporción?

Como ilustración, la expresión convencional del Standard Error para una proporción Bernoulli con muestreo independiente es \(SE(\hat p)\approx\sqrt{\hat p(1-\hat p)/n}\). Si sustituimos \(\hat p=0.5\) y \(n=6\), obtenemos \(\sqrt{0.25/6}\approx0.204\), aproximadamente 20.4 puntos porcentuales. Esta cifra de Plug-in no constituye una garantía válida y precisa para nuestros registros sintéticos, seleccionados sin muestreo aleatorio; además, las aproximaciones normales son problemáticas con muestras tan pequeñas. Su propósito es evidenciar por qué seis observaciones no justifican afirmaciones seguras para producción. Un intervalo serio requiere un diseño muestral adecuado y métodos apropiados para n pequeño.

Laboratorio de verificación: Matrix Multiplication y derivadas numéricas

El siguiente código añade dos pruebas al ejemplo reproducible anterior. Primero, expresa en una sola matriz dos predicciones de duración de reparto. Después compara el gradiente analítico de la pequeña Loss logística de la Sección 13 con una aproximación por diferencias finitas centradas. El segundo método modifica un parámetro a la vez y vuelve a calcular la Loss; no requiere conocer su fórmula derivada, por lo que sirve como control independiente.

Los dos pedidos son completamente sintéticos. Cada fila contiene [1, distancia en km, paradas]; el 1 corresponde al Intercept. Las unidades de los coeficientes son minutos, minutos/km y minutos/parada. Por tanto, la suma produce minutos, no kilómetros ni una probabilidad.

\[X_{delivery}=\begin{bmatrix}1&4&2\\1&6&1\end{bmatrix},\quad \theta=\begin{bmatrix}8\\3\\5\end{bmatrix},\quad \widehat t=X_{delivery}\theta=\begin{bmatrix}8+12+10\\8+18+5\end{bmatrix}=\begin{bmatrix}30\\31\end{bmatrix}\,\text{min}.\]
import numpy as np

# Two synthetic deliveries: intercept, distance (km), stops
routes = np.array([[1.0, 4.0, 2.0], [1.0, 6.0, 1.0]])
minutes_per_feature = np.array([8.0, 3.0, 5.0])
eta_minutes = routes @ minutes_per_feature
assert np.allclose(eta_minutes, [30.0, 31.0])
print('delivery minutes:', eta_minutes)

# The two-sample Logistic Loss from Section 13
x = np.array([0.2, 0.7])
y = np.array([0.0, 1.0])
def loss(w, b):
    z = w * x + b
    return np.mean(np.logaddexp(0.0, z) - y * z)

h = 1e-5
numerical_w = (loss(h, 0.0) - loss(-h, 0.0)) / (2 * h)
numerical_b = (loss(0.0, h) - loss(0.0, -h)) / (2 * h)
analytic = np.array([-0.125, 0.0])
assert np.allclose([numerical_w, numerical_b], analytic, atol=1e-8)
print('numerical gradient:', np.round([numerical_w, numerical_b], 6))

18. Errores comunes: identificar y corregir el razonamiento

1. Tratar unidades diferentes como intercambiables

Sumar 60°C y 2 mm/s no produce una medición física interpretable. Una puntuación ponderada requiere coeficientes y definiciones de unidades explícitos; Scaling modifica el significado de sus pesos.

2. Confundir filas con columnas

Un dataset de 6×2 contiene seis máquinas y dos Features. Al transponerlo obtenemos 2×6, pero todas las operaciones posteriores deben adaptarse al nuevo orden; no basta con cambiar Shape.

3. Multiplicar Matrices elemento por elemento

Matrix Multiplication utiliza Dot Products entre filas y columnas. Las Matrices de la sección 6 producen AB = [[4,10],[10,20]], no el producto elemento a elemento [[2,0],[3,20]].

4. Pensar que Euclidean Distance mide similitud de manera universal

Las diferencias de temperatura dominan numéricamente sobre las de vibración. Las Features, sus unidades, el Scaling y la métrica elegida determinan qué significa «cerca».

5. Interpretar Correlation como causalidad

La Correlation aproximada de 0.943 refleja variación conjunta en seis casos sintéticos. No demuestra que elevar temperatura eleve vibración ni que alguna de ellas cause o evite fallas.

6. Confundir una Derivative con la variación promedio en un intervalo grande

La Derivative de x² en 3 es 6, pero el cambio promedio entre 3 y 3.1 vale 6.1. Una Derivative es un límite local y no garantiza cómo responderá un sistema a una intervención grande.

7. Suponer que Derivative igual a cero garantiza el mejor resultado

Un punto estacionario puede ser mínimo, máximo o Saddle Point. Debemos estudiar la forma de la función, las restricciones y lo que ocurre alrededor del punto.

8. Olvidar Chain Rule

Si un Parameter modifica la Loss a través de un score y Sigmoid, diferenciamos toda la composición. Para Binary Log Loss, la derivación lleva al Gradient compacto (p−y)x.

9. Creer que Gradient Descent siempre reduce la Loss

El algoritmo elige una dirección local; un Learning Rate excesivo puede rebasar mínimos o divergir. Recalcular Loss después de la actualización permite verificar el resultado.

10. Invertir Conditional Probabilities

P(falla | alerta) no es generalmente P(alerta | falla). El Base Rate y los False Positives importan, como demuestra el caso numérico de 1,000 máquinas.

11. Confundir Sample Variance y Population Variance

En nuestro ejemplo, la suma de cuadrados de vibración es 17.5. Dividir entre 5 produce Sample Variance 3.5; entre 6, Population Variance aproximadamente 2.917. Primero definamos la cantidad estadística buscada.

12. Creer que un patrón limpio con datos sintéticos demuestra Generalization

Nuestras seis filas fueron diseñadas para estudiar. Los scores inventados no son probabilidades calibradas; una implementación real exige datos representativos, evaluación externa y Monitoring.

20. Glosario y síntesis final

Scalar
Un único valor numérico, acompañado de unidades cuando corresponde.
Feature
Medición de entrada disponible al momento de predecir.
Target
Resultado observado que se utiliza para entrenamiento o evaluación en Supervised Learning.
Vector
Conjunto ordenado de números que representa coordenadas o Parameters.
Matrix
Arreglo rectangular con significado explícito para filas y columnas.
Transpose
Operación que intercambia filas y columnas.
Dot Product
Suma de los productos de coordenadas correspondientes.
Matrix Multiplication
Operación que combina filas y columnas mediante Dot Products.
Norm
Medida de magnitud de un Vector según una regla definida.
Feature Scaling
Cambio de representación para controlar escalas numéricas relativas.
Covariance
Medida de las desviaciones conjuntas respecto de las medias, con unidades producto.
Correlation
Medida estandarizada de asociación lineal entre Variables no constantes.
Sigmoid Function
Transformación no lineal de un score real al intervalo (0,1).
Derivative
Tasa instantánea de cambio respecto de un input.
Partial Derivative
Tasa de cambio de una variable manteniendo constantes otras variables.
Gradient
Vector que reúne las Partial Derivatives de una función escalar.
Chain Rule
Regla para diferenciar composiciones de Functions.
Loss Function
Cantidad que mide desacuerdo entre predicciones y Targets según un objetivo elegido.
Learning Rate
Tamaño de paso usado durante una actualización de Optimization.
Conditional Probability
Probabilidad de un Event dado que otro Event ocurre.
Prior / Posterior
Probabilidad previa / posterior a incorporar evidencia con Bayes' Theorem.
Expected Value
Promedio de resultados posibles ponderado por probabilidades.
Variance
Dispersión cuadrática alrededor de la media mediante una fórmula muestral o poblacional definida.
Generalization
Capacidad de mantener desempeño útil sobre datos nuevos apropiados.
