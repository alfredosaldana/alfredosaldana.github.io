Classification vs. Regression: cómo identificar problemas de predicción

Aprende a distinguir Classification y Regression desde el significado del Target. Incluye aplicaciones clínicas, comerciales y financieras, dos datasets completos, cálculos paso a paso, probabilidades, métricas, Thresholds, errores comunes y ejercicios resueltos.

1. Empecemos por la decisión: ¿qué queremos predecir?

Supongamos que una clínica de consultas externas desea identificar qué citas tienen mayor probabilidad de no ser atendidas por el paciente. Su finalidad es ofrecer recordatorios adecuados, no negar atención. Por otra parte, una empresa minorista necesita pronosticar sus ventas de la próxima semana para planificar personal e inventario. Ambos problemas tienen ejemplos históricos y resultados conocidos. Ambos pertenecen a Supervised Learning. Sin embargo, las preguntas son fundamentalmente diferentes.

  • Classification: ¿A qué categoría pertenecerá el resultado? Para la clínica, el Target puede ser cita perdida (1) frente a cita atendida (0).
  • Regression: ¿Qué cantidad numérica esperamos obtener? Para la empresa, el Target puede ser ventas semanales expresadas en miles de dólares.
Idea central. La distinción depende principalmente del significado del Target y de la pregunta que queremos responder, no del nombre del algoritmo, el formato del archivo ni de que el dataset contenga números. Un Target 0/1 representa clases; una cantidad monetaria representa una magnitud.

Desarrollaremos los dos casos de manera independiente, presentaremos sus pequeños datasets completos, calcularemos los resultados paso a paso y compararemos las métricas de evaluación y las decisiones prácticas. Todos los datasets y las predicciones utilizados aquí son ejemplos construidos con fines educativos; no representan resultados de investigación ni estimaciones reales de una clínica o empresa.

Objetivos de aprendizaje: qué podrás hacer al finalizar

  1. Convertir una decisión real en una unidad de observación, Features válidas y un Target claramente definido.
  2. Reconocer si el Target es una cantidad medida, una categoría, una categoría ordenada o varias etiquetas simultáneas.
  3. Estimar e interpretar un modelo sencillo de Regression, sus Residuals y métricas de error.
  4. Transformar probabilidades de Classification en categorías mediante un Decision Threshold, y calcular una Confusion Matrix con sus métricas.
  5. Explicar por qué los Baselines, las divisiones correctas de datos, la incertidumbre y los costos operativos son esenciales para comparar modelos.
  6. Reformular de manera independiente un dataset nuevo como pronóstico numérico o riesgo de una clase, justificar la elección y revisar sus consecuencias.

2. Desde los fundamentos: observaciones, Features, Targets y momento de predicción

Un dataset reúne observaciones. Una observación puede corresponder a una cita programada, una transacción de un cliente o una semana de ventas. Las Features son datos que el modelo puede conocer antes de predecir. El Target —también llamado variable respuesta, resultado o Label— es aquello que queremos aprender a pronosticar.

Concepto Classification clínica Regression comercial
Unidad de observación Una cita programada Una semana de ventas
Ejemplos de Features Días entre reserva y cita, ausencias previas, hora programada Inversión publicitaria, período, indicador de promoción
Target Faltó (1) o asistió (0) Ingreso por ventas (miles de dólares)
Output deseado Probabilidad y/o categoría Cantidad numérica estimada
Error relevante Omitir una cita de riesgo o intervenir innecesariamente Subestimar o sobreestimar ventas

Representemos por \(x_i\) las Features de la observación i y por \(y_i\) el Target observado. Con ejemplos \((x_i,y_i)\), el modelo aprende una regla de predicción. Escribimos \(\hat y_i\) para una predicción numérica y \(\hat p_i\) para la probabilidad estimada de una clase. El símbolo de sombrero indica una estimación generada por el modelo, no un hecho observado.

Por qué importa el momento en que vamos a predecir

La clínica debe determinar cuándo hará la predicción: por ejemplo, 24 horas antes de la cita. En ese momento todavía no conoce si el paciente finalmente asistirá. Ese resultado futuro no puede usarse como Feature. De manera similar, una empresa que pronostica las ventas de la próxima semana no puede usar las ventas reales de esa semana ni información publicitaria que solo se registrará después.

La regla se denomina disponibilidad en el momento de predicción. Incumplirla genera Data Leakage: el modelo parece funcionar bien porque durante su desarrollo recibió información imposible de conocer cuando se toma la decisión real.

Distinción importante. Un identificador de cliente se almacena con dígitos, pero no por ello representa una cantidad numérica. En cambio, el número de productos devueltos (0, 1, 2, …) es un conteo cuantitativo, aunque solo adopte valores enteros. Lo decisivo es el significado de la variable.

3. ¿Qué estima Regression y cómo se interpreta un número pronosticado?

Regression estima un resultado cuantitativo a partir de la información disponible. Responde preguntas como «¿cuánto ingreso esperamos?» o «¿cuántas unidades podrían demandarse?». La predicción puede ser 8.4 miles de dólares, 17.2 kilovatios-hora o 3.6 días, incluso si los datos originales tienen valores distintos.

Un modelo general de Regression se representa así:

\[\hat y = f_{\theta}(x)\]

En esta expresión, \(x\) reúne las Features, \(f\) es una función predictiva, \(\theta\) representa los parámetros aprendidos y \(\hat y\) es la cantidad pronosticada. Los métodos pueden utilizar funciones diferentes: Linear Regression combina variables de forma lineal; un Decision Tree calcula predicciones dentro de regiones finales; una Neural Network puede aprender relaciones no lineales.

Valor esperado, observación real y Residual

La predicción no tiene por qué coincidir exactamente con el resultado observado. Las ventas dependen del clima, las decisiones de los compradores, acontecimientos imprevistos y muchos factores que no siempre se miden. El Residual compara el resultado real con la predicción ajustada:

\[e_i=y_i-\hat y_i\]

Si las ventas reales son 8.0 y el modelo predice 8.7 (ambos en miles de dólares), el Residual es \(8.0-8.7=-0.7\) miles de dólares, es decir, −$700. El modelo sobreestimó las ventas en $700. Con nuestra convención de signos, un Residual positivo significa que el modelo subestimó el resultado.

Cuando se minimiza Squared Error, una función de Regression poblacional correctamente especificada intenta aproximar la media condicional, \(E[Y\mid X=x]\). Otras Loss Functions pueden estimar una mediana o un cuantil condicional. Por tanto, Regression no significa solamente dibujar una línea recta.

Nuestra tienda registra la inversión publicitaria y las ventas de cada semana. El dataset tiene solamente cinco observaciones para poder verificar cada cálculo. Ambas variables se miden en miles de dólares. Ajustaremos un modelo con una sola Feature; esto no significa que la publicidad, por sí sola, provoque los cambios observados en ventas.

1 1 4
2 2 5
3 3 7
4 4 8

Utilizaremos Ordinary Least Squares (OLS), o Mínimos Cuadrados Ordinarios: elegimos la recta \(\hat y=b_0+b_1x\) que minimiza la suma de Residuals al cuadrado. Sus parámetros son el Intercept \(b_0\) y la Slope o pendiente \(b_1\).

\[b_1=\frac{\sum_{i=1}^{n}(x_i-\bar x)(y_i-\bar y)}{\sum_{i=1}^{n}(x_i-\bar x)^2},\qquad b_0=\bar y-b_1\bar x\]

Aquí \(n=5\), \(\bar x\) es la media de publicidad y \(\bar y\) es la media de ventas. El denominador mide la variación de la publicidad; el numerador muestra cómo varían conjuntamente publicidad y ventas. Para calcular una pendiente necesitamos que \(x\) presente variación distinta de cero.

Paso A — Calcular ambas medias sin omitir operaciones

\[\bar x=\frac{1+2+3+4+5}{5}=\frac{15}{5}=3\]
\[\bar y=\frac{4+5+7+8+11}{5}=\frac{35}{5}=7\]

Paso B — Calcular las desviaciones y productos fila por fila

1 −2 −3 6 4
2 −1 −2 2 1

5 2 4 8 4
Total 0 0 17 10

Las desviaciones suman cero porque cada variable se centró en su propia media. La suma de productos es 17 y la suma de desviaciones cuadráticas de publicidad es 10.

Paso C — Estimar los parámetros e interpretar sus unidades

\[b_1=\frac{17}{10}=1.7,\quad b_0=7-(1.7)(3)=1.9\]
\[\boxed{\hat y=1.9+1.7x}\]

Cuando la publicidad aumenta en $1,000 (es decir, \(x\) aumenta una unidad), la recta ajustada predice ventas $1,700 mayores, manteniendo fija la especificación del modelo. El Intercept pronostica $1,900 con publicidad cero, pero ese valor está fuera del rango observado; extrapolar requiere cautela. Ninguno de estos coeficientes demuestra, por sí solo, una relación causal.

5. Evaluación de Regression: un buen ajuste no garantiza buenos pronósticos

Las métricas de evaluación describen distintos aspectos de los mismos Residuals. Emplearemos todos los valores obtenidos en las cinco semanas:

\[\mathrm{MAE}=\frac{\sum|e_i|}{n}=\frac{0.4+0.3+0+0.7+0.6}{5}=\frac{2.0}{5}=0.40\]
\[\mathrm{MSE}=\frac{\sum e_i^2}{n}=\frac{0.16+0.09+0+0.49+0.36}{5}=\frac{1.10}{5}=0.22\]
\[\mathrm{RMSE}=\sqrt{0.22}\approx0.469\]
  • Mean Absolute Error (MAE): error absoluto promedio de 0.40 miles de dólares = $400; es fácil interpretarlo en las unidades del negocio.
  • Mean Squared Error (MSE): error cuadrático promedio de 0.22 (miles de dólares)²; penaliza proporcionalmente más los errores grandes.
  • Root Mean Squared Error (RMSE): aproximadamente $469; vuelve a las unidades originales, pero sigue otorgando mayor peso a errores grandes.

Comparación con un Baseline sencillo

Un Baseline es una referencia simple. Supongamos que siempre pronosticamos las ventas promedio históricas, 7, para todas las semanas. Los errores absolutos serían \(3,2,0,1,4\). Por tanto:

\[\mathrm{MAE}_{\mathrm{baseline}}=\frac{3+2+0+1+4}{5}=2.00\]

El MAE dentro de la muestra de la recta (0.40) es menor que el del Baseline constante (2.00). Esto demuestra que la recta describe estas cinco observaciones utilizadas para entrenarla mejor bajo MAE. No demuestra que pronosticará correctamente nuevas semanas porque ajustamos y evaluamos utilizando los mismos datos. Para sostener una afirmación sobre Generalization necesitamos un Test set futuro, separado e intacto.

Cuidado con extrapolar. Si reemplazamos \(x=20\), obtenemos \(\hat y=35.9\), pero solo observamos publicidad entre 1 y 5. Que la fórmula produzca un número fuera del rango no es evidencia de que la relación comercial continúe igual.

6. ¿Qué estima Classification? Categorías, Scores y probabilidades

Classification predice pertenencia a una o varias categorías discretas. Para la clínica definiremos como Positive Class la cita perdida, codificada como \(y=1\), y como Negative Class la cita atendida, codificada como \(y=0\). «Positivo» no significa que el resultado sea deseable: solo indica la categoría de interés.

Un clasificador binario puede producir un Score. Algunos modelos generan una probabilidad estimada \(\hat p=P(Y=1\mid X=x)\); otros devuelven un Score que no puede interpretarse automáticamente como probabilidad. Posteriormente, una regla de decisión transforma el Score o la probabilidad pertinente en una etiqueta.

\[\hat y=\begin{cases}1,&\hat p\ge t\\0,&\hat p<t\end{cases}\]

Aquí \(t\) es el Decision Threshold. Si \(t=0.50\), una probabilidad mayor o igual a 0.50 se transforma en «cita perdida». Eso no significa que el paciente faltará con certeza. Una probabilidad de 0.80 expresa incertidumbre estimada, no un hecho. Incluso puede ser necesario aplicar Calibration antes de confiar en su interpretación numérica.

Por qué Logistic Regression es Classification

Un método frecuente es Logistic Regression. Aunque su nombre contiene «Regression», su salida habitual en un problema binario es una probabilidad de clase. Primero calcula un Score lineal \(z=b_0+b_1x_1+\cdots+b_px_p\) y después aplica la función sigmoid:

\[\hat p=\frac{1}{1+e^{-z}}\]

Si \(z=0.5\), entonces \(e^{-0.5}\approx0.6065\), de modo que \(\hat p\approx1/(1+0.6065)=0.6225\). Con Threshold 0.50 se predice clase 1; con Threshold 0.70, clase 0. La probabilidad estimada no cambió. Es un ejemplo de la transformación matemática, no un modelo clínico realmente entrenado.

De las probabilidades a una Decision Boundary con dos Features

Un modelo puede utilizar más de una Feature. Para distinguir visualmente una superficie de probabilidad de una decisión categórica, consideremos otro modelo de Logistic Regression totalmente hipotético. Usa d = días entre la reserva y la cita, y m = número de citas perdidas anteriormente. Sus coeficientes son únicamente ilustrativos: no provienen de ningún estudio ni estiman relaciones clínicas reales.

\[z=-2+0.4d+0.8m,\qquad \hat p=\frac{1}{1+e^{-z}}\]

Si \(d=1,m=0\), obtenemos \(z=-2+0.4=-1.6\) y, por tanto, \(\hat p\approx0.168\): con Threshold 0.50, la predicción es «asiste». Si \(d=4,m=1\), obtenemos \(z=-2+1.6+0.8=0.4\) y \(\hat p\approx0.599\): la predicción cambia a «falta». Con Threshold 0.50, la Sigmoid devuelve al menos 0.50 exactamente cuando \(z\ge0\). En consecuencia, la frontera cumple \(d+2m=5\). A cada lado se asignan categorías diferentes, aunque las probabilidades varían de forma continua.

Paso A — Contar correctamente los cuatro resultados

Un True Positive (TP) ocurre cuando el modelo identifica una cita perdida y efectivamente se pierde: A, B, D, F → TP = 4. Un False Positive (FP) indica que la cita se marcó como perdida, pero el paciente asistió: C, E → FP = 2. Un False Negative (FN) es una cita que el modelo consideró atendida, pero terminó perdida: H → FN = 1. Un True Negative (TN) corresponde a una cita prevista como atendida y realmente atendida: G, I, J, K, L → TN = 5.

Real / Predicho Predijo falta (1) Predijo asistencia (0) Total fila
Realmente faltó (1) TP = 4 FN = 1 5
Realmente asistió (0) FP = 2 TN = 5 7
Total columna 6 6 12

Comprobación: \(4+2+1+5=12\). Tenemos cinco ausencias reales y siete asistencias. Confundir las filas de resultados reales con las columnas de predicciones provoca muchos errores al calcular métricas.

Paso B — Calcular e interpretar las métricas

\[\mathrm{Accuracy}=\frac{TP+TN}{N}=\frac{4+5}{12}=\frac{9}{12}=0.75\]
\[\mathrm{Precision}=\frac{TP}{TP+FP}=\frac4{4+2}=\frac46\approx0.667\]
\[\mathrm{Recall}=\frac{TP}{TP+FN}=\frac4{4+1}=\frac45=0.80\]
\[\mathrm{Specificity}=\frac{TN}{TN+FP}=\frac5{5+2}=\frac57\approx0.714\]
\[F_1=\frac{2PR}{P+R}=\frac{2TP}{2TP+FP+FN}=\frac8{8+2+1}=\frac8{11}\approx0.727\]

Accuracy = 75% significa que acertamos nueve de doce etiquetas. Precision ≈ 66.7% significa que, entre seis citas marcadas como posibles ausencias, cuatro realmente se perdieron. Recall = 80% significa que identificamos cuatro de las cinco ausencias. Specificity ≈ 71.4% significa que identificamos correctamente cinco de las siete citas atendidas. F1 ≈ 72.7% combina Precision y Recall mediante su media armónica; no mide costos ni Calibration.

La interpretación importa más que memorizar fórmulas. Precision pregunta: «Entre las citas a las que enviaríamos un recordatorio especial, ¿qué proporción efectivamente se perdería en estos datos?». Recall pregunta: «De todas las citas que terminaron perdiéndose, ¿qué proporción identificó el modelo?». Son preguntas operativas diferentes.

Un gráfico de puntos permite inspeccionar casos individuales; una distribución por intervalos permite contar cuántas citas caen en cada rango de probabilidad. Utilizamos los mismos 12 registros sintéticos, sin volver a entrenar el modelo. 8. Decision Thresholds: costos y compromisos entre métricas

Las probabilidades estimadas no cambian cuando modificamos el Threshold. Lo que cambia es qué citas quedan clasificadas como positivas y, por lo tanto, los conteos TP, FP, FN y TN.

Threshold TP FP FN TN Precision Recall Accuracy
t = 0.70 2 1 3 6 2/3 = 66.7% 2/5 = 40% 8/12 = 66.7%
t = 0.50 4 2 1 5 4/6 = 66.7% 4/5 = 80% 9/12 = 75%
t = 0.30 5 4 0 3 5/9 = 55.6% 5/5 = 100% 8/12 = 66.7%

Con Threshold 0.70 se marcan solamente A, B y C. Detectamos dos de cinco ausencias (Recall 40%). Con Threshold 0.30 se marcan A hasta I: capturamos las cinco ausencias, pero señalamos innecesariamente cuatro citas que sí fueron atendidas. Este es el trade-off entre Precision y Recall: mejorar una dimensión puede empeorar otra. Precision no necesariamente sigue una evolución estrictamente monótona en todos los datasets.

Ejemplo de costos con supuestos explícitos

Para ilustrar la toma de decisiones, supongamos que no identificar una ausencia genera un costo de oportunidad de $80, mientras que intervenir innecesariamente en una cita atendida cuesta $20. Asumamos costos constantes y ningún costo incremental cuando la clasificación es correcta.

  • Con 0.70: tres FN y un FP cuestan \(3(80)+1(20)=\$260\).
  • Con 0.50: un FN y dos FP cuestan \(1(80)+2(20)=\$120\).
  • Con 0.30: cero FN y cuatro FP cuestan \(0(80)+4(20)=\$80\).

Entre estos tres Thresholds, el de menor costo ilustrativo es 0.30, aunque su Accuracy sea inferior a la de 0.50. Por eso elegir el Threshold que maximiza Accuracy puede no coincidir con el objetivo de la organización.

Disciplina de evaluación. Estos costos son inventados y no incorporan la posibilidad de que el recordatorio modifique la asistencia. En la práctica, las intervenciones cambian conductas, los costos varían y la clínica debe considerar el acceso equitativo a la atención. Se debe seleccionar el Threshold en un conjunto de Validation con un objetivo justificado y evaluarlo después en un Test independiente. No optimices repetidamente sobre el mismo Test que presentarás como evaluación final.

Derivación de un Decision Threshold a partir de costos

Supongamos que \(p=P(Y=1\mid X=x)\) es una probabilidad estimada calibrada para una cita futura. Un False Positive cuesta \(C_{FP}=\$20\), un False Negative cuesta \(C_{FN}=\$80\), y las decisiones acertadas no tienen costo incremental. Son supuestos monetarios didácticos, no costos reales de una clínica.

\[\begin{aligned} E[\mathrm{costo}\mid \mathrm{intervenir}] &= (1-p)C_{FP}+p(0)=20(1-p),\\ E[\mathrm{costo}\mid \mathrm{no\ intervenir}] &=pC_{FN}+(1-p)(0)=80p. \end{aligned}\]

Intervenimos cuando su costo esperado no supera al de no intervenir: \(20(1-p)\le80p\). Desarrollamos: \(20-20p\le80p\); entonces \(20\le100p\) y \(p\ge0.20\). En general, \(t=C_{FP}/(C_{FP}+C_{FN})\) si ambos costos son positivos y se cumplen los supuestos.

No confundas costo esperado con costo observado. La tabla anterior compara tres costos observados en apenas 12 citas y encuentra $80 con el Threshold 0.30 entre esas opciones. Eso no valida el Threshold teórico 0.20 ni permite elegir un Threshold con el Test set final. En la práctica, un recordatorio puede modificar la asistencia y estas fórmulas dejarían de representar adecuadamente la decisión. Ajusta y selecciona reglas con Training/Validation; evalúa la regla congelada en Test sin contaminarlo.

9. Más allá de sí/no: Binary, Multiclass, Multilabel y Ordinal Classification

La estructura del Target determina la variante de Classification. Si reducimos todos los problemas a decisiones binarias, perdemos información relevante.

Tipo Significado Ejemplo Qué representa la predicción
Binary Dos categorías excluyentes Fraude / no fraude Una de dos clases; a menudo, Score de la clase positiva
Multiclass Una entre tres o más categorías excluyentes Ticket: facturación / soporte técnico / entrega Una sola clase dentro de varias posibilidades
Multilabel Pueden aplicarse varias etiquetas simultáneas Etiquetas: finanzas, salud, política Conjunto de etiquetas que pueden coexistir
Ordinal Categorías con un orden significativo Satisfacción: baja / media / alta Categoría ordenada, no distancia numérica medida

En Multiclass Classification, las probabilidades para tres categorías excluyentes pueden ser \(0.10,0.70,0.20\) para facturación, soporte técnico y entrega. Suman uno, y la categoría más probable es soporte técnico. En Multilabel Classification, un mismo documento puede pertenecer tanto a «finanzas» como a «política»; las etiquetas no son excluyentes y cada una puede tener su propio Threshold.

En Ordinal Classification, «alta» supera a «media», pero codificar los valores como 1, 2 y 3 no demuestra que la distancia psicológica entre baja y media sea igual a la distancia entre media y alta. Tratar esas categorías como Regression continua puede introducir una suposición injustificada.

Algunos datasets requieren más atención que simplemente distinguir entre «dólares» y «sí/no». Debemos preguntarnos qué significa el resultado, qué necesita el usuario y cómo se evaluarán los errores.

Pregunta Target Tipo habitual Razón
¿Cuánta electricidad consumirá una vivienda mañana? kWh Regression Magnitud física numérica
¿El consumo superará 30 kWh? Sí / no Classification Categoría definida mediante un umbral
¿Cuántas llamadas de soporte recibiremos? Conteo entero no negativo Count Regression Número de eventos con estructura de conteo
¿El código de producto es 001, 002 o 003? Identificador de categoría Classification Los dígitos son códigos, no distancias medidas

Sistemas con dos etapas y métodos combinados

Una compañía de entregas podría predecir primero si un paquete llegará tarde (Classification) y después estimar cuántas horas de retraso tendrá (Regression). Otra estrategia consistiría en pronosticar directamente la hora de llegada mediante Regression y luego aplicar una regla para identificar retrasos. Las dos estrategias no son automáticamente equivalentes: la primera puede optimizar directamente la detección de retrasos; la segunda mantiene un pronóstico continuo, pero quizá necesite una Loss Function apropiada cerca de la hora límite.

Lección práctica. Un Target categórico no se convierte en Regression porque lo codifiquemos con números enteros. Un Target cuantitativo tampoco se convierte en Classification solo porque el reporte agrupe las predicciones en intervalos. Primero define la pregunta y el resultado que necesitas.

Una empresa de logística de última milla quiere responder (a) «¿Cuántos minutos tardará una entrega?» o (b) «¿Durará más de 24 minutos?». Son dos preguntas sobre las mismas observaciones, pero con diferentes Targets. Estas cuatro rutas son sintéticas. 11. ¿Qué algoritmos sirven para Classification, Regression o ambos?

Classification y Regression son tipos de problemas predictivos; los algoritmos son herramientas para resolverlos. Varias familias poseen versiones para ambas tareas. Lo que cambia es el Target, la función de entrenamiento, la estructura del Output y las métricas de evaluación.

La misma familia Decision Tree, pero diferente predicción

Imaginemos un árbol que divide observaciones comerciales según «publicidad ≥ $3,000». En un Regression Tree, una región final podría contener ventas \(7,8,11\), con predicción promedio \((7+8+11)/3\approx8.67\) miles de dólares. En un Classification Tree, una región con cuatro ausencias y una asistencia puede estimar una proporción de ausencias de \(4/5=0.80\) antes de realizar posibles ajustes de Calibration. La estructura de reglas se parece, pero el resultado y la Loss Function son diferentes.

Cómo escoger un algoritmo

Conviene comenzar con un Baseline interpretable (pronóstico promedio, clase mayoritaria, Linear/Logistic Regression) y comparar alternativas bajo el mismo esquema de Validation. También debemos preguntar: ¿necesitamos explicaciones?, ¿son costosos ciertos errores?, ¿cuántas observaciones tenemos?, ¿existen relaciones no lineales?, ¿cuánto tiempo puede tardar una predicción? Un modelo complejo no es automáticamente superior si aporta mejoras marginales o riesgos operativos innecesarios.

12. Loss Functions: por qué Regression y Classification aprenden de manera distinta

Una Loss Function transforma la discrepancia entre una predicción y el Target observado en un valor que el algoritmo intenta reducir. No es solamente una estadística para el reporte: su forma matemática influye en los parámetros que terminamos aprendiendo.

Regression: Squared Error penaliza la magnitud del error

Para una observación, Squared Error es \((y-\hat y)^2\). Si las ventas son 8.0 y el pronóstico 8.7, obtenemos \((8-8.7)^2=(-0.7)^2=0.49\) en unidades monetarias al cuadrado. Si el error se duplica hasta 1.4, Squared Error es \(1.4^2=1.96\): ¡cuatro veces mayor y no solo el doble!

Para \(n\) observaciones, Mean Squared Error promedia los errores al cuadrado:

\[L_{\mathrm{MSE}}=\frac1n\sum_{i=1}^n(y_i-\hat y_i)^2\]

Así se explica por qué MSE es sensible a los errores grandes. En cambio, Mean Absolute Error promedia \(|y_i-\hat y_i|\) y penaliza linealmente la magnitud del error. Ambos son válidos en diferentes contextos, pero favorecen distintas soluciones.

Classification: Log Loss evalúa la calidad de las probabilidades

Para un Target binario \(y\in\{0,1\}\) y una probabilidad pronosticada \(0<\hat p<1\), Binary Cross-Entropy (Log Loss) para una observación es:

\[\ell(y,\hat p)=-\big[y\ln(\hat p)+(1-y)\ln(1-\hat p)\big]\]

Si el paciente realmente faltó (\(y=1\)) y el modelo estimó \(\hat p=0.80\), el Loss es \(-\ln(0.80)\approx0.2231\). Si asignó solamente \(\hat p=0.10\) a esa misma ausencia, el Loss asciende a \(-\ln(0.10)\approx2.3026\). En el segundo caso, el pronóstico fue erróneo con mucha confianza, por lo que la penalización es mayor.

Si el paciente asistió (\(y=0\)) y \(\hat p=0.20\), el resultado es \(-\ln(1-0.20)\approx0.2231\). Estos ejemplos muestran que Log Loss premia probabilidades informativas y penaliza la confianza injustificada. Accuracy, en cambio, evalúa etiquetas después de aplicar el Threshold.

¿Por qué no usar una Loss Function universal?

Una categoría codificada como 0 o 1 no representa necesariamente una magnitud medible cuyos errores numéricos reflejen los costos reales. Técnicamente, Squared Error también puede entrenar modelos probabilísticos en algunos contextos (y se relaciona con Brier Score), pero Classification suele utilizar objetivos diseñados para resultados categóricos. Por su parte, Accuracy no le dice al gerente si el pronóstico de ventas falló por $100 o por $100,000.

13. Métricas, Baselines y los riesgos de Class Imbalance

La métrica debe conectarse con la tarea y con el impacto real de equivocarse. Un «Score» aislado, sin Baseline, incertidumbre ni interpretación, puede inducir conclusiones equivocadas.

Regression: evaluar el tamaño y la dirección de los errores

MAE expresa cuánto nos equivocamos en promedio, en las unidades del Target. RMSE da mayor importancia a errores grandes. El error promedio con signo puede detectar sobreestimación o subestimación sistemática, pero los errores positivos y negativos pueden cancelarse; por ello también necesitamos una métrica de magnitud. En pronósticos empresariales conviene evaluar por temporada, tienda o producto porque un buen promedio puede ocultar fallas en determinados segmentos.

Un Baseline razonable para una serie temporal de ventas puede ser las ventas de la semana anterior o de la misma semana del año previo, en lugar de la media de todos los períodos. La referencia apropiada depende de lo que se conoce al pronosticar. Debemos comparar los modelos en los mismos períodos futuros, no en un Split histórico artificialmente fácil.

Classification: evaluar a quién detectamos y a quién perjudicamos con falsas alarmas

Accuracy cuenta etiquetas correctas por igual. Precision y Recall examinan la Positive Class desde dos perspectivas. Specificity evalúa los negativos reales. F1 combina Precision y Recall, pero no incluye TN en su fórmula. Otras métricas como ROC AUC (Area Under the Receiver Operating Characteristic Curve) y PR AUC (Area Under the Precision–Recall Curve) resumen el rendimiento a través de distintos Thresholds. Responden preguntas diferentes y también requieren interpretación contextual.

La trampa de los eventos raros: cálculo completo

Imaginemos 1,000 transacciones bancarias, de las cuales 10 son fraudulentas y 990 legítimas. Un modelo que siempre predice «legítima» no detecta ningún fraude. Sus resultados son \(TN=990\), \(FN=10\), \(TP=0\) y \(FP=0\).

\[\mathrm{Accuracy}=\frac{990}{1000}=99\%,\qquad \mathrm{Recall}_{\mathrm{fraud}}=\frac0{10}=0\%\]

El 99% de Accuracy suena excelente, pero el modelo no detecta ninguno de los fraudes. Precision para fraude es matemáticamente indefinida porque no existen predicciones positivas (algunas herramientas le asignan cero por convención). Este ejemplo explica por qué debemos mirar la distribución de clases y los resultados de clasificación, no celebrar un porcentaje aislado.

Una sutileza adicional. Cuando cambia la prevalencia del evento entre entrenamiento y producción, Precision puede cambiar aunque Recall y Specificity permanezcan aproximadamente constantes. En modelos de riesgo también debemos revisar Calibration y el rendimiento en grupos relevantes.

14. Training, Validation, Test y Data Leakage: un escenario clínico completo

Para comprobar si el modelo aprendió patrones generalizables, debemos separar ajuste, selección y evaluación final. Las tres funciones se complementan, pero no son intercambiables.

Conjunto Para qué sirve Qué debemos evitar
Training Aprender coeficientes, reglas, pesos y parámetros de preparación Considerar el rendimiento en estas filas una prueba de futuro éxito
Validation Comparar algoritmos, ajustar Hyperparameters y Thresholds Presentar resultados usados repetidamente para Tuning como independientes
Test Evaluación final de un procedimiento ya seleccionado Regresar una y otra vez para optimizar decisiones tras ver sus resultados

Por qué puede ser necesario un Split temporal

Supongamos que tenemos citas registradas entre enero y septiembre y queremos predecir las de octubre. Una simulación razonable consiste en entrenar con meses anteriores, validar en meses posteriores pero previos a octubre y reservar un período subsiguiente para evaluación. El Split concreto depende del volumen de datos, los cambios operativos, la repetición de pacientes y el momento en que se conocen las etiquetas. Un Split aleatorio podría permitir que información de citas futuras de una persona ayudara a predecir citas anteriores, o sobreestimar de otras maneras el rendimiento real.

Ejemplo de Data Leakage

Una Feature denominada «estado final de la cita» se completa después de la consulta. Si la utilizamos para predecir la ausencia correspondiente, la variable casi revela la respuesta. Una versión más sutil sería usar el «número de recordatorios enviados», cuando esos mensajes se enviaron después de la fecha de predicción. También aparece Leakage si calculamos la media para Normalization con todas las filas antes de separar los datos: las observaciones reservadas influyen entonces en la transformación del Training set.

Procedimiento correcto: crear primero los Splits que correspondan al escenario real; estimar Imputation, Scaling, Encoding y Feature Selection usando solamente Training; aplicar las transformaciones aprendidas a Validation y Test. Seleccionar modelo y Threshold con Validation y evaluar posteriormente una sola vez en un Test independiente.

Cross-Validation ayuda, pero no soluciona un diseño incorrecto

Cross-Validation repite Training y Validation en diferentes particiones para reducir la dependencia de un único Split. Para pronósticos temporales, debemos conservar la cronología y evitar folds aleatorios inapropiados. En datos clínicos, quizá debamos agrupar registros por paciente o episodio para impedir que observaciones casi duplicadas de una persona aparezcan a ambos lados del Split. Aumentar el número de folds no corrige un diseño que utiliza información futura.

15. Probability Calibration, incertidumbre y consecuencias de las decisiones

Una probabilidad estimada solo es útil como probabilidad si su interpretación numérica resulta razonablemente confiable. Un clasificador puede ordenar correctamente las citas según riesgo y, al mismo tiempo, exagerar sistemáticamente sus probabilidades de ausencia. Calibration estudia la correspondencia entre probabilidades pronosticadas y frecuencias observadas.

Imaginemos 100 citas con probabilidades estimadas cercanas a 0.80. Si aproximadamente 80 terminan perdiéndose bajo condiciones de evaluación estables, ese grupo es compatible con una buena Calibration. Si solamente faltan 30, las probabilidades son excesivamente altas. Se trata de una interpretación de frecuencias, no de una garantía acerca de una persona específica. Las muestras pequeñas, los cambios poblacionales y los mecanismos de selección complican la evaluación de Calibration.

Brier Score: un cálculo probabilístico sencillo

Para un resultado binario, la contribución individual al Brier Score es \((\hat p-y)^2\). Si \(y=1\) y \(\hat p=0.8\), obtenemos \((0.8-1)^2=0.04\). Si \(\hat p=0.1\), obtenemos \((0.1-1)^2=0.81\). El Brier Score promedia esas contribuciones. Un valor menor es preferible, pero su interpretación requiere tener en cuenta la frecuencia de clases y compararlo con una referencia apropiada.

Los modelos de Regression también requieren pensar en incertidumbre: pronosticar $8,700 de ventas no garantiza exactamente $8,700. Un Prediction Interval busca describir un rango para una nueva observación; no es lo mismo que un Confidence Interval para la media o un parámetro estimado. Un valor puntual sin contexto puede provocar una seguridad injustificada en decisiones comerciales.

El Output de un modelo no constituye por sí mismo una política. Incluso una predicción bien calibrada no determina qué intervención debemos realizar. Las decisiones también dependen de costos reales, recursos disponibles, equidad, requisitos legales y del posible efecto de intervenir sobre el evento pronosticado.

Calculemos el Brier Score completo de las 12 citas

El dataset de la clínica ya contiene las 12 probabilidades estimadas y sus Targets observados. Al elevar al cuadrado cada error de probabilidad, en el orden A–L, obtenemos:

\[\begin{aligned} \text{Suma de errores cuadrados}\; &=0.0100+0.0400+0.5184+0.1225\\ &\quad+0.3600+0.2304+0.2304+0.3600\\ &\quad+0.1024+0.0784+0.0225+0.0100\\ &=2.0850 \end{aligned}\]
\[\mathrm{Brier}=\frac{1}{12}\sum_{i=1}^{12}(\hat p_i-y_i)^2=\frac{2.0850}{12}=\boxed{0.17375}\]

Compáralo con un Baseline que asigna probabilidad 0.40 a todas las citas, escogida sin consultar las 12 etiquetas de evaluación. Existen cinco faltas reales y siete asistencias, por lo que su Brier Score sería \([5(0.4-1)^2+7(0.4-0)^2]/12=[5(0.36)+7(0.16)]/12=2.92/12\approx0.2433\). Las predicciones ilustrativas son mejores que ese Baseline específico en esta muestra. Sin embargo, 12 citas no permiten demostrar una Calibration fiable; necesitamos más observaciones reservadas para evaluación, agrupaciones pertinentes y revisar el desempeño en diferentes rangos de probabilidad.

16. Interpretabilidad, causalidad y aplicaciones responsables

Prediction pregunta si la información disponible permite estimar un resultado. Causality pregunta si cambiar un factor específico produciría un cambio en el resultado. Una relación fuerte entre inversión publicitaria y ventas no demuestra que invertir $1,000 adicionales cause $1,700 más de ventas. Las promociones pueden coincidir con temporadas de gran demanda, la dirección puede gastar más precisamente cuando espera más clientes y otras variables pueden influir simultáneamente en ambas magnitudes.

Del mismo modo, una clínica puede identificar pacientes con mayor probabilidad de faltar, pero estos patrones podrían reflejar problemas de transporte, horarios laborales, accesibilidad o procedimientos de reserva de la propia clínica. Una aplicación responsable sería ofrecer recordatorios flexibles o facilitar la asistencia, nunca utilizar la predicción para suponer que una persona no merece atención o tiene determinada motivación.

Lista práctica de interpretación

  1. Precisar qué estamos pronosticando y en qué momento se observan las Features.
  2. Identificar quién puede resultar afectado por False Positives y False Negatives.
  3. Distinguir entre etiqueta, Score no calibrado, probabilidad calibrada, cantidad pronosticada e intervalo.
  4. Revisar el rendimiento en las poblaciones, períodos y grupos relevantes para la aplicación.
  5. No afirmar que encontramos una causa solamente porque el modelo predice bien.

Estas precauciones forman parte de la calidad técnica. Un modelo con un buen promedio estadístico que no puede aplicarse de manera segura o transparente puede resultar inadecuado para el objetivo real.

18. Errores comunes: explicaciones y correcciones detalladas

Cada error incluye por qué falla y cómo corregirlo. Reconocerlos es fundamental: una formulación incorrecta puede invalidar todas las etapas posteriores del proyecto.

1. «Logistic Regression debe predecir una cantidad porque su nombre dice Regression».

Por qué es incorrecto: Logistic Regression binaria transforma un Score lineal con sigmoid para estimar la probabilidad de una clase. Corrección: observar el Target y el Output, no el nombre histórico del método. Falta/asistencia es Classification.

2. «Si una variable tiene valores 0, 1 y 2, automáticamente corresponde a Regression».

Por qué es incorrecto: Los dígitos pueden identificar categorías independientes, como facturación, soporte técnico y entrega. Las diferencias numéricas no representan magnitudes naturales. Corrección: describir qué significa cada código y usar Multiclass Classification cuando se trate de categorías.

3. «Si el resultado es entero, obligatoriamente es Classification».

Por qué es incorrecto: El número de llamadas recibidas o de productos defectuosos es una cantidad, aunque sea entera. Corrección: utilizar Count Regression cuando queremos el número y Classification cuando queremos una categoría como «más de diez llamadas».

4. «Una probabilidad de 0.80 significa que el evento ocurrirá».

Por qué es incorrecto: Una probabilidad expresa incertidumbre. Incluso entre predicciones perfectamente calibradas cercanas a 0.80, algunas no se materializarán. Corrección: interpretarla como riesgo estimado y evaluar Calibration.

5. «La etiqueta y la probabilidad son equivalentes».

Por qué es incorrecto: Tanto 0.52 como 0.95 generan clase 1 con Threshold 0.50, pero expresan riesgos estimados muy diferentes. Corrección: conservar probabilidades cuando necesitamos priorizar recursos, ordenar casos o modificar el Threshold.

6. «Siempre debemos utilizar Decision Threshold = 0.50».

Por qué es incorrecto: Los False Negatives y False Positives suelen producir consecuencias distintas. En nuestro ejemplo, 0.30 tuvo menor costo ilustrativo aun con menor Accuracy. Corrección: seleccionar un Threshold según costos o restricciones justificadas y datos de Validation.

7. «Un Accuracy alto demuestra que un modelo para eventos raros es bueno».

Por qué es incorrecto: Predecir «sin fraude» en 1,000 transacciones con diez fraudes proporcionó 99% Accuracy y 0% Recall para fraude. Corrección: comparar contra un Baseline adecuado e inspeccionar Precision, Recall, la distribución de clases y las métricas relevantes.

8. «El modelo con menor Training Error es necesariamente el mejor».

Por qué es incorrecto: Un modelo flexible puede memorizar peculiaridades de los datos. El MAE comercial se calculó sobre las mismas cinco semanas que sirvieron para estimar la recta. Corrección: comparar sobre Validation correctamente separado y utilizar Test solo después de seleccionar el procedimiento.

9. «Podemos aplicar Scaling o Imputation a todos los datos antes de separarlos».

Por qué es incorrecto: Incluso una transformación no supervisada puede transmitir información del Test set al desarrollo del modelo. Corrección: estimar transformaciones únicamente en Training y aplicarlas posteriormente dentro de un Pipeline.

10. «Un error pequeño en Regression demuestra causalidad».

Por qué es incorrecto: La asociación predictiva puede deberse a Confounding, causalidad inversa o tendencias comunes. Corrección: describir los coeficientes como predictivos salvo que un diseño causal convincente respalde conclusiones más fuertes.

11. «Precision y Recall significan lo mismo».

Por qué es incorrecto: Precision divide entre predicciones positivas; Recall divide entre positivos reales. Para la clínica con Threshold 0.50 eran \(4/6\) y \(4/5\), respectivamente. Corrección: explicar verbalmente el denominador antes de aplicar cada fórmula.

12. «Todos los Scores continuos son salidas de Regression».

Por qué es incorrecto: Un clasificador puede producir un Score numérico sin límites o entre cero y uno sin dejar de resolver un problema categórico. Corrección: identificar la tarea a partir del Target y del objetivo de aprendizaje.

13. «Basta con obtener el menor error promedio para desplegar un modelo».

Por qué es incorrecto: Un promedio puede ocultar errores graves en ciertas clínicas, temporadas, regiones o grupos. La producción añade cambios de datos y nuevas restricciones. Corrección: revisar segmentos relevantes, incertidumbre, estabilidad e impacto operativo.

14. «Aplicar un umbral a una predicción de Regression equivale exactamente a entrenar Classification».

Por qué es incorrecto: Regression optimiza errores numéricos sobre todo el rango del Target; Classification puede optimizar directamente la detección del evento definido por el umbral. Corrección: comparar ambas estrategias con la misma métrica de decisión y datos reservados.

15. «Si el Test Score es excelente, puedo seguir ajustando hasta que mejore aún más».

Por qué es incorrecto: Elegir repetidamente configuraciones según Test convierte ese conjunto en parte de las decisiones de entrenamiento. Corrección: volver a Validation y conservar una evaluación final verdaderamente independiente cuando sea posible.

19. Comprueba lo aprendido: razona y verifica cada respuesta

Intenta resolver cada pregunta antes de expandir su explicación. Los ejercicios vuelven a las aplicaciones, cálculos y limitaciones, en lugar de pedir únicamente definiciones.

1. Un hospital predice cuántas camas estarán disponibles mañana. ¿Classification o Regression?

Regression. El Target es un conteo numérico de camas disponibles; aunque sus valores sean enteros, representa una cantidad. Podría convenir un modelo específico para conteos. Si el hospital pregunta si la capacidad caerá por debajo de cinco camas, habrá definido un problema de Binary Classification.

2. Una tienda online considera «alto riesgo» una transacción cuando su probabilidad estimada de fraude es al menos 0.60. ¿Cuál es el Target y cuál la regla?

El Target subyacente es fraude/no fraude, por lo que se trata de Binary Classification. La probabilidad es un Output intermedio; la regla convierte \(\hat p\ge0.60\) en «alto riesgo». El Threshold es una decisión práctica y no una ley matemática.

3. Con los totales 17 y 10, vuelve a calcular la pendiente OLS de la tienda.

La pendiente es \(b_1=17/10=1.7\). Como publicidad y ventas están expresadas en miles de dólares, aumentar $1,000 de publicidad se asocia con $1,700 más de ventas ajustadas por el modelo; no demuestra un efecto causal.

4. Pronostica ventas para x = 4 e interpreta un Residual de −0.7.

En \(\hat y=1.9+1.7x\), sustituimos \(x=4\): \(\hat y=1.9+1.7(4)=8.7\) miles de dólares. Si el valor real fue 8.0, entonces \(e=8.0-8.7=-0.7\); el modelo sobreestimó las ventas en $700.

5. Calcula MAE con errores absolutos 0.4, 0.3, 0, 0.7 y 0.6.

Sumamos todos: \(0.4+0.3+0+0.7+0.6=2.0\). Dividimos entre cinco: \(\mathrm{MAE}=2/5=0.4\) miles de dólares, es decir, $400. MAE no puede ser negativo y conserva las unidades originales del Target.

6. En la clínica con Threshold 0.50, ¿por qué Precision y Recall son distintos?

Tenemos cuatro TP, dos FP y un FN. Precision pregunta cuántos casos marcados realmente faltaron: \(4/(4+2)=4/6\). Recall pregunta cuántas ausencias reales fueron detectadas: \(4/(4+1)=4/5\). Sus denominadores corresponden a preguntas operativas diferentes.

7. Con Threshold 0.30, calcula Recall y Precision.

Las cinco ausencias reales se detectaron: \(TP=5\), \(FN=0\), Recall \(=5/5=100\%\). También se marcaron cuatro citas atendidas: Precision \(=5/(5+4)=5/9\approx55.6\%\).

8. ¿Por qué la clínica podría preferir Threshold 0.30 frente a 0.50 si Accuracy es menor?

Con los costos ilustrativos, 0.30 produce cuatro FP y cero FN: \(4(20)=\$80\). Con 0.50 aparecen dos FP y un FN: \(2(20)+1(80)=\$120\). La solución de menor costo no siempre tiene máximo Accuracy. Una aplicación real también exige justificar costos y evaluar equidad.

9. Un modelo no detecta fraude en 1,000 transacciones con diez fraudes. ¿Accuracy y Recall?

Acertó las 990 transacciones legítimas y omitió los diez fraudes. Accuracy \(=990/1000=99\%\); Recall para fraude \(=0/10=0\%\). Precision es indefinida porque no hizo predicciones positivas. El Accuracy elevado oculta la incapacidad total de detectar fraude.

10. Un Target utiliza códigos 1, 2 y 3 para «bronce», «plata» y «oro». ¿Qué tarea corresponde?

Se trata de categorías ordenadas, pero sin garantía de distancias numéricas iguales. Corresponde Ordinal Classification; los códigos enteros no convierten la variable automáticamente en Regression.

11. ¿Qué problema aparece al utilizar «el paciente asistió» registrado después de la consulta para predecir esa ausencia?

Es Data Leakage. La variable contiene el resultado final, imposible de conocer 24 horas antes. El entrenamiento daría resultados engañosos. Solo pueden utilizarse Features disponibles cuando realmente se hace la predicción.

12. Para una ausencia real y = 1, compara Log Loss con p = 0.80 y p = 0.10.

Si \(y=1\), el Loss es \(-\ln(\hat p)\). Para 0.80 vale aproximadamente 0.2231; para 0.10 vale 2.3026. La predicción muy segura pero incorrecta recibe más de diez veces la penalización de la predicción 0.80.

13. ¿Por qué no podemos afirmar que el error futuro de ventas será $400 solo por el Training MAE?

Estimamos la recta y calculamos el error sobre las mismas cinco observaciones. Ese ajuste dentro de la muestra es optimista para nuevas semanas, especialmente con tan pocos datos. Necesitamos períodos futuros reservados, un Split temporal válido y comparación con un Baseline apropiado.

14. Un sistema asigna a un ticket las etiquetas «facturación» y «soporte técnico» a la vez. ¿Multiclass o Multilabel?

Multilabel Classification, porque dos etiquetas pueden ser verdaderas simultáneamente. Multiclass Classification supone que cada observación pertenece a una sola clase entre varias alternativas excluyentes.

15. ¿Por qué una misma probabilidad estimada puede producir etiquetas diferentes?

Supongamos \(\hat p=0.60\). Con \(t=0.50\), la regla \(\hat p\ge t\) predice clase 1. Con \(t=0.70\), predice clase 0. El modelo produjo el mismo 0.60 en ambos casos; cambió la regla de decisión. Modificar un Threshold no mejora por sí mismo la Calibration; debemos escogerlo según objetivos y costos validados.

16. Calcula el Brier Score de la clínica si la suma de errores cuadrados es 2.0850 y hay 12 citas.

Por definición, el Brier Score binario es la media de \((\hat p_i-y_i)^2\). Por lo tanto, \(2.0850/12=0.17375\). En esta métrica, menos es mejor, pero un solo número no equivale a una curva de Calibration y 12 casos no bastan para validar la calidad de las probabilidades en una población clínica.

Nuevos desafíos de transferencia: datos distintos de los ejemplos resueltos

17. Nuevos registros de transporte: calcula un error y el Recall de entregas tardías.

Tres entregas ilustrativas independientes tienen parejas (duración real, duración pronosticada), en minutos: (18,20), (27,23) y (30,29). Los errores absolutos de Regression son \(|18-20|=2\), \(|27-23|=4\) y \(|30-29|=1\). Por tanto, \(\mathrm{MAE}=(2+4+1)/3=7/3\approx2.33\) minutos. Llamaremos tardía a una entrega con duración estrictamente mayor de 24 minutos. Las etiquetas reales son (0,1,1), y las derivadas de los pronósticos son (0,0,1). Así, \(TP=1,FN=1,TN=1,FP=0\), \(\mathrm{Recall}=TP/(TP+FN)=1/(1+1)=50\%\) y \(\mathrm{Accuracy}=(1+1)/3\approx66.7\%\). El mismo conjunto permite formular dos preguntas distintas, pero no permite afirmar cómo rendiría un Classifier entrenado por separado.

18. Nuevos Scores en seguros: ¿cuatro casos validan Probability Calibration?

Cuatro reclamaciones sintéticas tienen (probabilidad estimada de fraude, etiqueta real): (0.10,0), (0.40,1), (0.65,0), (0.90,1). Con Threshold 0.50 se marcan solo los casos 3 y 4: \(TP=1,FP=1,FN=1,TN=1\). Precision es \(1/(1+1)=0.50\) y Recall es también \(1/(1+1)=0.50\). Con Threshold 0.30 se marcan los casos 2, 3 y 4: \(TP=2,FP=1,FN=0,TN=1\), Precision \(2/3\approx66.7\%\) y Recall \(2/2=100\%\). Cuatro resultados no permiten validar Calibration y estas son evaluaciones didácticas, no una autorización para optimizar el Threshold sobre el Test final.

19. Demanda eléctrica: ¿qué Task y qué Target corresponde si cambia la pregunta?

«Predecir el consumo de mañana en kilowatt-hours (kWh)» es Regression, con Target cuantitativo \(E\) medido en kWh. «¿Superará el consumo de mañana 30 kWh?» es Binary Classification, con \(Y=\mathbf{1}\{E>30\}\). Un código de medidor como «001» es un identificador, no un Target cuantitativo porque esté escrito con dígitos. Las Features deben existir al momento del pronóstico. Incluso un pronóstico de Regression de exactamente 29 kWh no establece por sí solo la probabilidad de superar 30 kWh.

20. Glosario, conexiones conceptuales y conclusión

Este glosario conecta cada término con su uso práctico. Vuelve a los ejemplos numéricos cuando una definición te parezca demasiado abstracta.

Término Significado y consecuencia práctica
Supervised Learning Aprender con Targets observados; incluye Classification y Regression.
Target / Label Resultado que queremos predecir; su significado establece el problema.
Feature Información disponible antes de decidir; valores futuros crean Data Leakage.
Regression Predecir una cantidad, idealmente considerando también su incertidumbre.
Classification Predecir una categoría discreta, frecuentemente mediante Scores o probabilidades.
Binary / Multiclass / Multilabel Dos categorías / una entre varias / varias etiquetas simultáneas.
Ordinal Classification Categorías ordenadas sin intervalos necesariamente iguales.
Model Parameter Cantidad aprendida, como la pendiente 1.7 del ejemplo comercial.
Hyperparameter Configuración escogida por quien desarrolla el modelo, como profundidad del árbol.
Residual Valor observado menos predicción numérica; el signo indica dirección del error.
MAE / MSE / RMSE Métricas de Regression; MAE y RMSE tienen unidades originales, MSE al cuadrado.
Decision Threshold Valor límite para convertir Score/probabilidad en decisión categórica.
TP / FP / FN / TN Cuatro conteos para una Positive Class y Threshold definidos.
Precision Proporción de predicciones positivas que realmente son positivas.
Recall / Sensitivity Proporción de positivos reales que el modelo identifica.
Specificity Proporción de negativos reales identificados como negativos.
Calibration Correspondencia entre probabilidades estimadas y frecuencias observadas.
Log Loss Loss probabilístico de Classification; penaliza errores muy seguros.
Baseline Predictor simple que sirve para medir si la complejidad agrega valor.
Training / Validation / Test Aprender parámetros / seleccionar decisiones / evaluación independiente.
Data Leakage Uso de datos futuros o información filtrada desde observaciones reservadas.
Class Imbalance Frecuencias muy diferentes entre clases; Accuracy puede engañar.
Generalization Capacidad de rendir bien en observaciones nuevas y representativas.
Decision BoundaryConjunto de combinaciones de Features donde cambia la clase predicha para un Threshold dado; la probabilidad estimada puede variar continuamente.
Brier ScoreMedia de los errores cuadrados entre probabilidades binarias y Targets observados 0/1; valores menores indican mejor puntuación.
Conditional MeanValor promedio esperado del Target entre observaciones con un mismo patrón de Features; es un objetivo central de Regression con Squared Error.

La pregunta final más útil

Antes de escoger cualquier algoritmo, completa esta frase: «Para cada observación, utilizando la información disponible en el momento ___, necesito predecir ___, y consideraré útil una predicción cuando ___». Si el resultado buscado es una cantidad medible, considera Regression; si es pertenencia a una categoría, considera Classification. Si la aplicación combina ambas, define explícitamente las dos tareas en vez de ocultarlas detrás de un único Score.

Ambos enfoques requieren rigor matemático, evaluación honesta e interpretación responsable. El método debe servir a la pregunta, y no al revés.
