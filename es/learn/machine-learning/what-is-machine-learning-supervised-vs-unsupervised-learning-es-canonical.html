¿Qué es Machine Learning? Supervised vs. Unsupervised Learning

Comprende cómo aprenden los modelos, qué distingue Supervised de Unsupervised Learning y qué métodos resuelven cada clase de problema. Ejemplos desarrollados de diferentes industrias y operaciones matemáticas paso a paso.

Tres sectores, tres preguntas diferentes

Un banco quiere identificar clientes que podrían atrasarse en el pago de un préstamo. Una empresa minorista desea descubrir grupos de compradores sin definirlos previamente. Un equipo de Marketing intenta estimar las ventas de la próxima semana. Los tres proyectos emplean datos, pero responden preguntas diferentes y, por tanto, necesitan formas distintas de aprendizaje.

En esta guía utilizaremos ejemplos de banca, Retail, Healthcare, Manufacturing, Marketing y servicios digitales. Cambia el sector, pero permanecen las preguntas esenciales: ¿qué problema queremos resolver?, ¿con qué información contamos?, ¿qué resultado produce el modelo? y ¿cómo podemos evaluarlo? Todos los datasets numéricos de este capítulo son ilustrativos e inventados exclusivamente para enseñar; no representan clientes, pacientes ni empresas reales.

Objetivo de aprendizaje: comprender qué es Machine Learning, distinguir Supervised Learning y Unsupervised Learning, reconocer los principales métodos de cada familia, seguir los cálculos sin saltos y entender qué conclusiones están justificadas —y cuáles no—.

1. ¿Qué significa que una máquina «aprenda»?

Machine Learning (ML) es un campo de Artificial Intelligence (AI) que desarrolla métodos para aprender relaciones, patrones o representaciones útiles a partir de datos. En lugar de programar explícitamente la respuesta correcta para cada situación nueva, seleccionamos un procedimiento de aprendizaje cuyos valores ajustables se estiman usando ejemplos.

Considera una empresa de telecomunicaciones. Una regla programada manualmente podría decir: «marcar a todos los clientes con menos de dos ingresos al sistema». En cambio, un modelo aprendido puede combinar frecuencia de uso, llamadas a soporte, antigüedad del contrato e historial de pagos, y ajustar la importancia de esas variables con resultados históricos conocidos. Que sea aprendido no garantiza que sea mejor ni más justo: ambas afirmaciones necesitan evaluación.

Programación tradicional frente a aprendizaje con ejemplos

En programación basada en reglas, el desarrollador establece las condiciones y la computadora las aplica. En Supervised Learning, el profesional sigue decidiendo el problema, las Features, la familia de modelos y el criterio de éxito, pero permite que los datos ayuden a estimar la relación entre Inputs y respuestas. Ninguna alternativa es automáticamente superior: una regla sencilla puede ser más confiable si el problema está bien definido.

Distinción importante: «aprender» no significa que la computadora piense como una persona ni que comprenda por qué ocurre un patrón. Significa que un procedimiento utiliza datos para ajustar o construir un modelo de acuerdo con un objetivo.

2. Anatomía de un dataset: observaciones, Features, Targets y tiempo

Una Observation (fila, registro o ejemplo) describe una unidad: cliente, transacción, visita médica, operación industrial o semana. Una Feature es una variable de entrada. Un Target (también llamado Label u Outcome) es la respuesta que se desea predecir mediante Supervised Learning.

Imaginemos que un banco quiere predecir si un cliente tendrá un pago atrasado el próximo mes. Un dataset histórico pequeño podría ser:

La expresión «próximo mes» define el momento de predicción. Podemos utilizar pagos anteriores, pero no un resultado que recién será conocido después de emitir la predicción. Respetar esa frontera temporal es fundamental para evitar Data Leakage.

3. Supervised Learning: aprender con respuestas conocidas

En Supervised Learning, los datos de Training contienen Features de entrada X y respuestas conocidas y. El objetivo es aprender una función que estime el Target en observaciones nuevas. «Supervised» se refiere a la existencia de respuestas durante el entrenamiento, no a que una persona supervise manualmente cada actualización.

Classification: el resultado es una categoría

Una empresa de suscripciones digitales quiere predecir si un cliente cancelará el servicio en los próximos 30 días. Los resultados posibles son cancelar o continuar. Aunque se almacenen como 1 y 0, siguen siendo categorías. El modelo puede entregar directamente una categoría o un score que luego se convierte en categoría con un Decision Threshold.

Supongamos que un modelo entrenado estima una probabilidad de cancelación de 0.76. Con un Threshold ilustrativo de 0.50, clasificamos al cliente como «cancelará». Si aumentamos el Threshold a 0.80, esa misma estimación de 0.76 se clasificaría como «continuará». La puntuación del modelo no cambió; cambió la regla utilizada para tomar una decisión.

Regression: el resultado es una cantidad

El equipo operativo de un hospital podría predecir el número de pacientes que llegarán mañana, mientras que una fábrica puede estimar consumo de energía en kilowatt-hours (kWh). Ambos problemas solicitan cantidades numéricas en las que importa la magnitud de la diferencia entre lo observado y lo estimado. Algunos conteos requieren modelos especializados, pero el punto esencial es que el resultado buscado es una cantidad y no una etiqueta de categoría.

Si una fábrica tiene un consumo real de 470 kWh y una predicción de 450 kWh, el error firmado (valor observado menos predicho) es +20 kWh. Su signo y magnitud poseen una interpretación física. En cambio, restar códigos arbitrarios de categorías «falló/no falló» no tiene la misma interpretación.

No confundas el tipo de aprendizaje con el nombre del algoritmo. Decision Trees, Random Forest, k-Nearest Neighbors y Neural Networks pueden utilizarse tanto para Classification como para Regression. La pregunta y el Target determinan cuál de las dos estamos resolviendo.

4. Unsupervised Learning: descubrir estructura sin Target conocido

En Unsupervised Learning, un algoritmo recibe mediciones de entrada sin una etiqueta objetivo designada para la tarea particular. Puede intentar agrupar observaciones similares, representar numerosas variables de forma más compacta, encontrar combinaciones frecuentes o detectar patrones poco habituales.

Imaginemos una tienda que registra la frecuencia de compra de cada cliente, el tamaño promedio de la canasta y la proporción de compras realizadas por Internet. La empresa no empieza con una respuesta correcta sobre si cada persona es un «cliente económico» o un «cliente leal». Un método de Clustering puede reunir perfiles parecidos; asignarles nombres e interpretar su utilidad comercial sigue siendo responsabilidad del analista.

Qué significa un Cluster y qué no significa

Un Cluster se define por las Features, la medida de distancia y el método utilizado. Dos personas con la misma frecuencia de compra pueden tener ingresos, satisfacción y preferencias muy diferentes. Clustering no descubre automáticamente tipos psicológicos reales ni causas del comportamiento; construye una descripción estructurada que debe contrastarse con conocimiento del sector.

5. Más allá de las dos familias: el panorama del aprendizaje

Supervised Learning y Unsupervised Learning son el centro de esta guía, pero no abarcan toda el área. Conocer sus límites evita clasificar incorrectamente otros proyectos.

6. Panorama de los principales métodos de Supervised Learning

No existe un único «algoritmo de Supervised Learning». Cada método emplea supuestos diferentes acerca de las relaciones entre variables y presenta ventajas y limitaciones relacionadas con interpretabilidad, flexibilidad, costo computacional y Preprocessing. Los ejemplos provienen de distintas industrias para que comprendamos los principios sin asociarlos a un único mercado.

Linear Regression — una relación numérica

Un equipo de Marketing predice las ventas semanales a partir de la inversión publicitaria. Un modelo lineal sencillo expresa las ventas predichas como un intercepto más un coeficiente multiplicado por el gasto. El coeficiente describe cuánto cambia la predicción del modelo al incrementar una unidad de publicidad, manteniendo constantes las otras variables incluidas; no demuestra por sí mismo un efecto causal.

Si obtenemos la función \(\hat y=1.5+1.4x\), con \(x\) medido en cientos de dólares y \(y\) en miles de dólares, entonces \(x=3\) genera \(\hat y=1.5+1.4(3)=5.7\), es decir, $5,700. En la sección 10 calcularemos esta relación usando las cuatro observaciones ilustrativas.

Logistic Regression — estimar probabilidades de clases

A pesar de su nombre, Logistic Regression se utiliza habitualmente en Classification. Primero combina Features mediante un score lineal y luego utiliza la función Sigmoid para transformarlo en un valor entre 0 y 1. En programación de citas médicas, podría estimar una probabilidad de 0.70 de que una cita no sea atendida, ayudando a decidir cuándo enviar recordatorios.

Un score estimado de 0.70 no garantiza que un paciente específico faltará. Además, es necesario evaluar la Calibration: entre muchos casos comparables a los que se asignó una probabilidad cercana a 0.70, ¿aproximadamente el 70% terminó faltando? Es algo que debe comprobarse empíricamente.

Decision Trees — aprender reglas comprensibles

Un Decision Tree divide sucesivamente los datos mediante preguntas. En mantenimiento industrial, una rama podría preguntar «¿La vibración supera 8 mm/s?» y otra «¿La máquina operó más de 1,000 horas desde el último servicio?». Los nodos terminales o Leaves generan estimaciones de clase o predicciones numéricas a partir de observaciones de Training.

La aparente claridad de un árbol puede ocultar Overfitting cuando alcanza demasiada profundidad: puede memorizar grupos pequeños e inusuales. Profundidad máxima y número mínimo de observaciones por Leaf son controles posibles, pero deben seleccionarse mediante Validation, no únicamente por Accuracy de Training.

Random Forest — combinar muchos árboles distintos

Random Forest entrena muchos Decision Trees usando muestras remuestreadas y aleatoriedad en las Features consideradas en las divisiones. Después agrega los resultados: votos o probabilidades en Classification, promedios en Regression. Como ilustración, cinco árboles predicen una falla industrial así: {sí, no, sí, sí, no}. La decisión mayoritaria sería «sí» (3 de 5).

Introducir diversidad entre árboles ayuda a reducir la variabilidad respecto de un árbol individual inestable. Sin embargo, las correlaciones entre errores, sesgos de los datos o Data Leakage siguen siendo posibles. Que tres de cinco árboles voten «sí» no equivale automáticamente a una probabilidad calibrada de falla del 60%.

Gradient Boosting y XGBoost — mejorar un modelo progresivamente

Boosting construye una secuencia de componentes predictivos, frecuentemente árboles poco profundos, de manera que los siguientes mejoren la predicción combinada según una Loss Function. Si una primera estimación del consumo de una fábrica es de 400 kWh y el consumo observado es 430 kWh, una etapa posterior puede ajustar la predicción en la dirección que reduzca el error. En la práctica, el ajuste considera todas las observaciones de Training, no una corrección memorizada para cada día.

XGBoost es una implementación conocida de árboles Gradient Boosting con Regularization y optimizaciones computacionales adicionales. Puede ser muy eficaz con datos tabulares, pero tiene Hyperparameters que requieren selección rigurosa y no elimina la necesidad de buenas particiones de los datos.

k-Nearest Neighbors (k-NN) — aprender de casos similares

k-NN compara una observación nueva con ejemplos de Training según una distancia. Supongamos que un comercio quiere predecir el número de artículos que comprará un cliente. Si las dos visitas históricas más cercanas compraron 3 y 5 artículos, el estimador Regression con dos vecinos es \((3+5)/2=\)4 artículos. Para Classification, los vecinos aportan votos por categoría o estimaciones ponderadas.

«Más cercano» depende de las escalas y los pesos de las variables. Una Feature en dólares puede dominar otra que representa conteos, salvo que el Feature Scaling se maneje de manera adecuada. Además, k-NN normalmente necesita conservar los ejemplos históricos para predecir.

Support Vector Machines (SVM) — fronteras de separación y margen

En Classification, Support Vector Machines (SVM) buscan una frontera que separe categorías, prestando especial atención al Margin respecto de observaciones relevantes. En control de calidad industrial, variables como grosor y rugosidad superficial pueden ayudar a diferenciar piezas aceptables de defectuosas.

La frontera no tiene que ser recta: los Kernel Methods permiten separaciones no lineales. También existen variantes SVM para Regression. El escalamiento y los Hyperparameters influyen en el resultado; separar perfectamente el conjunto de Training no garantiza un desempeño adecuado en el futuro.

Neural Networks — transformaciones aprendidas en capas

Una Neural Network combina Weights, Biases y funciones de activación no lineales organizadas en Layers. En imágenes médicas, los cálculos iniciales pueden representar bordes o texturas y los posteriores patrones más complejos. En un centro de atención telefónica, una red podría pronosticar demanda usando horarios, feriados e historial de llamadas.

Las redes permiten aprender relaciones no lineales complejas, pero también necesitan datos apropiados, Regularization, evaluación y salvaguardas del dominio. Arquitecturas profundas no son automáticamente superiores en datasets tabulares pequeños. Sus resultados siempre deben interpretarse según el problema que se busca resolver.

7. Panorama de los principales métodos de Unsupervised Learning

Unsupervised Learning también contiene métodos variados: no es sinónimo de Clustering. Cada uno responde una pregunta exploratoria diferente. Primero debemos saber qué resultado esperamos y recién después interpretar el algoritmo. La ausencia de Target no significa que todos los métodos intenten lo mismo.

k-means Clustering — grupos alrededor de medias representativas

k-means necesita elegir un número \(k\) de grupos. Alterna entre asignar observaciones al centro más cercano y actualizar cada centro mediante la media de las observaciones asignadas. Para clientes de Retail con canastas promedio de $20, $22, $24, $80, $82 y $84, elegir \(k=2\) puede separar perfiles de compra más bajos y más altos. En la sección 11 desarrollamos todas las asignaciones y actualizaciones.

La operación no demuestra que existan dos clases económicas naturales. El resultado depende de la Feature «monto de la canasta», del valor seleccionado de \(k\) y de la medida de distancia.

Hierarchical Clustering — grupos anidados con distintos niveles

Agglomerative Hierarchical Clustering empieza con cada observación en su propio grupo y combina progresivamente grupos cercanos de acuerdo con una regla de Linkage. Imaginemos tres mediciones de laboratorio donde A≈B y C es muy diferente. A y B pueden unirse primero, y luego los tres formar un grupo mayor. Un Dendrogram representa esa estructura jerárquica.

Reglas Single, Complete, Average o Ward Linkage pueden producir distintas jerarquías. Elegir la altura a la que se corta el Dendrogram para obtener grupos es una decisión analítica, no el descubrimiento de un número indiscutible de grupos.

DBSCAN — regiones densas y observaciones aisladas

Density-Based Spatial Clustering of Applications with Noise (DBSCAN) forma grupos de observaciones conectadas a través de vecindarios densos. En datos de entregas, varias ubicaciones próximas pueden formar zonas urbanas y las entregas muy alejadas aparecer como Noise. El método admite grupos de formas irregulares sin fijar de antemano un número de Clusters.

Depende de parámetros de radio de vecindad, densidad mínima y escala de variables. Que un punto sea catalogado como «Noise» no demuestra fraude ni error: puede ser un cliente legítimo en una zona apartada.

Principal Component Analysis (PCA) — resumir variables correlacionadas

Una fábrica puede registrar temperatura en °C, presión en kPa, vibración en mm/s y consumo de potencia en kW. Si estas mediciones varían de manera relacionada, Principal Component Analysis (PCA) construye nuevas direcciones que capturan proporciones importantes de la variación total. Las componentes son combinaciones ponderadas de Features, no categorías naturales de máquinas o clientes.

PCA trabaja con datos centrados y muchas veces requiere Standardization cuando las variables tienen unidades distintas. Capturar mucha varianza no significa necesariamente ser útil para predecir fallas: una dirección de varianza pequeña podría contener información crucial sobre eventos raros.

Association Rule Learning — productos que aparecen juntos

Supongamos 20 canastas de supermercado: 8 contienen café, 6 contienen tanto café como leche y 10 contienen leche. La regla «café → leche» tiene Support \(6/20=0.30\) y Confidence \(6/8=0.75\). La frecuencia total de leche es \(10/20=0.50\), por lo que Lift es \(0.75/0.50=\)1.50.

Esto describe Co-occurrence en veinte compras frente a la frecuencia marginal de leche, no significa que comprar café cause comprar leche. Haría falta una muestra mayor e interpretación de negocio antes de actuar.

Anomaly Detection — comportamientos inusuales frente a una referencia

Un sistema de monitoreo industrial observa normalmente temperaturas de aproximadamente 60 a 70 °C y detecta una lectura de 105 °C. Un Anomaly Detector puede señalarla por su diferencia respecto del patrón aprendido. Es una señal de comportamiento inusual, no una demostración automática de falla.

Anomaly Detection puede implementarse con enfoques Unsupervised, Semi-Supervised o Supervised, según exista o no información etiquetada de anomalías. Las falsas alarmas y los eventos no detectados tienen costos que se deben evaluar por separado.

8. Comparación de las familias: el Target cambia el problema

Ambos enfoques trabajan con Features, pueden necesitar Scaling y requieren evaluación. Lo que cambia es el objetivo fundamental. En Supervised Learning, la calidad predictiva se define respecto de un Target conocido. En Unsupervised Learning, evaluamos si la estructura hallada cumple un objetivo exploratorio o práctico bien identificado.

¿Se pueden aplicar ambas familias a un mismo sector?

Sí. Un hospital puede estimar el riesgo de Readmission dentro de 30 días usando resultados históricos conocidos (Supervised Learning), y explorar grupos de mediciones de laboratorio sin utilizar Readmission como Target (Unsupervised Learning). Esos Clusters no deben interpretarse como diagnósticos médicos sin validación clínica independiente.

Un banco puede predecir atrasos mediante Supervised Classification y emplear PCA para condensar numerosas variables de comportamiento. Incluso podría utilizar Features obtenidas con PCA dentro de un Pipeline supervisado. Las familias describen cómo utilizamos la información, no etiquetas permanentes de una industria.

9. Fundamentos matemáticos: datos, funciones, parámetros y objetivos

La notación formal nos permite expresar con precisión qué se aprende. No es necesario memorizar inmediatamente todas las fórmulas, pero cada símbolo debe representar un elemento concreto de los ejemplos.

\[\mathbf{x}_i=(x_{i1},x_{i2},\ldots,x_{ip}),\qquad \hat{y}_i=f_{\boldsymbol\theta}(\mathbf{x}_i)\]

Aquí \(i\) identifica una observación; \(p\) es el número de Features; \(\mathbf{x}_i\) es el vector de valores de entrada; \(f\) es la función que transforma entradas en un resultado; y \(\boldsymbol\theta\) representa los Model Parameters aprendidos, como coeficientes o Weights. \(\hat y_i\) representa la predicción y \(y_i\) el Target observado, cuando existe.

Función objetivo habitual en Supervised Learning

\[\hat{\boldsymbol\theta}=\arg\min_{\boldsymbol\theta}\frac{1}{n}\sum_{i=1}^{n}L\big(y_i,f_{\boldsymbol\theta}(\mathbf{x}_i)\big)\]

\(n\) representa el número de observaciones de Training. \(L\) es una Loss Function que cuantifica qué tan costosa es la diferencia entre Prediction y Target. El operador \(\arg\min\) indica que buscamos los parámetros que hacen mínima la pérdida promedio. Distintos problemas utilizan distintas Loss Functions: Squared Error es una opción para cantidades; Classification suele utilizar una función basada en probabilidades. La optimización detallada se estudia en guías posteriores.

El objetivo de Unsupervised Learning no compara respuestas conocidas

\[J=\sum_{j=1}^{k}\sum_{i\in C_j}\left\|\mathbf{x}_i-\boldsymbol\mu_j\right\|_2^2\]

En k-means, \(k\) es el número elegido de Clusters; \(C_j\) agrupa las observaciones asignadas al Cluster \(j\); \(\boldsymbol\mu_j\) es el vector promedio del grupo; y \(\|\cdot\|_2^2\) expresa distancia euclidiana al cuadrado. Minimizar \(J\) favorece grupos compactos, pero no demuestra que esos grupos representen categorías científicas o comerciales auténticas.

Model Parameters frente a Hyperparameters

En una recta ajustada, el intercepto y la pendiente son Parameters: se estiman a partir de Training Data. El número de Clusters \(k\) y la profundidad máxima de un Decision Tree son Hyperparameters: se seleccionan mediante decisiones del analista o procesos de Model Selection. Ambos influyen en los resultados, pero su origen es distinto.

Minimizar una Loss Function no equivale a resolver perfectamente una decisión real. El objetivo matemático elegido puede no representar todas las consecuencias financieras, médicas, éticas u operativas.

12. Evaluación de Supervised Learning: Accuracy no cuenta toda la historia

Un modelo debe evaluarse según la pregunta que busca responder. En Regression importan los tamaños de los errores numéricos; en Classification importan las decisiones de clase, los Rankings, las probabilidades y los costos de equivocarse de diferentes formas. Un buen resultado de Training no demuestra automáticamente Generalization.

Cálculo completo de Classification: cancelación de suscripciones

Consideremos diez clientes ilustrativos reservados para evaluación. Un clasificador previamente entrenado genera los scores siguientes para cancelar en 30 días. Utilizaremos un Threshold hipotético de 0.50. Los scores se proporcionan para explicar las métricas; no pretendemos que hayan sido aprendidos con estos diez casos.

El modelo marca cuatro clientes (A–D). Dos realmente cancelan (A y D): True Positives (TP) = 2. Dos marcados permanecen (B y C): False Positives (FP) = 2. Los otros seis, no marcados, efectivamente permanecen: True Negatives (TN) = 6. No se omite ninguna cancelación real: False Negatives (FN) = 0.

\[\mathrm{Accuracy}=\frac{TP+TN}{TP+FP+TN+FN}=\frac{2+6}{10}=0.80\]
\[\mathrm{Precision}=\frac{TP}{TP+FP}=\frac{2}{4}=0.50\]
\[\mathrm{Recall}=\frac{TP}{TP+FN}=\frac{2}{2}=1.00\]

En estas diez observaciones ilustrativas, Accuracy es 80%, Precision es 50% y Recall es 100%. De los clientes marcados como posibles cancelaciones, la mitad realmente cancela; de los que verdaderamente cancelaron, identificamos a todos. Precision y Recall contestan preguntas distintas y ninguna incorpora por sí sola todos los costos de una acción.

Por qué 80% de Accuracy puede inducir a error

Ocho de los diez clientes no cancelan. Un Baseline que predice «continuará» para todos alcanza \(8/10=80\%\) de Accuracy, igual que nuestro modelo, pero su Recall para cancelaciones es \(0/2=0\%\). El modelo puede ser más útil para encontrar clientes en riesgo aunque no supere al Baseline en Accuracy. Si conviene usarlo comercialmente depende, entre otros factores, del costo de contactar personas que de todos modos continuarían.

Regression necesita otras métricas

En predicción de ventas, MAE resume el error absoluto promedio en las unidades originales; MSE penaliza más los errores grandes al elevarlos al cuadrado; RMSE vuelve a expresar el resultado en las unidades de ventas. Ninguna de esas métricas demuestra por sí misma si las probabilidades de cancelación están calibradas. Asimismo, Accuracy no indica por cuántos kWh falla una predicción industrial.

Decision Threshold no es una propiedad natural del Target. Reducirlo puede mejorar Recall y aumentar False Positives. Su selección necesita Validation y un análisis de consecuencias para el problema real.

13. Evaluación de Unsupervised Learning: evidencia sin Labels objetivo

Un algoritmo de Clustering puede producir grupos siempre que se le indique hacerlo. La pregunta relevante es si esa partición presenta una estructura confiable y útil, o si simplemente refleja las unidades, las Features y decisiones arbitrarias del analista.

Evaluación interna: ¿qué tan compacta es la estructura seleccionada?

En k-means, el objetivo de distancias al cuadrado mide qué tan cerca están las observaciones de sus Centroids. Nuestro ejercicio Retail disminuyó de 40 a 16 dólares cuadrados después de actualizar los centros. Eso muestra una mejora según esa función objetivo, no demuestra que existan segmentos reales de consumidores. Si aumentamos el número de Clusters, el objetivo puede disminuir mecánicamente: por eso no basta para elegir \(k\).

Stability: ¿se conservaría el resultado con pequeñas variaciones?

Podemos repetir el análisis con otros centros iniciales, grupos de clientes remuestreados o conjuntos razonables de Features. Si las personas cambian frecuentemente de segmento, una campaña basada en esas etiquetas podría ser poco robusta. Las seis observaciones del ejemplo no bastan para un análisis operacional; solo hacen posibles cálculos transparentes.

Utilidad externa: ¿ayuda la estructura al problema planteado?

En Retail, podemos estudiar si los grupos difieren en compras posteriores, preferencias de productos o respuesta a campañas, procurando separar esa evaluación de los datos usados para diseñar y ajustar los grupos. En Manufacturing, PCA puede evaluarse por varianza retenida y facilidad de visualización, no por inventar nombres de grupos. En Anomaly Detection, especialistas pueden investigar alertas para cuantificar falsas alarmas y eventos omitidos.

No conviertas una interpretación en un Label verdadero. El nombre «compradores premium» es una propuesta humana que necesita evidencia; no es una categoría objetiva descubierta automáticamente por el algoritmo.

14. De un cálculo correcto a predicciones confiables: el Workflow

Un ejercicio matemático puede ser completamente correcto y aun así no representar un modelo útil en producción. El aprendizaje confiable exige relacionar la pregunta estadística con recolección, división, preparación, evaluación y uso adecuado de los datos.

  1. Definir pregunta y momento de decisión. Un banco quiere predecir atrasos el próximo mes con información disponible antes de que empiece ese período. Retail desea explorar segmentos a partir de compras de un intervalo definido.
  2. Examinar calidad y disponibilidad de datos. Revisar Missing Values, registros repetidos, definiciones de variables, proporción de clases, unidades y momento en que se conoce cada Feature.
  3. Separar datos para desarrollo y evaluación. En Supervised Learning, Training ajusta Parameters; Validation permite seleccionar modelos y Thresholds; Test queda reservado para una evaluación final. Eventos del mismo cliente pueden requerir Grouped Splits o divisiones cronológicas.
  4. Preparar Features sin utilizar información del futuro. Ajustar Imputation, Standardization, Encoding y Feature Selection únicamente con Training Data y aplicar las transformaciones aprendidas en Validation y Test. Unsupervised Learning también requiere cuidado si se evaluará contra resultados externos.
  5. Comenzar con un Baseline transparente. Para cantidades, predecir la media de Training; para clases, una regla sencilla como la clase mayoritaria. Los métodos complejos deben justificar su valor adicional.
  6. Entrenar, evaluar e interpretar. Utilizar métricas apropiadas, examinar incertidumbre, grupos relevantes y consecuencias reales de equivocarse.
  7. Desplegar y monitorear con controles adecuados. Los datos nuevos pueden ser distintos. Revisar calidad, cambios en las distribuciones de entrada y resultados futuros cuando puedan observarse.

Data Leakage: ejemplo bancario

Un banco quiere pronosticar si habrá retrasos el próximo mes. Una columna denominada «número de llamadas de cobranza posteriores al atraso» podría anticipar muy bien el resultado porque se registra después del evento. Incluirla le permite al modelo conocer el futuro. Un desempeño artificialmente excelente desaparecerá cuando tenga que predecir de verdad con información disponible antes del atraso.

Por qué nuestros datasets pequeños no prueban desempeño real

La Regression de cuatro semanas y el Clustering de seis clientes son pequeños intencionalmente para poder comprobar cada operación. No permiten demostrar Generalization, estimar adecuadamente incertidumbre ni sustentar decisiones financieras o clínicas. Un proyecto real requiere datos representativos, particiones apropiadas, análisis de errores y revisión posterior al Deployment.

15. Prediction, explicación, Causality y uso responsable

Machine Learning puede generar pronósticos útiles sin demostrar por qué ocurren los resultados. Son objetivos científicos diferentes. Un cliente que llama repetidamente a soporte puede tener mayor riesgo observado de cancelación; quizá las llamadas reflejan insatisfacción previa, pero provocar llamadas adicionales no necesariamente causaría una cancelación.

Prediction no equivale a intervención causal

Recordemos la Regression de Marketing: el coeficiente ajustado asoció cada $100 adicionales en publicidad con $1,400 más de ventas predichas. Esa relación observacional podría reflejar estacionalidad, promociones, demanda u otras variables omitidas. Para estimar el efecto de modificar la publicidad sería necesario un diseño causal, como un experimento aleatorizado adecuado o un análisis cuasiexperimental cuidadosamente justificado.

Un Risk Score no autoriza automáticamente una decisión

Un banco podría utilizar Scores para priorizar una revisión humana; un hospital podría usar la probabilidad estimada de una ausencia para ofrecer recordatorios útiles. Negar crédito o modificar cuidados médicos requiere controles legales, éticos y específicos del sector que el score no proporciona por sí solo. También es importante examinar el desempeño en poblaciones relevantes cuando hay riesgos de trato desigual.

Los datos y las poblaciones cambian

El comportamiento de los clientes, las políticas de préstamo, los sensores industriales y los procesos hospitalarios evolucionan. Patrones de Training pueden dejar de representar a las personas u operaciones futuras. Esto se relaciona con Distribution Shift; el Monitoring y una posible actualización del modelo forman parte del uso responsable.

Principio práctico: distingue tres preguntas: «¿Predice bien el modelo?», «¿Qué explica esta asociación?» y «¿Qué acción está justificada?». Contestar la primera no resuelve automáticamente las otras dos.

16. Errores comunes: por qué ocurren y cómo corregirlos

Estos errores aparecen cuando memorizamos nombres de algoritmos sin revisar qué información poseemos, qué función se minimiza y qué significan realmente los resultados. Cada corrección se conecta con un ejemplo desarrollado en las secciones anteriores.

Error 1: «Si la columna es numérica, necesariamente es Regression».

Por qué es incorrecto: Un código de clase como 0 = no canceló y 1 = canceló sigue siendo categórico. Corrección: interpreta qué significa el Target, no cómo está almacenado. La cancelación de una suscripción es Classification aunque se registre con números.

Error 2: «Unsupervised Learning no recibe información».

Por qué es incorrecto: Recibe Features medidas y decisiones matemáticas, como la distancia y el número de Clusters. Lo que no existe es un Target obligatorio para la tarea exploratoria. Corrección: identifica Inputs, pregunta y función objetivo.

Error 3: «El modelo encontró la causa del crecimiento de ventas».

Por qué es incorrecto: Una pendiente de Ordinary Least Squares resume una relación observada, no una intervención controlada. Promociones o estacionalidad pueden explicar tanto el gasto publicitario como las ventas. Corrección: separa asociación predictiva de afirmaciones causales.

Error 4: «Más Accuracy en Training implica mayor calidad predictiva».

Por qué es incorrecto: Un árbol muy profundo puede memorizar registros ruidosos. Corrección: evalúa en datos independientes representativos del escenario real y compara con un Baseline sencillo.

Error 5: «Si dos Clusters se ven bien, existen dos tipos reales de clientes».

Por qué es incorrecto: Indicamos a k-means que encuentre dos grupos utilizando solamente una Feature Retail. Las decisiones de escala, Features y \(k\) determinan el resultado. Corrección: comprueba estabilidad, relevancia comercial y parámetros alternativos.

Error 6: «Una Anomaly Flag demuestra fraude o daño industrial».

Por qué es incorrecto: Observaciones inusuales pueden ser legítimas; eventos problemáticos pueden parecer comunes. Corrección: considera las Flags como hipótesis sujetas a investigación, falsos positivos y omisiones.

Error 7: «Logistic Regression predice cantidades continuas porque se llama Regression».

Por qué es incorrecto: Este método suele estimar probabilidades de clases. Corrección: examina Target y Output; el nombre histórico del método no define la naturaleza del problema.

Error 8: «Todos los algoritmos Unsupervised hacen Clustering».

Por qué es incorrecto: PCA construye componentes, Association Rules encuentra coocurrencias y Anomaly Detection evalúa rareza. Corrección: identifica primero la clase de resultado matemático que necesitas.

Error 9: «Una probabilidad 0.70 garantiza exactamente siete resultados entre diez».

Por qué es incorrecto: La probabilidad no promete un conteo fijo en muestras pequeñas. Incluso predicciones calibradas pueden producir números de eventos diferentes. Corrección: estudia Calibration en grupos suficientemente grandes y comparables.

Error 10: «Si un campo existe en el dataset, podemos incluirlo como Feature».

Por qué es incorrecto: Podría haberse generado después del momento de predicción, revelar el resultado o plantear problemas de privacidad y equidad. Corrección: verifica disponibilidad legítima y pertinencia en el instante real de decisión.

Error 11: «El menor objetivo k-means revela el número correcto de segmentos».

Por qué es incorrecto: Aumentar Clusters puede reducir mecánicamente la distancia interna. Corrección: considera compactación, estabilidad, interpretabilidad y utilidad en lugar de minimizar un único indicador.

Error 12: «80% de Accuracy garantiza un buen modelo de cancelaciones».

Por qué es incorrecto: En nuestro ejemplo de diez personas, el Baseline «todos continúan» alcanza también 80% y no detecta ninguna de las dos cancelaciones. Corrección: revisa Precision, Recall, Thresholds, costos y prevalencia.

Error 13: «El RMSE de cuatro semanas demuestra buen Forecasting».

Por qué es incorrecto: Los mismos cuatro registros se usaron para ajustar el modelo y calcular RMSE: solo medimos Training Fit. Corrección: reserva períodos representativos para una evaluación auténtica.

Error 14: «Siempre podemos dividir un dataset aleatoriamente».

Por qué es incorrecto: Tendencias temporales o registros repetidos del mismo cliente pueden filtrar información entre particiones. Corrección: imita las restricciones de tiempo, entidad y población del Deployment.

17. Comprueba lo aprendido: soluciones completas y razonadas

Primero intenta responder sin desplegar cada panel. Después compara tu procedimiento con la explicación detallada. Queremos que identifiques el problema, reconstruyas cálculos y justifiques la interpretación, no que adivines el nombre de un algoritmo.

1. Un banco codifica los atrasos de pago como 0 y 1. ¿Classification o Regression?

Classification. Los números representan dos resultados posibles, no montos cuantitativos. Si el banco busca predecir dólares vencidos, entonces hablamos de Regression. Primero interpreta el Target.

2. Una plataforma agrupa usuarios según horas de contenido visto, sin etiquetas previas. ¿Qué familia corresponde?

Unsupervised Learning, posiblemente un problema de Clustering. Existen Features como tiempo de visualización, pero no un Target categórico conocido utilizado para entrenar. Aun así, deben validarse estabilidad y utilidad de los grupos.

3. ¿Por qué la media de publicidad de nuestro ejemplo es 2.5?

Los cuatro valores son 1, 2, 3 y 4, expresados en unidades de $100. La suma es 10 y el promedio es 10/4 = 2.5, equivalente a $250. Comprender las unidades permite interpretar luego la pendiente.

4. Calcula la pendiente de Marketing utilizando la tabla de desviaciones.

La suma de productos cruzados es 3+0−0.5+4.5 = 7. La suma de desviaciones cuadráticas de x es 2.25+0.25+0.25+2.25 = 5. Así, \(b_1=7/5=1.4\) miles de dólares de ventas por cada cien dólares de publicidad.

5. Con publicidad de $300, ¿cuánto predice la recta y cuál es el Residual?

Para $300, \(x=3\). Predicción: \(1.5+1.4(3)=5.7\) miles de dólares = $5,700. En la semana 3 observamos $4,000, por lo tanto Residual = $4,000 − $5,700 = −$1,700. El modelo sobreestima.

6. Recalcula el MAE de Training del modelo lineal.

Los Residuals absolutos en miles de dólares son 0.1, 0.7, 1.7 y 0.9. Su suma es 3.4. Dividimos entre cuatro: 3.4/4 = 0.85 miles de dólares = $850. No representa el error de Test.

7. ¿Por qué un cliente con compra de $24 se asigna al centro $20 en k-means?

La distancia a $20 es |24−20| = $4 y la distancia a $80 es |24−80| = $56. k-means elige el centro más cercano, por lo cual asigna la observación al Cluster 1. No indica motivaciones de compra.

8. Recalcula los dos nuevos Centroids de Retail.

El primer grupo contiene $20, $22 y $24: su media es (20+22+24)/3 = $22. El segundo contiene $80, $82 y $84: su media es (80+82+84)/3 = $82. Con esos centros no se producen cambios de grupo.

9. ¿Por qué el objetivo de k-means disminuye de 40 a 16 y cuáles son sus unidades?

Con centros iniciales $20 y $80, los cuadrados de distancia son 0, 4, 16, 0, 4 y 16; total 40 USD². Con centros $22 y $82 pasan a 4, 0, 4, 4, 0 y 4; total 16 USD². Una distancia interna menor no demuestra grupos comercialmente verdaderos.

10. Calcula Precision y Recall en el ejemplo de cancelación.

Los conteos son TP=2, FP=2, TN=6 y FN=0. Precision = 2/(2+2)=0.50; Recall = 2/(2+0)=1.00. Encontramos ambas cancelaciones, pero generamos dos alertas falsas.

11. ¿Por qué el Baseline «todos continúan» también obtiene 80% de Accuracy?

Ocho de diez clientes continúan. Predecir que todos seguirán produce ocho aciertos: 8/10=80%. Sin embargo, no identifica ninguna de las dos cancelaciones: Recall para cancelaciones = 0%. Importan la prevalencia y la métrica.

12. Identifica un caso de Data Leakage al predecir ausencias médicas.

Usar una columna «resultado final de asistencia» registrada después de la cita permite conocer anticipadamente la respuesta. Solamente deben usarse datos disponibles antes de decidir enviar un recordatorio. La separación de datos también debe evitar que historiales repetidos de pacientes contaminen la evaluación.

13. Un componente PCA explica 70% de la variación en sensores. ¿Explica 70% de las fallas?

No. PCA busca direcciones de alta varianza de las Features, sin entrenarse para explicar Labels de falla. Una dirección que concentra mucha varianza puede resultar irrelevante para defectos. Sería necesario estudiar un Target específico con otro análisis validado.

14. ¿Qué evidencia adicional necesitamos antes de usar Clusters para campañas de Marketing?

Un dataset mayor y representativo; distintas configuraciones de Features y Scaling; estabilidad con remuestreo e inicializaciones alternativas; comparación de conductas posteriores entre grupos; y evaluación de si una acción comercial realmente aporta valor. Seis puntos permiten aprender aritmética, no justificar Deployment.

18. Glosario ampliado y cómo continuar estudiando

Consulta el glosario mientras repasas los ejemplos. Si dos conceptos parecen equivalentes, vuelve al sector correspondiente y pregunta si estamos prediciendo una respuesta, describiendo estructura o tomando una decisión.

Artificial Intelligence (AI)
Campo amplio que desarrolla sistemas para tareas relacionadas con razonamiento, percepción, lenguaje o decisiones.
Machine Learning (ML)
Métodos que ajustan o construyen modelos a partir de datos para predecir o identificar patrones.
Observation / Record
Unidad del análisis: cliente, canasta de compras, visita médica, operación o semana.
Feature
Medición o variable codificada utilizada como entrada; importa cuándo está disponible.
Target / Label
Resultado conocido utilizado en Supervised Learning; puede ser categórico o numérico.
Supervised Learning
Aprendizaje mediante observaciones que poseen Inputs y Targets conocidos.
Unsupervised Learning
Búsqueda de estructura en Inputs sin necesidad de Target conocido para la tarea.
Classification
Predicción de una categoría o de probabilidades asociadas a clases.
Regression
Predicción de cantidades para las cuales importa la magnitud del error.
Clustering
Agrupación según una representación y una medida de similitud o distancia.
Model
Función o estructura computacional que transforma Features en Predictions o representaciones.
Learning Algorithm
Procedimiento para ajustar Parameters o construir un modelo.
Parameter
Valor aprendido con datos, como pendiente, Weight o Centroid.
Hyperparameter
Configuración elegida antes o fuera del ajuste individual, como k o Tree Depth.
Loss Function
Fórmula que cuantifica penalizaciones por errores durante Training.
Residual
Resultado numérico observado menos su valor predicho.
MAE / MSE / RMSE
Mean Absolute Error, Mean Squared Error y Root Mean Squared Error; métricas de Regression con distintas unidades y penalizaciones.
Precision
Proporción de Predicted Positives que son positivos reales: TP/(TP+FP).
Recall
Proporción de Actual Positives correctamente encontrada: TP/(TP+FN).
Baseline
Método de referencia sencillo que permite juzgar el valor agregado de otro modelo.
Data Leakage
Uso indebido de información futura o contaminación de información entre Training y evaluación.
Generalization
Desempeño en observaciones pertinentes que no se emplearon para ajustar el modelo.
PCA
Principal Component Analysis: direcciones ortogonales que capturan variación en datos centrados.
DBSCAN
Density-Based Spatial Clustering of Applications with Noise: identifica grupos conectados por densidad y observaciones de Noise.
Calibration
Concordancia entre probabilidades estimadas y frecuencias observadas en grupos comparables.
Distribution Shift
Cambio en la distribución de variables o relaciones entre el Training y el uso posterior.
Causality
Efecto de una intervención o cambio, no simplemente una asociación útil para predicción.

Una estrategia práctica de estudio

Primero, selecciona una aplicación diferente, como predicción de fallas de equipos. Identifica Observation, Features, Target y momento de predicción. Segundo, determina si se necesita una clase, un número o una estructura sin Labels. Tercero, elige un Baseline y define qué evidencia permitiría afirmar que el resultado mejora. Solamente después selecciona una familia de algoritmos.

Idea fundamental

Machine Learning no comienza con un algoritmo: comienza con una pregunta. Supervised Learning utiliza Targets conocidos durante Training para predecir clases o cantidades. Unsupervised Learning utiliza Features para buscar grupos, componentes, asociaciones o casos inusuales sin una respuesta objetivo designada. Los métodos resuelven problemas matemáticos diferentes y sus resultados solo adquieren valor cuando se interpretan y validan adecuadamente.
