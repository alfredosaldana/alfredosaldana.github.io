Bank Customer Churn Prediction

An end-to-end machine learning case study that asks whether customer attributes can be used to identify elevated churn risk while preserving a rigorous train/test workflow.

Completed

1. Project question

Can customer attributes be used to estimate the risk that a bank customer will churn, and which modeling choices produce useful predictions on customers the model has never seen before?

In this project, churn means that a customer leaves the bank or stops using its services. The target variable is binary: Exited = 1 for a customer who churned and Exited = 0 for a customer who stayed. The repository contains 10,000 customer records and 18 original columns, followed by cleaning, feature engineering, model comparison and a reusable prediction module.

Key idea: churn prediction is a supervised binary classification problem. We know the historical outcome for each training customer, and we use those labeled examples to learn a rule that can estimate churn risk for future customers.

2. What a classification model is learning

Let Y represent the customer outcome:

Y ∈ {0,1}
Y = 1 means churn; Y = 0 means the customer stayed.

Let X represent the available customer characteristics, such as age, credit score, tenure, balance, number of products, activity status and geography. A classifier attempts to learn a relationship between X and Y.

Many classifiers can be interpreted as estimating a probability:

p(X) = P(Y = 1 | X)
Read this as: “the probability that the customer churns, given the customer's observed characteristics.”

A decision threshold can then convert that probability into a class prediction. For example, with a threshold of 0.50:

ŷ = 1 if p(X) ≥ 0.50, otherwise ŷ = 0

The threshold does not have to be 0.50. In a real retention program, a bank may lower or raise the threshold depending on the cost of missing a likely churner versus contacting a loyal customer unnecessarily.

3. Dataset and predictive features

The project begins with customer attributes such as CreditScore, Geography, Gender, Age, Tenure, Balance, NumOfProducts, HasCrCard, IsActiveMember, EstimatedSalary, Satisfaction Score, Card Type and Point Earned. Several identifier fields are removed because they do not represent meaningful predictive information.

4. Data leakage: a model can be “too good” for the wrong reason

One of the most important findings in this project is that the Complain variable is almost perfectly aligned with the target. In the repository analysis it has approximately 0.99 Pearson correlation with Exited and is nearly identical row-for-row. That makes it a classic example of target leakage.

Why leakage is dangerous: if a variable contains information that would only be known after—or as part of—the churn event, the model may appear extremely accurate during development but fail in real deployment. A predictive model must only use information that would genuinely be available at the moment the prediction is made.

This is an academically important lesson: high accuracy is not automatically evidence of a good model. We must first ask whether the information used to obtain that accuracy is legitimate.

5. Preprocessing: putting variables on a usable scale

Continuous numerical variables may live on very different scales. For example, Age might be measured in tens, while Balance may be measured in thousands. Standardization transforms a numeric feature into units of standard deviations from its mean:

z = (x − μ) / σ
x = original value, μ = feature mean, σ = feature standard deviation.
Mini example. Suppose mean age μ = 50 years and standard deviation σ = 10 years. A customer aged 65 has:

z = (65 − 50) / 10 = 1.5

The customer is 1.5 standard deviations above the mean age.

The project intentionally leaves binary indicators such as HasCrCard and IsActiveMember as 0/1 values. Categorical variables are transformed with one-hot encoding, creating indicator columns that algorithms can use without inventing an artificial numerical ordering.

6. Class imbalance: why accuracy can mislead

The original data are approximately 80% non-churners and 20% churners. This matters because a naive classifier could predict “stay” for everyone and obtain roughly 80% accuracy while identifying zero customers who actually churn.

Key idea: when classes are imbalanced, model quality must be judged with metrics such as precision, recall, F1 score and ROC-AUC, not accuracy alone.

7. Train/test split and why SMOTE belongs only in the training set

The project uses a stratified 80/20 train/test split: about 8,000 customers for model development and 2,000 untouched customers for evaluation. The test set remains real and imbalanced so it behaves like the population the model would face in practice.

SMOTE means Synthetic Minority Over-sampling Technique. It creates synthetic minority-class examples by interpolating between neighboring minority observations.

xnew = xi + λ(xneighbor − xi)
where 0 ≤ λ ≤ 1. The new point lies somewhere between two minority-class observations.

SMOTE is applied only after the train/test split and only to the training data. Applying it before the split would allow synthetic information derived from future test observations to leak into model development.

8. Six classification models

The project compares six algorithms. Each represents a different way of approximating the unknown decision boundary between churners and non-churners.

9. Logistic regression: the probability baseline

Logistic regression is particularly useful for understanding classification because it converts a linear score into a probability using the logistic—or sigmoid—function.

p(X) = 1 / [1 + e−(β₀ + β₁X₁ + ··· + βₚXₚ)]

The quantity inside the exponential is a linear predictor. The sigmoid compresses any real-valued score into the interval from 0 to 1.

The same model can be written using log-odds:

log[p/(1−p)] = β₀ + β₁X₁ + ··· + βₚXₚ

For a one-unit increase in Xj, holding the other variables fixed, eβⱼ is the multiplicative change in the odds. This is one reason logistic regression remains important even when a more flexible model eventually performs better.

10. Decision trees and Random Forest

A decision tree repeatedly asks questions such as “Is Age > 52?” or “Is IsActiveMember = 0?” and splits the dataset into increasingly homogeneous groups.

A common impurity measure is the Gini impurity:

Gini = 1 − Σ pk2
For binary classification: Gini = 1 − p02 − p12.
Mini example. If a node contains 80% stayers and 20% churners:

Gini = 1 − 0.8² − 0.2² = 1 − 0.64 − 0.04 = 0.32.

A perfectly pure node has Gini = 0.

Random Forest builds many trees rather than trusting one. For classification, each tree votes for a class or contributes a probability, and the forest aggregates those results:

p̂forest(X) = (1/B) Σ p̂b(X)
B is the number of trees. Averaging helps reduce variance and improves robustness.

In this project, Random Forest is selected because it provides the strongest overall balance in F1 score and ROC-AUC while also supporting feature-importance analysis.

11. Confusion matrix: understanding prediction errors

Every binary classifier produces four basic outcomes:

Actually churnedActually stayed
Predicted churnTrue Positive (TP)False Positive (FP)
Predicted stayFalse Negative (FN)True Negative (TN)

Accuracy

(TP + TN) / N

Fraction of all predictions that are correct.

Precision

TP / (TP + FP)

Among customers predicted to churn, how many actually churn?

Recall

TP / (TP + FN)

Among actual churners, how many did the model identify?

F1 score

2 × Precision × Recall / (Precision + Recall)

Harmonic mean balancing precision and recall.

Mini example. Suppose a test set contains TP = 120, FP = 40 and FN = 80.

Precision = 120/(120+40) = 0.75
Recall = 120/(120+80) = 0.60
F1 = 2(0.75×0.60)/(0.75+0.60) ≈ 0.67.

This example shows why one metric alone rarely tells the full story.

12. ROC curve and AUC

The Receiver Operating Characteristic (ROC) curve evaluates the classifier over many probability thresholds. It plots:

True Positive Rate = TP/(TP+FN)False Positive Rate = FP/(FP+TN)

The Area Under the ROC Curve (AUC) summarizes discrimination. A useful interpretation is:

AUC = P(scorechurner > scorenon-churner)

So an AUC of 0.80 can be interpreted as: if we randomly select one churner and one non-churner, the model assigns the higher risk score to the churner about 80% of the time.

Important: AUC measures ranking discrimination. It does not guarantee that predicted probabilities are well calibrated. A model may rank customers correctly but still overstate or understate the true probability of churn.

13. Why model evaluation must use unseen data

A model can memorize patterns in its training sample. Therefore, evaluating performance on the same customers used to fit the model produces an optimistically biased estimate of generalization performance.

The project keeps an untouched test set during model selection. Only after selecting the model is the final Random Forest retrained using all real customer records. The final production fit does not use SMOTE so that its probability estimates remain aligned with the real class distribution rather than an artificial 50/50 training world.

14. Interpreting feature importance carefully

Random Forest feature importance helps identify which variables contribute strongly to the forest's predictive decisions. In the project, important predictors include Age, NumOfProducts, IsActiveMember, Balance and Geography.

Feature importance is not causality. If Age receives high importance, that means the model found Age useful for prediction in this dataset. It does not prove that changing age causes churn, nor does it explain the mechanism by itself.

The repository is organized as seven sequential Jupyter notebooks, a reusable BankChurn_Module.py inference class and a Streamlit application. This makes the project more than a model comparison exercise: it illustrates how an analysis can move toward a reproducible prediction pipeline.

16. What this project teaches

  • Predictive performance begins with data quality. Leakage can invalidate an otherwise sophisticated model.
  • Class imbalance changes how metrics should be interpreted.
  • Resampling must be isolated from the test set.
  • Different algorithms encode different assumptions about the decision boundary.
  • F1 and ROC-AUC complement accuracy when the minority class matters.
  • Prediction is not causation. A variable can be useful for prediction without being a causal driver.
  • Deployment requires reproducible preprocessing. The same transformations used during training must be applied to future customers.
